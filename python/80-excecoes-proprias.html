Por que criar suas exceções

Na aula 53 você viu raise ValueError("..."). Isso funciona, mas ValueError é genérico demais: pode ser qualquer coisa. Num sistema de banco, é muito mais claro receber um SaldoInsuficiente. Exceção própria deixa o código mais legível e permite tratar cada problema do jeito certo.

Uma exceção é só uma classe que herda de Exception:

class SaldoInsuficiente(Exception):
    pass

def sacar(saldo, valor):
    if valor > saldo:
        raise SaldoInsuficiente(f"saldo de R$ {saldo:.2f}, saque de R$ {valor:.2f}")
    return saldo - valor

print(sacar(100, 30))
try:
    sacar(100, 250)
except SaldoInsuficiente as e:
    print("Não deu:", e)

70
Não deu: saldo de R$ 100.00, saque de R$ 250.00

Dica: Por convenção, o nome de uma exceção descreve o problema e muitas vezes termina em Error, como SaldoInsuficienteError. Em português, nomes como SaldoInsuficiente ou CpfInvalido também ficam claros. O importante é ser consistente.

Uma família de exceções

Crie uma exceção base para o seu programa e faça as outras herdarem dela. Assim dá para tratar um erro específico ou todos de uma vez.

class ErroDaLoja(Exception):
    """Base de todos os erros da loja."""

class ProdutoEsgotado(ErroDaLoja):
    pass

class CupomInvalido(ErroDaLoja):
    pass

def comprar(produto, cupom=None):
    if produto == "videogame":
        raise ProdutoEsgotado(produto)
    if cupom is not None and cupom != "DIGITAR10":
        raise CupomInvalido(cupom)
    return f"{produto} comprado!"

for produto, cupom in [("livro", None), ("videogame", None), ("fone", "GRATIS")]:
    try:
        print(comprar(produto, cupom))
    except ProdutoEsgotado as e:
        print("Esgotado:", e)
    except ErroDaLoja as e:
        print(f"Outro problema ({type(e).__name__}):", e)

livro comprado!
Esgotado: videogame
Outro problema (CupomInvalido): GRATIS

Como CupomInvalido é filha de ErroDaLoja, ela cai no except ErroDaLoja.

Atenção: Herde de Exception, não de BaseException. A BaseException é a mãe de coisas especiais, como o Ctrl+C (KeyboardInterrupt), que não devem ser pegas por engano.

Exceção com informações extras

Como a exceção é uma classe, ela pode ter __init__ e atributos. Chame super().__init__(mensagem) para a mensagem continuar funcionando.

class NotaInvalida(Exception):
    def __init__(self, aluno, nota):
        super().__init__(f"nota {nota} de {aluno} está fora de 0 a 10")
        self.aluno = aluno
        self.nota = nota

def lancar(aluno, nota):
    if not 0 <= nota <= 10:
        raise NotaInvalida(aluno, nota)
    print(f"{aluno}: {nota} lançada")

for aluno, nota in [("Ana", 9), ("Beto", 12), ("Cris", -1)]:
    try:
        lancar(aluno, nota)
    except NotaInvalida as e:
        print("Erro:", e, "| corrija a nota de", e.aluno)

Ana: 9 lançada
Erro: nota 12 de Beto está fora de 0 a 10 | corrija a nota de Beto
Erro: nota -1 de Cris está fora de 0 a 10 | corrija a nota de Cris

raise ... from: contando a causa

Quando um erro acontece por causa de outro, use raise NovoErro(...) from erro_original. O Python guarda a causa em __cause__ e mostra as duas no traceback.

class IdadeInvalida(Exception):
    pass

def ler_idade(texto):
    try:
        return int(texto)
    except ValueError as e:
        raise IdadeInvalida(f"idade inválida: {texto!r}") from e

try:
    ler_idade("treze")
except IdadeInvalida as e:
    print("Erro:", e)
    print("Causa:", repr(e.__cause__))

Erro: idade inválida: 'treze'
Causa: ValueError("invalid literal for int() with base 10: 'treze'")

add_note: uma dica a mais (Python 3.11+)

A partir do Python 3.11, toda exceção tem o método add_note(texto), que acrescenta uma nota. As notas ficam na lista __notes__ e aparecem no final do traceback, ajudando quem for ler o erro.

def converter(texto):
    try:
        return float(texto)
    except ValueError as e:
        e.add_note("Dica: use ponto, e não vírgula, nas casas decimais (3.5).")
        raise

try:
    converter("3,5")
except ValueError as e:
    print("Erro:", e)
    for nota in e.__notes__:
        print("Nota:", nota)

Erro: could not convert string to float: '3,5'
Nota: Dica: use ponto, e não vírgula, nas casas decimais (3.5).

O raise sozinho, dentro do except, relança a mesma exceção depois de acrescentar a nota. Se ninguém pegar o erro, o traceback termina assim:

Traceback (most recent call last):
  ...
ValueError: could not convert string to float: '3,5'
Dica: use ponto, e não vírgula, nas casas decimais (3.5).

Exercícios

1. Crie a exceção SenhaFraca e a função cadastrar(senha) que gera essa exceção se a senha tiver menos de 8 caracteres. Teste com "123" e "pao-de-queijo".

Ver resposta 
class SenhaFraca(Exception):
    pass

def cadastrar(senha):
    if len(senha) < 8:
        raise SenhaFraca(f"a senha tem só {len(senha)} caracteres")
    return "Senha cadastrada!"

for s in ["123", "pao-de-queijo"]:
    try:
        print(cadastrar(s))
    except SenhaFraca as e:
        print("Senha fraca:", e)

Senha fraca: a senha tem só 3 caracteres
Senha cadastrada!

2. Crie a base ErroDeViagem e as filhas SemPassagem e MalaPesada. Faça a função embarcar(passagem, kg) e trate as duas com um único except ErroDeViagem.

Ver resposta 
class ErroDeViagem(Exception):
    pass

class SemPassagem(ErroDeViagem):
    pass

class MalaPesada(ErroDeViagem):
    pass

def embarcar(passagem, kg):
    if not passagem:
        raise SemPassagem("compre a passagem primeiro")
    if kg > 23:
        raise MalaPesada(f"mala com {kg} kg passa do limite de 23 kg")
    print("Boa viagem!")

for passagem, kg in [(True, 20), (False, 10), (True, 30)]:
    try:
        embarcar(passagem, kg)
    except ErroDeViagem as e:
        print(type(e).__name__ + ":", e)

Boa viagem!
SemPassagem: compre a passagem primeiro
MalaPesada: mala com 30 kg passa do limite de 23 kg

3. Crie a exceção EstoqueInsuficiente com os atributos produto, pedido e disponivel, e mostre uma mensagem usando esses atributos ao tratar o erro.

Ver resposta 
class EstoqueInsuficiente(Exception):
    def __init__(self, produto, pedido, disponivel):
        super().__init__(f"{produto}: pediu {pedido}, tem {disponivel}")
        self.produto = produto
        self.pedido = pedido
        self.disponivel = disponivel

estoque = {"coxinha": 4}

def vender(produto, qtd):
    tem = estoque.get(produto, 0)
    if qtd > tem:
        raise EstoqueInsuficiente(produto, qtd, tem)
    estoque[produto] = tem - qtd

try:
    vender("coxinha", 10)
except EstoqueInsuficiente as e:
    print(f"Só temos {e.disponivel} {e.produto}(s). Faltam {e.pedido - e.disponivel}.")

Só temos 4 coxinha(s). Faltam 6.

4. Faça a função dividir_conta(total, pessoas) que, se pessoas for 0, pega o ZeroDivisionError, acrescenta a nota "Informe pelo menos 1 pessoa." e relança. Mostre a mensagem e a nota.

Ver resposta 
def dividir_conta(total, pessoas):
    try:
        return total / pessoas
    except ZeroDivisionError as e:
        e.add_note("Informe pelo menos 1 pessoa.")
        raise

print(dividir_conta(120, 4))
try:
    dividir_conta(120, 0)
except ZeroDivisionError as e:
    print("Erro:", e)
    print("Nota:", e.__notes__[0])

30.0
Erro: division by zero
Nota: Informe pelo menos 1 pessoa.

5. Faça a função ler_cep(texto) que gera a exceção própria CepInvalido se o texto, sem o traço, não tiver 8 dígitos. Teste com "01310-100" e "123".

Ver resposta 
class CepInvalido(Exception):
    pass

def ler_cep(texto):
    numeros = texto.replace("-", "")
    if len(numeros) != 8 or not numeros.isdigit():
        raise CepInvalido(f"CEP {texto!r} precisa ter 8 dígitos")
    return numeros

for cep in ["01310-100", "123"]:
    try:
        print("CEP ok:", ler_cep(cep))
    except CepInvalido as e:
        print("Erro:", e)

CEP ok: 01310100
Erro: CEP '123' precisa ter 8 dígitos
