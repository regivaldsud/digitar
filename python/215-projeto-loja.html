Aula para fazer no computador: o assunto desta aula precisa do seu computador. Os códigos sem o botão Executar devem ser copiados para um arquivo .py no VS Code e rodados no seu computador, como mostrado na aula 03.

O que vamos construir

Uma loja simples de camisetas, mas com as peças que toda loja de verdade tem:

  • a vitrine (/) e a página de cada produto (/produto/camiseta-python/), onde se escolhe a variação (tamanho e cor);
  • o carrinho (/carrinho/), onde dá para mudar a quantidade, remover itens e ver o total;
  • o botão Fechar pedido, que exige login, grava o pedido e tira os itens do estoque;
  • a página do pedido (/pedido/1/), com o resumo da compra.

Partimos do que você já sabe: models e admin (aula 203), formulários com csrf_token (aula 205) e login (aula 206).

Passo 2: dinheiro é Decimal

Antes dos models, uma regra de ouro: **dinheiro nunca é float**. O float guarda os números em binário e erra nas casas decimais (aula 29). Numa loja, centavos errados viram reclamação. Compare:

from decimal import Decimal

print("float:  ", 0.1 + 0.2)
print("Decimal:", Decimal("0.10") + Decimal("0.20"))

preco = Decimal("19.90")
print("3 camisetas:", preco * 3)
print("Com 10% de desconto:", (preco * 3 * Decimal("0.90")).quantize(Decimal("0.01")))

float:   0.30000000000000004
Decimal: 0.30
3 camisetas: 59.70
Com 10% de desconto: 53.73

Crie o Decimal sempre a partir de texto: Decimal("19.90"). Escrever Decimal(19.90) copia o erro do float para dentro dele. No banco, o campo correspondente é o DecimalField.

Passo 3: os models

Uma camiseta pode ser P azul, M azul, G preta… Cada combinação tem o seu preço e o seu estoque. Por isso o produto e as variações ficam em tabelas separadas. Escreva loja/models.py:

# loja/models.py
from django.conf import settings
from django.db import models
from django.urls import reverse


class Produto(models.Model):
    nome = models.CharField(max_length=120)
    slug = models.SlugField(unique=True)
    descricao = models.TextField(blank=True)
    ativo = models.BooleanField(default=True)

    class Meta:
        ordering = ["nome"]

    def __str__(self):
        return self.nome

    def get_absolute_url(self):
        return reverse("produto", args=[self.slug])


class Variacao(models.Model):
    produto = models.ForeignKey(Produto, on_delete=models.CASCADE, related_name="variacoes")
    tamanho = models.CharField(max_length=10, blank=True)   # P, M, G...
    cor = models.CharField(max_length=30, blank=True)       # azul, preta...
    preco = models.DecimalField(max_digits=8, decimal_places=2)
    estoque = models.PositiveIntegerField(default=0)

    class Meta:
        verbose_name = "variação"
        verbose_name_plural = "variações"

    def __str__(self):
        detalhes = " ".join(parte for parte in [self.tamanho, self.cor] if parte)
        return f"{self.produto.nome} {detalhes}".strip()


class Pedido(models.Model):
    usuario = models.ForeignKey(settings.AUTH_USER_MODEL, on_delete=models.PROTECT, related_name="pedidos")
    total = models.DecimalField(max_digits=10, decimal_places=2, default=0)
    criado_em = models.DateTimeField(auto_now_add=True)

    def __str__(self):
        return f"Pedido {self.pk}"


class ItemPedido(models.Model):
    pedido = models.ForeignKey(Pedido, on_delete=models.CASCADE, related_name="itens")
    variacao = models.ForeignKey(Variacao, on_delete=models.PROTECT)
    quantidade = models.PositiveIntegerField()
    preco = models.DecimalField(max_digits=8, decimal_places=2)   # preço no dia da compra

    @property
    def subtotal(self):
        return self.preco * self.quantidade

(sem saída: os models descrevem as tabelas)

  • DecimalField(max_digits=8, decimal_places=2) guarda até 999999,99 com exatamente 2 casas.
  • PositiveIntegerField não aceita estoque negativo.
  • O ItemPedido guarda o preço do momento da compra. Se a camiseta ficar mais cara amanhã, o pedido de hoje continua com o valor certo.
  • on_delete=models.PROTECT na variação impede apagar um produto que já foi vendido: o histórico de pedidos não pode quebrar.

Passo 5: o que é a sessão

O HTTP "esquece" tudo entre um pedido e outro. Para lembrar que este visitante pôs duas camisetas no carrinho, o Django usa a sessão: ele grava um dicionário no banco e entrega ao navegador só um cookie com um código (sessionid). Em cada visita, request.session traz o dicionário de volta — mesmo para quem não fez login.

O carrinho vai na sessão no formato {id_da_variacao: quantidade}. Só que a sessão é gravada em JSON, e no JSON as chaves de um dicionário são sempre texto. Veja o que acontece com uma chave número:

import json

carrinho = {7: 2}
guardado = json.dumps(carrinho)
de_volta = json.loads(guardado)

print("Gravado na sessão:", guardado)
print("Lido de volta:", de_volta)
print("A chave 7 ainda existe?", 7 in de_volta)
print("E a chave '7'?", "7" in de_volta)

Gravado na sessão: {"7": 2}
Lido de volta: {'7': 2}
A chave 7 ainda existe? False
E a chave '7'? True

Por isso, no carrinho, a chave será sempre str(variacao.pk). Outra consequência: só guarde na sessão coisas que o JSON entende (texto, número, lista, dicionário). Um Decimal ou um objeto do model não cabem lá — guarde o id e busque o resto no banco.

Atenção: Se você mudar um dicionário que está dentro da sessão (request.session["carrinho"]["7"] = 3), o Django não percebe a mudança e não salva. Ou você atribui de novo (request.session["carrinho"] = carrinho), ou avisa com request.session.modified = True.

Passo 6: a classe Carrinho

Para as views ficarem curtas, toda a lógica do carrinho vai numa classe. Primeiro, veja a mesma ideia em Python puro, com um dicionário comum no papel da sessão e outro no papel do banco:

from decimal import Decimal

BANCO = {  # id: (nome, preço, estoque)
    1: ("Camiseta P azul", Decimal("49.90"), 5),
    2: ("Camiseta M preta", Decimal("54.90"), 2),
}


class Carrinho:
    def __init__(self, sessao):
        self.dados = sessao.setdefault("carrinho", {})

    def adicionar(self, variacao_id, quantidade=1):
        estoque = BANCO[variacao_id][2]
        chave = str(variacao_id)
        self.dados[chave] = min(self.dados.get(chave, 0) + quantidade, estoque)

    def remover(self, variacao_id):
        self.dados.pop(str(variacao_id), None)

    def total(self):
        return sum((BANCO[int(c)][1] * q for c, q in self.dados.items()), Decimal("0.00"))


sessao = {}
carrinho = Carrinho(sessao)
carrinho.adicionar(1, 2)
carrinho.adicionar(2, 5)      # só há 2 em estoque
print("Sessão:", sessao)
print("Total: R$", carrinho.total())
carrinho.remover(1)
print("Depois de remover:", sessao, "Total: R$", carrinho.total())

Sessão: {'carrinho': {'1': 2, '2': 2}}
Total: R$ 209.60
Depois de remover: {'carrinho': {'2': 2}} Total: R$ 109.80

Repare no min(...): ninguém consegue pôr no carrinho mais do que existe no estoque. Agora a versão com o Django, em loja/carrinho.py:

# loja/carrinho.py
from decimal import Decimal
from .models import Variacao


class Carrinho:
    """Guarda {id_da_variacao: quantidade} na sessão do visitante."""

    def __init__(self, request):
        self.session = request.session
        self.dados = self.session.setdefault("carrinho", {})

    def salvar(self):
        self.session.modified = True   # avisa o Django que o dicionário mudou

    def adicionar(self, variacao, quantidade=1):
        chave = str(variacao.pk)
        nova = self.dados.get(chave, 0) + quantidade
        self.dados[chave] = min(nova, variacao.estoque)
        self.salvar()

    def alterar(self, variacao, quantidade):
        chave = str(variacao.pk)
        if quantidade <= 0:
            self.dados.pop(chave, None)
        else:
            self.dados[chave] = min(quantidade, variacao.estoque)
        self.salvar()

    def remover(self, variacao_id):
        self.dados.pop(str(variacao_id), None)
        self.salvar()

    def limpar(self):
        self.session["carrinho"] = {}
        self.dados = self.session["carrinho"]

    def itens(self):
        variacoes = Variacao.objects.filter(pk__in=self.dados.keys()).select_related("produto")
        for variacao in variacoes:
            quantidade = self.dados[str(variacao.pk)]
            yield {
                "variacao": variacao,
                "quantidade": quantidade,
                "subtotal": variacao.preco * quantidade,
            }

    def total(self):
        return sum((item["subtotal"] for item in self.itens()), Decimal("0.00"))

    def __len__(self):
        return sum(self.dados.values())

(sem saída: a classe é usada pelas views)

O preço não fica na sessão: itens() busca as variações no banco a cada vez. Assim, se o preço mudar, o carrinho mostra o valor atual. O __len__ (aula 81) permite escrever len(carrinho) para saber quantas peças há nele.

Para mostrar "Carrinho (3)" no topo de todas as páginas, use um context processor, como no blog (aula 211). Crie loja/context_processors.py:

# loja/context_processors.py
from .carrinho import Carrinho


def carrinho(request):
    return {"qtd_no_carrinho": len(Carrinho(request))}

(todo template passa a enxergar qtd_no_carrinho)

E acrescente "loja.context_processors.carrinho", à lista context_processors dentro de TEMPLATES, no config/settings.py.

Passo 7: fechar o pedido numa transação

Fechar o pedido são vários passos: criar o Pedido, criar cada ItemPedido, baixar o estoque de cada variação. E se faltar estoque do terceiro item, depois que os dois primeiros já foram gravados? Ficaria um pedido pela metade e um estoque errado.

A transação resolve: os comandos dentro dela valem todos juntos ou nenhum. Se der erro no meio, o banco desfaz tudo (*rollback*). Veja com o sqlite3 (aula 174), em que with con: abre uma transação:

import sqlite3

con = sqlite3.connect(":memory:")
con.execute("CREATE TABLE variacao (id INTEGER PRIMARY KEY, nome TEXT, estoque INTEGER)")
con.execute("CREATE TABLE item (variacao_id INTEGER, quantidade INTEGER)")
con.executemany("INSERT INTO variacao VALUES (?, ?, ?)",
                [(1, "Camiseta P azul", 5), (2, "Camiseta M preta", 2)])
con.commit()


def fechar_pedido(carrinho):
    try:
        with con:   # tudo aqui dentro vale junto ou nada vale
            for variacao_id, qtd in carrinho.items():
                nome, estoque = con.execute(
                    "SELECT nome, estoque FROM variacao WHERE id = ?", (variacao_id,)).fetchone()
                if estoque < qtd:
                    raise ValueError(f"Só temos {estoque} de {nome}.")
                con.execute("UPDATE variacao SET estoque = estoque - ? WHERE id = ?", (qtd, variacao_id))
                con.execute("INSERT INTO item VALUES (?, ?)", (variacao_id, qtd))
        print("Pedido fechado!")
    except ValueError as erro:
        print("Pedido recusado:", erro)
    print("  estoque:", con.execute("SELECT nome, estoque FROM variacao").fetchall())
    print("  itens gravados:", con.execute("SELECT COUNT(*) FROM item").fetchone()[0])


fechar_pedido({1: 2, 2: 3})   # falta camiseta preta: nada muda
fechar_pedido({1: 2, 2: 1})   # tudo certo

Pedido recusado: Só temos 2 de Camiseta M preta.
  estoque: [('Camiseta P azul', 5), ('Camiseta M preta', 2)]
  itens gravados: 0
Pedido fechado!
  estoque: [('Camiseta P azul', 3), ('Camiseta M preta', 1)]
  itens gravados: 2

No primeiro pedido, a baixa da camiseta azul chegou a acontecer, mas foi desfeita quando faltou a preta. No Django, o mesmo papel é do with transaction.atomic():.

Passo 8: as views e as URLs

Escreva loja/views.py inteiro:

# loja/views.py
from django.contrib import messages
from django.contrib.auth.decorators import login_required
from django.db import transaction
from django.shortcuts import get_object_or_404, redirect, render
from django.views.decorators.http import require_POST
from .carrinho import Carrinho
from .models import ItemPedido, Pedido, Produto, Variacao


class EstoqueInsuficiente(Exception):
    pass


def lista(request):
    produtos = Produto.objects.filter(ativo=True).prefetch_related("variacoes")
    return render(request, "loja/lista.html", {"produtos": produtos})


def produto(request, slug):
    item = get_object_or_404(Produto, slug=slug, ativo=True)
    return render(request, "loja/produto.html", {"produto": item})


@require_POST
def adicionar(request):
    variacao = get_object_or_404(Variacao, pk=request.POST.get("variacao"))
    quantidade = int(request.POST.get("quantidade", 1))
    Carrinho(request).adicionar(variacao, quantidade)
    messages.success(request, f"{variacao} foi para o carrinho.")
    return redirect("carrinho")


@require_POST
def alterar(request, variacao_id):
    variacao = get_object_or_404(Variacao, pk=variacao_id)
    Carrinho(request).alterar(variacao, int(request.POST.get("quantidade", 0)))
    return redirect("carrinho")


@require_POST
def remover(request, variacao_id):
    Carrinho(request).remover(variacao_id)
    return redirect("carrinho")


def ver_carrinho(request):
    carrinho = Carrinho(request)
    contexto = {"itens": list(carrinho.itens()), "total": carrinho.total()}
    return render(request, "loja/carrinho.html", contexto)


@login_required
@require_POST
def finalizar(request):
    carrinho = Carrinho(request)
    if len(carrinho) == 0:
        messages.error(request, "Seu carrinho está vazio.")
        return redirect("carrinho")
    try:
        with transaction.atomic():
            pedido = Pedido.objects.create(usuario=request.user)
            for item in carrinho.itens():
                variacao = Variacao.objects.select_for_update().get(pk=item["variacao"].pk)
                if variacao.estoque < item["quantidade"]:
                    raise EstoqueInsuficiente(f"Só temos {variacao.estoque} de {variacao}.")
                variacao.estoque -= item["quantidade"]
                variacao.save()
                ItemPedido.objects.create(pedido=pedido, variacao=variacao,
                                          quantidade=item["quantidade"], preco=variacao.preco)
            pedido.total = carrinho.total()
            pedido.save()
    except EstoqueInsuficiente as erro:
        messages.error(request, str(erro))
        return redirect("carrinho")
    carrinho.limpar()
    return redirect("pedido", pk=pedido.pk)


@login_required
def ver_pedido(request, pk):
    pedido = get_object_or_404(Pedido, pk=pk, usuario=request.user)
    return render(request, "loja/pedido.html", {"pedido": pedido})

(sem saída: as views só rodam quando alguém abre uma página)

  • @require_POST faz as views que mudam algo aceitarem só POST (com csrf_token). Um link comum, que é GET, recebe "405 método não permitido".
  • select_for_update() "tranca" a linha da variação até a transação acabar. Se duas pessoas comprarem a última camiseta ao mesmo tempo, uma espera a outra, e o estoque não fica negativo. (No SQLite essa trava é ignorada, mas no PostgreSQL da aula 220 ela funciona.)
  • Quando a exceção sai de dentro do with transaction.atomic():, o Django desfaz o pedido e as baixas de estoque, e a mensagem de erro aparece no carrinho.
  • ver_pedido filtra por usuario=request.user: ninguém vê o pedido dos outros trocando o número na URL.

# loja/tests.py
from decimal import Decimal
from django.contrib.auth.models import User
from django.test import TestCase
from .models import Pedido, Produto, Variacao


class LojaTeste(TestCase):
    def setUp(self):
        camiseta = Produto.objects.create(nome="Camiseta Python", slug="camiseta-python")
        self.azul = Variacao.objects.create(produto=camiseta, tamanho="P", cor="azul",
                                            preco=Decimal("49.90"), estoque=5)
        self.preta = Variacao.objects.create(produto=camiseta, tamanho="M", cor="preta",
                                             preco=Decimal("54.90"), estoque=2)
        User.objects.create_user("bia", password="senha-de-teste-123")

    def test_carrinho_na_sessao(self):
        self.client.post("/carrinho/adicionar/", {"variacao": self.azul.pk, "quantidade": 2})
        self.client.post("/carrinho/adicionar/", {"variacao": self.preta.pk, "quantidade": 9})
        self.assertEqual(self.client.session["carrinho"], {str(self.azul.pk): 2, str(self.preta.pk): 2})
        self.client.post(f"/carrinho/{self.preta.pk}/remover/")
        self.assertContains(self.client.get("/carrinho/"), "Total: R$ 99,80")   # pt-br usa vírgula

    def test_fechar_pedido(self):
        self.client.login(username="bia", password="senha-de-teste-123")
        self.client.post("/carrinho/adicionar/", {"variacao": self.azul.pk, "quantidade": 2})
        self.client.post("/carrinho/adicionar/", {"variacao": self.preta.pk, "quantidade": 1})
        self.client.post("/carrinho/finalizar/")
        pedido = Pedido.objects.get()
        self.assertEqual(pedido.total, Decimal("154.70"))
        self.azul.refresh_from_db()
        self.assertEqual(self.azul.estoque, 3)
        self.assertEqual(self.client.session["carrinho"], {})

    def test_falta_estoque_desfaz_tudo(self):
        self.client.login(username="bia", password="senha-de-teste-123")
        self.client.post("/carrinho/adicionar/", {"variacao": self.azul.pk, "quantidade": 2})
        self.client.post("/carrinho/adicionar/", {"variacao": self.preta.pk, "quantidade": 2})
        Variacao.objects.filter(pk=self.preta.pk).update(estoque=1)   # alguém comprou antes
        resposta = self.client.post("/carrinho/finalizar/", follow=True)
        self.assertContains(resposta, "Só temos 1")
        self.assertEqual(Pedido.objects.count(), 0)
        self.azul.refresh_from_db()
        self.assertEqual(self.azul.estoque, 5)

1. Escreva a função aplicar_cupom(total, porcento) com Decimal que devolve o total com desconto, arredondado a 2 casas. Teste com R$ 137,30 e 10%.

Ver resposta 
from decimal import Decimal, ROUND_HALF_UP


def aplicar_cupom(total, porcento):
    desconto = total * Decimal(porcento) / 100
    return (total - desconto).quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)


print(aplicar_cupom(Decimal("137.30"), 10))

123.57

quantize(Decimal("0.01")) deixa exatamente duas casas; ROUND_HALF_UP arredonda 0,5 centavo para cima, como se aprende na escola.

2. Escreva a função frete(total): grátis para compras a partir de R$ 200,00; abaixo disso, R$ 15,00. Mostre o valor final de compras de R$ 154,70 e de R$ 210,00.

Ver resposta 
from decimal import Decimal

FRETE_GRATIS_A_PARTIR = Decimal("200.00")
VALOR_FRETE = Decimal("15.00")


def frete(total):
    if total >= FRETE_GRATIS_A_PARTIR:
        return Decimal("0.00")
    return VALOR_FRETE


for compra in [Decimal("154.70"), Decimal("210.00")]:
    print(f"Compra R$ {compra} + frete R$ {frete(compra)} = R$ {compra + frete(compra)}")

Compra R$ 154.70 + frete R$ 15.00 = R$ 169.70
Compra R$ 210.00 + frete R$ 0.00 = R$ 210.00

3. Por que o model ItemPedido guarda o campo preco, se a Variacao já tem um preço?

Ver resposta

Porque o preço da variação pode mudar depois da compra (promoção, aumento).
O pedido precisa lembrar quanto o cliente pagou NAQUELE dia. Se o item usasse
o preço da variação, um pedido antigo mudaria de valor sozinho quando a loja
mudasse o preço — o que estaria errado para o cliente e para a contabilidade.

5. No carrinho em Python puro do Passo 6, acrescente o método alterar(variacao_id, quantidade): quantidade 0 ou menor remove o item; acima do estoque fica no máximo do estoque.

Ver resposta 
from decimal import Decimal

BANCO = {1: ("Camiseta P azul", Decimal("49.90"), 5)}


class Carrinho:
    def __init__(self, sessao):
        self.dados = sessao.setdefault("carrinho", {})

    def alterar(self, variacao_id, quantidade):
        chave = str(variacao_id)
        if quantidade <= 0:
            self.dados.pop(chave, None)
        else:
            self.dados[chave] = min(quantidade, BANCO[variacao_id][2])


sessao = {}
carrinho = Carrinho(sessao)
carrinho.alterar(1, 3)
print(sessao)
carrinho.alterar(1, 50)
print(sessao)
carrinho.alterar(1, 0)
print(sessao)
