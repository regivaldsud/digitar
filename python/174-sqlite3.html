O módulo sqlite3

Nas aulas 170 a 173 você aprendeu a linguagem SQL. Agora o foco é o lado do Python: como o seu programa conversa com o banco, guarda o que foi feito e trata os erros.

O módulo sqlite3 já vem com o Python, sem instalar nada. Ele segue uma regra comum a quase todas as bibliotecas de banco do Python, chamada DB-API. Por isso, o que você aprender aqui (connect, cursor, execute, fetchall, commit) vale também para o MySQL da aula 176 e para o PostgreSQL.

O roteiro de qualquer programa com banco é sempre o mesmo:

  • abrir a conexão com sqlite3.connect(...);
  • mandar comandos com execute;
  • buscar os resultados com fetchone ou fetchall;
  • gravar as mudanças com commit;
  • fechar a conexão com close.

Conexão e cursor

A conexão representa o banco aberto. O cursor é quem executa os comandos e anda pelas linhas do resultado, uma de cada vez, como o dedo que acompanha a leitura de uma lista.

import sqlite3

con = sqlite3.connect(":memory:")
cur = con.cursor()
cur.execute("CREATE TABLE livros (id INTEGER PRIMARY KEY, titulo TEXT, autor TEXT)")
cur.execute("INSERT INTO livros (titulo, autor) VALUES (?, ?)", ("Dom Casmurro", "Machado de Assis"))
print("id do novo livro:", cur.lastrowid)
cur.execute("INSERT INTO livros (titulo, autor) VALUES (?, ?)", ("Iracema", "José de Alencar"))
print("id do novo livro:", cur.lastrowid)

cur.execute("SELECT titulo, autor FROM livros")
print(cur.fetchone())
print(cur.fetchone())
print(cur.fetchone())
con.close()

id do novo livro: 1
id do novo livro: 2
('Dom Casmurro', 'Machado de Assis')
('Iracema', 'José de Alencar')
None

  • lastrowid diz o id que o banco gerou no último INSERT. É útil para ligar esse registro a outro logo em seguida.
  • fetchone() pega a próxima linha; quando acabam as linhas, devolve None.
  • O ? dentro do comando é um placeholder: o valor vai separado, numa tupla. A aula 175 explica por que isso é tão importante.

O con.execute(...) que usamos nas aulas anteriores é um atalho: ele cria um cursor, executa e devolve esse cursor. Para programas pequenos, o atalho basta.

fetchone, fetchall ou um for

Existem três jeitos de ler o resultado de um SELECT. Escolha conforme a quantidade de linhas que você espera:

import sqlite3

con = sqlite3.connect(":memory:")
con.execute("CREATE TABLE notas (aluno TEXT, nota REAL)")
con.executemany("INSERT INTO notas VALUES (?, ?)",
                [("Ana", 9.0), ("Bruno", 6.5), ("Carla", 8.0)])

# uma linha só (ex.: uma contagem)
total = con.execute("SELECT COUNT(*) FROM notas").fetchone()[0]
print("Alunos:", total)

# todas as linhas numa lista
lista = con.execute("SELECT aluno FROM notas ORDER BY aluno").fetchall()
print("Lista:", lista)

# uma por vez, sem carregar tudo na memória
for aluno, nota in con.execute("SELECT aluno, nota FROM notas WHERE nota >= 7"):
    print(aluno, "passou com", nota)
con.close()

Alunos: 3
Lista: [('Ana',), ('Bruno',), ('Carla',)]
Ana passou com 9.0
Carla passou com 8.0

Cada linha volta como uma tupla. Mesmo quando você pede uma coluna só, ela vem como ('Ana',), por isso usamos [0] para pegar o valor.

Dica: Para resultados enormes (milhares de linhas), prefira o for direto no cursor: ele lê uma linha por vez e não enche a memória.

commit, rollback e transações

Quando você faz INSERT, UPDATE ou DELETE, a mudança ainda não está garantida no banco. Ela só fica gravada de verdade depois do commit(). Se algo der errado no meio do caminho, o rollback() desfaz tudo o que ainda não foi gravado.

Esse conjunto de mudanças que vale "tudo ou nada" se chama transação. Pense numa transferência de dinheiro: tirar de uma conta e pôr na outra precisam acontecer juntas, ou nenhuma das duas.

O jeito mais fácil é usar with con:. Se o bloco termina bem, o Python faz o commit; se acontece um erro, ele faz o rollback sozinho:

import sqlite3

con = sqlite3.connect(":memory:")
con.execute("CREATE TABLE contas (dono TEXT PRIMARY KEY, saldo REAL CHECK (saldo >= 0))")
with con:
    con.executemany("INSERT INTO contas VALUES (?, ?)", [("Ana", 100.0), ("Beto", 20.0)])


def transferir(con, de, para, valor):
    try:
        with con:
            con.execute("UPDATE contas SET saldo = saldo + ? WHERE dono = ?", (valor, para))
            con.execute("UPDATE contas SET saldo = saldo - ? WHERE dono = ?", (valor, de))
        print(f"Transferiu {valor:.2f} de {de} para {para}")
    except sqlite3.IntegrityError:
        print(f"Saldo insuficiente: transferência de {valor:.2f} cancelada")


transferir(con, "Ana", "Beto", 30)
transferir(con, "Beto", "Ana", 500)
print(con.execute("SELECT * FROM contas").fetchall())
con.close()

Transferiu 30.00 de Ana para Beto
Saldo insuficiente: transferência de 500.00 cancelada
[('Ana', 70.0), ('Beto', 50.0)]

Na segunda transferência, a Ana chegou a ganhar 500 dentro da transação, mas em seguida a regra CHECK (saldo >= 0) barrou o saldo negativo do Beto. Como deu erro, o with con: desfez as duas mudanças. Ninguém ficou com dinheiro a mais.

Atenção: O with con: não fecha a conexão: ele só faz commit ou rollback. Ainda é preciso chamar con.close() no fim do programa.

Linhas como dicionários com sqlite3.Row

Tuplas obrigam você a lembrar a ordem das colunas: linha[2] era o quê mesmo? Com row_factory = sqlite3.Row, cada linha pode ser lida pelo nome da coluna:

import sqlite3

con = sqlite3.connect(":memory:")
con.row_factory = sqlite3.Row
con.execute("CREATE TABLE times (nome TEXT, estado TEXT, titulos INTEGER)")
con.executemany("INSERT INTO times VALUES (?, ?, ?)",
                [("Bahia", "BA", 2), ("Fortaleza", "CE", 0)])
for t in con.execute("SELECT * FROM times"):
    print(t["nome"], "-", t["estado"], "-", t["titulos"], "título(s) brasileiro(s)")

primeiro = con.execute("SELECT * FROM times").fetchone()
print(primeiro.keys())
print(dict(primeiro))
con.close()

Bahia - BA - 2 título(s) brasileiro(s)
Fortaleza - CE - 0 título(s) brasileiro(s)
['nome', 'estado', 'titulos']
{'nome': 'Bahia', 'estado': 'BA', 'titulos': 2}

Um sqlite3.Row também aceita índice (t[0]) e vira dicionário com dict(t), o que ajuda a mandar os dados para um JSON (aula 62).

Um pequeno sistema: CRUD em funções

Num programa de verdade, você não espalha SQL pelo código todo. Cada operação vira uma função com um nome claro. Quem usa a função nem precisa saber SQL:

import sqlite3


def criar_banco(caminho=":memory:"):
    con = sqlite3.connect(caminho)
    con.row_factory = sqlite3.Row
    con.execute("""CREATE TABLE IF NOT EXISTS livros (
        id INTEGER PRIMARY KEY,
        titulo TEXT NOT NULL,
        autor TEXT NOT NULL
    )""")
    return con


def adicionar(con, titulo, autor):
    with con:
        cur = con.execute("INSERT INTO livros (titulo, autor) VALUES (?, ?)", (titulo, autor))
    return cur.lastrowid


def buscar(con, id_livro):
    return con.execute("SELECT * FROM livros WHERE id = ?", (id_livro,)).fetchone()


def listar(con):
    return con.execute("SELECT * FROM livros ORDER BY titulo").fetchall()


def trocar_autor(con, id_livro, autor):
    with con:
        cur = con.execute("UPDATE livros SET autor = ? WHERE id = ?", (autor, id_livro))
    return cur.rowcount == 1


def remover(con, id_livro):
    with con:
        cur = con.execute("DELETE FROM livros WHERE id = ?", (id_livro,))
    return cur.rowcount == 1


con = criar_banco()
adicionar(con, "O Cortiço", "Aluísio Azevedo")
n = adicionar(con, "Vidas Secas", "Graciliano")
adicionar(con, "Iracema", "José de Alencar")
print("Trocou?", trocar_autor(con, n, "Graciliano Ramos"))
print("Removeu o 1?", remover(con, 1))
print("Removeu o 99?", remover(con, 99))
print("Livro 2:", dict(buscar(con, 2)))
for livro in listar(con):
    print(livro["id"], livro["titulo"], "-", livro["autor"])
con.close()

Trocou? True
Removeu o 1? True
Removeu o 99? False
Livro 2: {'id': 2, 'titulo': 'Vidas Secas', 'autor': 'Graciliano Ramos'}
3 Iracema - José de Alencar
2 Vidas Secas - Graciliano Ramos

  • CREATE TABLE IF NOT EXISTS não dá erro se a tabela já existir: perfeito para um banco em arquivo que é aberto todo dia.
  • rowcount diz quantas linhas o UPDATE ou o DELETE mudou. Se for 0, o id não existia.
Atenção: Uma tupla de um item só precisa de vírgula: (id_livro,). Sem a vírgula, (id_livro) é só um número entre parênteses e o sqlite3 reclama com ProgrammingError ou ValueError.

Banco em arquivo

Com ":memory:" o banco some quando o programa termina. Para guardar os dados entre uma execução e outra, passe o nome de um arquivo. Salve como biblioteca.py e rode duas vezes com python biblioteca.py:

import sqlite3
from pathlib import Path

caminho = Path("biblioteca.db")
existia = caminho.exists()

con = sqlite3.connect(caminho)
con.execute("CREATE TABLE IF NOT EXISTS visitas (id INTEGER PRIMARY KEY, quando TEXT)")
with con:
    con.execute("INSERT INTO visitas (quando) VALUES (datetime('now'))")
total = con.execute("SELECT COUNT(*) FROM visitas").fetchone()[0]
con.close()

print("O arquivo já existia?", existia)
print("Este programa já rodou", total, "vez(es)")

O arquivo já existia? False
Este programa já rodou 1 vez(es)

Na segunda vez, aparece O arquivo já existia? True e 2 vez(es): os dados ficaram guardados em biblioteca.db, na mesma pasta do programa.

Dica: Programas como o DB Browser for SQLite (gratuito) abrem o arquivo .db para você ver as tabelas e os dados, como se fosse uma planilha.
Pratique no DIGITAR: digite este trecho no modo Programar do app. 
cur.execute("SELECT * FROM livros WHERE id = ?", (1,))
