Testar na mão cansa

Até agora você testou seus programas assim: roda, olha a saída e confere com os olhos. Funciona para programas pequenos, mas imagine conferir 50 casos toda vez que mudar uma linha. A gente cansa, esquece um caso e o erro escapa.

Um teste automático é um pedacinho de código que confere outro código. Ele roda em segundos, quantas vezes você quiser, e nunca fica com preguiça.

O comando assert

O jeito mais simples de testar em Python é o assert: você afirma que algo é verdade. Se for, nada acontece. Se não for, o Python para com um AssertionError.

def dobro(n):
    return n * 2


assert dobro(3) == 6
assert dobro(0) == 0
assert dobro(-2) == -4
print("Todos os testes passaram!")

Todos os testes passaram!

Agora veja o que acontece quando a função tem um erro (ela soma em vez de multiplicar):

def dobro(n):
    return n + 2


assert dobro(3) == 6, "dobro(3) deveria dar 6"
print("Esta linha nem chega a rodar.")

AssertionError: dobro(3) deveria dar 6

O texto depois da vírgula é a mensagem que aparece quando o assert falha. Ela ajuda a entender o que deu errado.

Atenção: assert não tem parênteses em volta de tudo. Escrever assert(dobro(3) == 6, "mensagem") cria uma tupla, que é sempre verdadeira, e o teste nunca falha! Escreva assert condicao, "mensagem".

O ciclo do TDD

TDD (do inglês *Test-Driven Development*, desenvolvimento guiado por testes) é um jeito de programar em que você escreve o teste antes do código. O ciclo tem três cores:

  • Vermelho: escreva um teste para algo que ainda não existe. Rode: ele falha.
  • Verde: escreva o código mais simples que faz o teste passar.
  • Refatorar: melhore o código (nomes, organização) sem mudar o que ele faz. Os testes avisam se algo quebrar.

Depois, repita com o próximo pedacinho. Veja o ciclo com a função e_maior_de_idade. Primeiro o vermelho: a função ainda não faz nada.

def e_maior_de_idade(idade):
    pass  # ainda não escrevemos


assert e_maior_de_idade(18) is True, "18 anos é maior de idade"

AssertionError: 18 anos é maior de idade

Agora o verde: o código mais simples que passa nos testes.

def e_maior_de_idade(idade):
    return idade >= 18


assert e_maior_de_idade(18) is True
assert e_maior_de_idade(30) is True
assert e_maior_de_idade(17) is False
print("Verde: tudo passou!")

Verde: tudo passou!

Dica: Ver o teste falhar primeiro é importante: prova que o teste realmente consegue pegar um erro. Um teste que nunca falha pode estar testando nada.

Escolhendo bons casos

Os erros adoram se esconder nos limites. Se a regra é "a partir de 18", teste 17, 18 e 19. Se é "nota maior ou igual a 7", teste 6.9, 7 e 7.1. Teste também casos estranhos: zero, número negativo, texto vazio.

def situacao(nota):
    if nota >= 7:
        return "aprovado"
    if nota >= 5:
        return "recuperação"
    return "reprovado"


casos = [(7, "aprovado"), (6.9, "recuperação"), (5, "recuperação"),
         (4.9, "reprovado"), (0, "reprovado"), (10, "aprovado")]
for nota, esperado in casos:
    assert situacao(nota) == esperado, f"nota {nota}"
print(len(casos), "casos testados, todos certos")

6 casos testados, todos certos

Na próxima aula você vai organizar testes assim com o módulo unittest, que mostra um relatório bonito de quais passaram e quais falharam.

Exercícios

1. Escreva três assert para a função triplo(n), que devolve o número vezes 3, testando 2, 0 e -1.

Ver resposta 
def triplo(n):
    return n * 3


assert triplo(2) == 6
assert triplo(0) == 0
assert triplo(-1) == -3
print("ok")

ok

2. A regra da meia-entrada do cinema é: até 12 anos (inclusive) ou a partir de 60 anos. Quais idades você testaria para pegar erros nos limites? Escreva a função e os testes.

Ver resposta 
def meia_entrada(idade):
    return idade <= 12 or idade >= 60


assert meia_entrada(12) is True
assert meia_entrada(13) is False
assert meia_entrada(59) is False
assert meia_entrada(60) is True
print("limites conferidos")

limites conferidos

Os limites são 12/13 e 59/60: é exatamente onde um < trocado por <= faria diferença.

3. Por que assert(1 == 2, "erro") nunca falha? Rode e veja.

Ver resposta 
resultado = (1 == 2, "erro")
print(bool(resultado))

True

Os parênteses criam uma tupla com dois itens, e toda tupla que não está vazia é verdadeira. O certo é assert 1 == 2, "erro".

4. Coloque em ordem as três etapas do TDD e diga o que acontece em cada uma.

Ver resposta

1. Vermelho: escrevo um teste para algo que ainda não existe; ele falha.
2. Verde: escrevo o código mais simples que faz o teste passar.
3. Refatorar: melhoro o código sem mudar o comportamento; os testes continuam passando.
