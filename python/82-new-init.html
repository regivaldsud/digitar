Aula 82 · __new__ e __init__

Nesta aula você vai aprender

  • As duas etapas da criação de um objeto: construir e inicializar
  • Quando o Python chama __new__ e quando chama __init__

Duas etapas para nascer um objeto

Quando você escreve Aluno("Bia"), parece que o Python faz uma coisa só. Na verdade são duas: primeiro o método especial __new__ constrói um objeto vazio; depois o __init__ inicializa esse objeto, guardando os atributos.

Pense numa casa: __new__ levanta as paredes e __init__ coloca os móveis. Quase sempre você só precisa mexer nos móveis — por isso, até agora, só escrevemos __init__.

class Aluno:
    def __new__(cls, *args, **kwargs):
        print("1. __new__: construindo o objeto")
        objeto = super().__new__(cls)
        return objeto

    def __init__(self, nome):
        print("2. __init__: guardando os atributos")
        self.nome = nome

bia = Aluno("Bia")
print("3. Pronto:", bia.nome)

1. __new__: construindo o objeto
2. __init__: guardando os atributos
3. Pronto: Bia

Repare nas diferenças: __new__ recebe cls (a classe), porque o objeto ainda não existe; __init__ recebe self (o objeto já construído). E __new__ precisa devolver o objeto com return; o __init__ não devolve nada.

Atenção: Se o seu __new__ esquecer o return, ele devolve None, o __init__ nem é chamado e a variável recebe None. Sempre termine com return super().__new__(cls) ou com o objeto criado.

Quando o __init__ não é chamado

O Python só chama o __init__ se o __new__ devolver um objeto da própria classe. Veja o que acontece quando ele devolve outra coisa:

class Estranho:
    def __new__(cls):
        print("__new__ rodou")
        return "eu sou um texto"

    def __init__(self):
        print("__init__ rodou")

x = Estranho()
print(x, type(x))

__new__ rodou
eu sou um texto <class 'str'>

O __init__ não apareceu, e x virou um texto. É um exemplo para entender a regra — não faça isso em programas de verdade.

Personalizando tipos imutáveis

Onde o __new__ faz falta de verdade é ao criar uma classe filha de um tipo imutável, como str, int ou tuple. Esses objetos não podem mudar depois de criados, então quando o __init__ roda já é tarde demais. Veja a tentativa errada:

class SiglaErrada(str):
    def __init__(self, texto):
        texto = texto.upper()

print(SiglaErrada("pe"))

pe

Continuou minúsculo! O certo é mudar o valor no __new__, antes do objeto existir:

class Sigla(str):
    def __new__(cls, texto):
        return super().__new__(cls, texto.strip().upper())

uf = Sigla("  pe ")
print(uf)
print(len(uf), uf == "PE", type(uf).__name__)

PE
2 True Sigla

O objeto uf continua sendo um texto: funciona com len, comparação e todos os métodos de str.

Um objeto só: o singleton

Às vezes um programa deve ter um único objeto de uma classe, como as configurações do jogo. Com __new__ dá para guardar o objeto criado e devolvê-lo sempre que alguém pedir outro:

class Configuracao:
    _unica = None

    def __new__(cls):
        if cls._unica is None:
            print("Criando a configuração pela primeira vez")
            cls._unica = super().__new__(cls)
            cls._unica.volume = 50
        return cls._unica

a = Configuracao()
b = Configuracao()
b.volume = 80
print(a is b)
print(a.volume)

Criando a configuração pela primeira vez
True
80

a e b são o mesmo objeto (is dá True), então mudar o volume em b muda em a.

Dica: Regra prática: use __init__ em 99% das classes. Pense em __new__ só quando herdar de um tipo imutável ou quando precisar controlar quantos objetos são criados.

class Senha(str):

5. Escreva a classe Juiz como singleton: não importa quantas vezes ela seja chamada, deve existir um único objeto. Mostre que Juiz() is Juiz() dá True.

Ver resposta 
class Juiz:
    _unico = None

    def __new__(cls):
        if cls._unico is None:
            cls._unico = super().__new__(cls)
        return cls._unico

print(Juiz() is Juiz())
