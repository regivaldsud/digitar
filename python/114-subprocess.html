Aula 114 · Rodando programas externos com subprocess

Nesta aula você vai aprender

  • Rodar um programa externo com subprocess.run passando o comando como lista
  • Capturar a saída e os erros com capture_output=True e text=True
  • Conferir se deu certo pelo returncode e com check=True
  • Limitar o tempo de espera com timeout
  • Entender por que evitar shell=True com textos que vêm de fora
Aula para fazer no computador: o assunto desta aula precisa do seu computador. Os códigos sem o botão Executar devem ser copiados para um arquivo .py no VS Code e rodados no seu computador, como mostrado na aula 03.

Por que chamar outros programas

Muita coisa útil já existe pronta como programa: o Git (aula 244), o compactador de arquivos, o conversor de vídeos, o próprio Python. Em vez de reescrever tudo, o seu script pode mandar esses programas trabalharem e depois ler o que eles responderam. É assim que se automatiza tarefas como "atualizar todos os repositórios" ou "converter todas as músicas de uma pasta".

O módulo subprocess (subprocesso = um programa rodando "debaixo" do seu) faz essa ponte. A função principal é subprocess.run.

Esta aula é para o computador: no navegador não existe "outro programa" para chamar. Copie os exemplos para um arquivo .py e rode com python nome.py.

O comando como lista

Você passa o comando em forma de lista: o primeiro item é o programa, os outros são os argumentos — exatamente as palavras que você digitaria no terminal, cada uma num item.

import subprocess
import sys

resultado = subprocess.run(
    [sys.executable, "-c", "print('Oi, eu sou outro programa!')"],
    capture_output=True,
    text=True,
)
print("Código de retorno:", resultado.returncode)
print("Saída:", resultado.stdout.strip())

Código de retorno: 0
Saída: Oi, eu sou outro programa!

  • sys.executable é o caminho do próprio Python que está rodando; assim o exemplo funciona em Windows, Linux e macOS;
  • -c manda o Python rodar o texto seguinte como código;
  • run espera o outro programa terminar e devolve um objeto CompletedProcess com o resultado.
Dica: Se você quisesse rodar no terminal python -c "print(2 + 3)", a lista seria ["python", "-c", "print(2 + 3)"]. Repare que as aspas do terminal somem: cada item da lista já é uma "palavra" inteira, com espaços e tudo.

Capturando a saída

Sem opções, o que o outro programa imprime vai direto para a tela, e o seu código não consegue ler. Com capture_output=True, a saída fica guardada em dois lugares:

  • stdout (saída padrão): o que foi impresso normalmente;
  • stderr (saída de erros): as mensagens de erro e avisos.

Com text=True elas chegam como str; sem ele, chegam como bytes (um texto com b na frente).

import subprocess
import sys

codigo = "print('linha 1'); print('linha 2'); print('linha 3')"
r = subprocess.run([sys.executable, "-c", codigo], capture_output=True, text=True)

linhas = r.stdout.splitlines()
print("Recebi", len(linhas), "linhas")
for numero, linha in enumerate(linhas, start=1):
    print(numero, "->", linha)

sem_text = subprocess.run([sys.executable, "-c", "print('oi')"], capture_output=True)
print(type(sem_text.stdout).__name__, sem_text.stdout.strip())

Recebi 3 linhas
1 -> linha 1
2 -> linha 2
3 -> linha 3
bytes b'oi'

Como a saída virou um texto comum, você usa tudo o que já sabe: splitlines, split, in, int()… É assim que um script "lê" a resposta de outro programa.

Deu certo ou deu erro?

Todo programa, ao terminar, devolve um número: o código de retorno. Por convenção, 0 quer dizer sucesso e qualquer outro número quer dizer que algo falhou.

import subprocess
import sys

resultado = subprocess.run([sys.executable, "-c", "1 / 0"], capture_output=True, text=True)
print("Código de retorno:", resultado.returncode)
print("Saída normal vazia?", resultado.stdout == "")
print("Última linha do erro:", resultado.stderr.strip().splitlines()[-1])

ok = subprocess.run([sys.executable, "-c", "import sys; sys.exit(0)"])
print("Programa que terminou bem:", ok.returncode)

Código de retorno: 1
Saída normal vazia? True
Última linha do erro: ZeroDivisionError: division by zero
Programa que terminou bem: 0

Repare que a falha do outro programa não derruba o seu: o run só conta o que aconteceu. Se você esquecer de olhar o returncode, o erro passa despercebido.

Atenção: Um erro comum é achar que o run avisa sozinho quando o programa falha. Sem check=True, ele não avisa: você precisa conferir resultado.returncode (ou usar check=True, a seguir).

check=True e timeout

Com check=True, o run gera a exceção subprocess.CalledProcessError quando o código de retorno não é 0. Com timeout=segundos, ele desiste de esperar e gera subprocess.TimeoutExpired — útil para um programa que travou não travar o seu junto. Os dois combinam com try/except (aula 53):

import subprocess
import sys

def rodar(codigo, limite=5):
    try:
        r = subprocess.run([sys.executable, "-c", codigo], capture_output=True,
                           text=True, check=True, timeout=limite)
        return "ok: " + r.stdout.strip()
    except subprocess.CalledProcessError as erro:
        return f"falhou com código {erro.returncode}"
    except subprocess.TimeoutExpired:
        return f"demorou mais de {limite} s e foi interrompido"

print(rodar("print(10 * 3)"))
print(rodar("import sys; sys.exit(3)"))
print(rodar("import time; time.sleep(10)", limite=1))

ok: 30
falhou com código 3
demorou mais de 1 s e foi interrompido

Quando o tempo esgota, o run encerra o programa filho antes de gerar a exceção, então nada fica rodando escondido.

Comandos do dia a dia

Fora o Python, você pode chamar qualquer programa instalado. Um uso comum é o Git (aula 244) — este exemplo só funciona numa pasta que é um repositório Git:

import subprocess

r = subprocess.run(["git", "status", "--short"], capture_output=True, text=True, check=True)
mudados = r.stdout.splitlines()
print(len(mudados), "arquivo(s) mudado(s)")
for linha in mudados:
    print(linha)

2 arquivo(s) mudado(s)
 M notas.py
?? rascunho.txt

Se o programa não estiver instalado (ou o nome estiver errado), o erro é outro: FileNotFoundError, antes mesmo de o programa começar.

Atenção: No Windows, comandos como dir, copy e del não são programas: eles fazem parte do Prompt de Comando. Por isso subprocess.run(["dir"]) dá FileNotFoundError. Para listar e copiar arquivos, prefira pathlib e shutil (aulas 103 e 104), que funcionam em qualquer sistema.

Por que evitar shell=True

Existe a opção shell=True, que manda o comando inteiro, como um texto só, para o terminal do sistema interpretar. Parece prático, mas é perigoso quando parte do texto vem de fora (do usuário, de um arquivo, da internet):

import subprocess

nome = input("Nome do arquivo: ")       # e se digitarem: x.txt & del /q *.*
subprocess.run("type " + nome, shell=True)                      # PERIGOSO
subprocess.run(["python", "contar.py", nome], check=True)       # seguro

(com shell=True, o terminal entende o & e roda o segundo comando também)

No terminal, símbolos como &, ; e | separam comandos. Com shell=True, quem digitar x.txt & del /q *.* faz o computador apagar arquivos. Com a lista e sem shell, o texto inteiro vira um único argumento e nada extra é executado. Esse tipo de ataque se chama injeção de comandos.

Pratique no DIGITAR: digite este trecho no modo Programar do app. 
subprocess.run(["git", "status"], check=True)

Exercícios

1. Rode, com subprocess.run, o Python mostrando a própria versão (-V) e imprima só a primeira palavra do resultado.

Ver resposta 
import subprocess
import sys

r = subprocess.run([sys.executable, "-V"], capture_output=True, text=True)
print((r.stdout or r.stderr).split()[0])

Python

O comando python -V mostra algo como Python 3.12.7; imprimindo só a primeira palavra, a saída é a mesma em qualquer versão.

2. Rode um programa Python que imprime os números de 1 a 5 (um por linha), capture a saída e mostre a soma deles.

Ver resposta 
import subprocess
import sys

r = subprocess.run([sys.executable, "-c", "for i in range(1, 6): print(i)"],
                   capture_output=True, text=True, check=True)
numeros = [int(linha) for linha in r.stdout.split()]
print("Soma:", sum(numeros))

Soma: 15

3. Escreva uma função deu_certo(codigo) que roda o texto codigo com o Python e devolve True se o programa terminou sem erro. Teste com "print(1)" e com "x = 1 +".

Ver resposta 
import subprocess
import sys

def deu_certo(codigo):
    r = subprocess.run([sys.executable, "-c", codigo], capture_output=True, text=True)
    return r.returncode == 0

print(deu_certo("print(1)"))
print(deu_certo("x = 1 +"))

True
False

4. O que significa returncode igual a 1? E qual exceção aparece quando o programa não termina dentro do timeout?

Ver resposta

returncode 1 quer dizer que o programa terminou com erro (por convenção,
0 é sucesso e qualquer outro número indica falha).
Quando o tempo acaba, o run encerra o programa e gera subprocess.TimeoutExpired.

5. Por que subprocess.run(["python", "contar.py", nome]) é mais seguro que subprocess.run("python contar.py " + nome, shell=True)?

Ver resposta

Na lista, o nome inteiro vira um único argumento e nada mais é executado.
Com shell=True, o terminal interpreta o texto: se o nome tiver &, ; ou |,
um segundo comando (que pode apagar arquivos) roda junto. Isso é injeção de comandos.
