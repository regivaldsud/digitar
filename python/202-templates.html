Por que templates

Na aula 201 as views devolviam HTML dentro de strings. Para uma página de verdade, com cabeçalho, menu, lista e rodapé, isso vira uma bagunça de aspas e +. A solução é separar as tarefas:

  • a view (Python) decide quais dados mostrar;
  • o template (um arquivo HTML com espaços marcados) decide como mostrar.

Assim quem cuida do visual mexe no HTML sem medo de quebrar o Python, e vice-versa. O próprio Python já tem uma ferramenta simples com essa ideia, a string.Template:

from string import Template

modelo = Template("<h1>$titulo</h1>\n<p>Olá, $nome! Você tem $idade anos.</p>")

print(modelo.substitute(titulo="Perfil", nome="Ana", idade=12))
print()
print(modelo.substitute(titulo="Perfil", nome="Caio", idade=13))

<h1>Perfil</h1>
<p>Olá, Ana! Você tem 12 anos.</p>
 
<h1>Perfil</h1>
<p>Olá, Caio! Você tem 13 anos.</p>

O mesmo modelo serviu para dois alunos: só os dados mudaram. Os templates do Django funcionam igual, mas com muito mais poder: laços, condições, filtros e herança.

render e o contexto

No Django, a função render junta o template com um dicionário chamado contexto. Cada chave do dicionário vira uma variável dentro do template.

Arquivo contatos/views.py:

from django.shortcuts import render


def lista(request):
    contexto = {
        "titulo": "Meus contatos",
        "contatos": ["Ana", "Bruno", "Carla"],
    }
    return render(request, "contatos/lista.html", contexto)

O Django procura contatos/lista.html dentro da pasta templates de cada app. Por isso o arquivo fica em contatos/templates/contatos/lista.html. A pasta repetida (templates/contatos/) parece estranha, mas evita confusão quando dois apps têm um template com o mesmo nome, como lista.html.

Registre a rota em contatos/urls.py: path("contatos/", views.lista, name="lista").

Atenção: O erro TemplateDoesNotExist at /contatos/ quer dizer que o Django não achou o arquivo. Confira três coisas: o caminho (contatos/templates/contatos/lista.html), o nome escrito na view e se o app está em INSTALLED_APPS — só os apps registrados têm a pasta templates lida. Pasta nova criada com o servidor rodando? Reinicie o runserver.

A linguagem de templates

Dentro do template existem duas marcações:

  • {{ variavel }} mostra um valor. Com um filtro depois da barra em pé, o valor é transformado: {{ nome|upper }} mostra o nome em maiúsculas;
  • {% tag %} faz uma ação: {% for %} repete, {% if %} decide. Toda tag de bloco termina com o seu {% end... %}.

Arquivo contatos/templates/contatos/lista.html (primeira versão, sem layout):

<h1>{{ titulo }}</h1>
<ul>
  {% for nome in contatos %}
    <li>{{ forloop.counter }}. {{ nome|upper }}</li>
  {% empty %}
    <li>Nenhum contato ainda.</li>
  {% endfor %}
</ul>
{% if contatos|length > 2 %}<p>Que turma grande!</p>{% endif %}
  • forloop.counter conta as voltas do for a partir de 1;
  • {% empty %} aparece quando a lista está vazia — sem precisar de um if à parte;
  • |length é o len() dos templates.

Alguns filtros úteis, numa view de teste com o contexto {"nome": "<b>Ana</b>", "nota": 8.756, "materias": ["matemática", "história"], "bio": ""}:

<p>Nome: {{ nome }}</p>
<p>Nota: {{ nota|floatformat:1 }}</p>
<p>Matérias: {{ materias|join:", " }} ({{ materias|length }})</p>
<p>Bio: {{ bio|default:"sem bio" }}</p>

O HTML gerado pelo Django (com LANGUAGE_CODE = "pt-br"):

<p>Nome: &lt;b&gt;Ana&lt;/b&gt;</p>
<p>Nota: 8,8</p>
<p>Matérias: matemática, história (2)</p>
<p>Bio: sem bio</p>

Repare em duas coisas: a nota saiu com vírgula, no padrão brasileiro, e o <b> do nome não virou negrito. Isso é de propósito, como você vai ver agora.

Dica: Dentro do template não se usa parênteses para chamar métodos nem colchetes: é tudo com ponto. {{ contato.nome }} lê um atributo, {{ dados.cidade }} lê a chave de um dicionário e {{ lista.0 }} pega o primeiro item.

Por que o Django escapa o HTML

Imagine um site de recados em que alguém escreve como "nome" o texto <script>roubar_senha()</script>. Se esse texto entrasse na página como HTML, o código rodaria no navegador de todo mundo que abrisse a página. Esse ataque se chama XSS.

Por isso o Django escapa toda variável: troca < por &lt;, > por &gt; e & por &amp;. O navegador mostra os sinais como texto e nada é executado. Veja um "mini motor de templates" fazendo o mesmo com html.escape:

import html
import re


def renderizar(modelo, contexto):
    def troca(m):
        valor = contexto.get(m.group(1), "")
        return html.escape(str(valor))
    return re.sub(r"\{\{ *(\w+) *\}\}", troca, modelo)


modelo = "<p>Recado de {{ nome }}: {{ texto }}</p>"
print(renderizar(modelo, {"nome": "Bia", "texto": "Oi, turma!"}))
print(renderizar(modelo, {"nome": "<script>roubar()</script>", "texto": "5 > 3 & 2 < 4"}))

<p>Recado de Bia: Oi, turma!</p>
<p>Recado de &lt;script&gt;roubar()&lt;/script&gt;: 5 &gt; 3 &amp; 2 &lt; 4</p>

A segunda linha mostra o "ataque" desarmado: o navegador exibiria o texto <script>... em vez de rodá-lo.

Atenção: Existe o filtro |safe, que desliga o escape de uma variável. Use só com HTML que você escreveu, nunca com texto que veio de um visitante.

Herança: um layout para todas as páginas

Todo site repete o mesmo cabeçalho, menu e rodapé em todas as páginas. Copiar e colar isso em cada template seria um problema: para mudar o menu, você teria de editar dezenas de arquivos. A herança de templates resolve: um arquivo base define o esqueleto e deixa blocos vazios, e cada página só preenche os blocos.

Arquivo contatos/templates/base.html:

{% load static %}
<!doctype html>
<html lang="pt-BR">
<head>
  <meta charset="utf-8">
  <title>{% block titulo %}Meu site{% endblock %}</title>
  <link rel="stylesheet" href="{% static 'css/estilo.css' %}">
</head>
<body>
  {% include "menu.html" %}
  {% block conteudo %}{% endblock %}
  <footer>Feito com Django</footer>
</body>
</html>

Arquivo contatos/templates/menu.html (um pedaço pequeno, colocado no base com include):

<nav><a href="{% url 'lista' %}">Contatos</a> | <a href="{% url 'sobre' %}">Sobre</a></nav>

Agora a lista herda do base. Arquivo contatos/templates/contatos/lista.html (versão final):

{% extends "base.html" %}
{% block titulo %}{{ titulo }}{% endblock %}
{% block conteudo %}
  <h1>{{ titulo }}</h1>
  <ul>
    {% for nome in contatos %}
      <li>{{ forloop.counter }}. {{ nome|upper }}</li>
    {% empty %}
      <li>Nenhum contato ainda.</li>
    {% endfor %}
  </ul>
  {% if contatos|length > 2 %}<p>Que turma grande!</p>{% endif %}
{% endblock %}

Crie também a view sobre (return render(request, "contatos/sobre.html")) e a rota path("sobre/", views.sobre, name="sobre"), porque o menu usa {% url 'sobre' %}. Abrindo http://127.0.0.1:8000/contatos/, o HTML que chega ao navegador é (sem as linhas em branco):

<!doctype html>
<html lang="pt-BR">
<head>
  <meta charset="utf-8">
  <title>Meus contatos</title>
  <link rel="stylesheet" href="/static/css/estilo.css">
</head>
<body>
  <nav><a href="/contatos/">Contatos</a> | <a href="/sobre/">Sobre</a></nav>
  <h1>Meus contatos</h1>
  <ul>
      <li>1. ANA</li>
      <li>2. BRUNO</li>
      <li>3. CARLA</li>
  </ul>
  <p>Que turma grande!</p>
  <footer>Feito com Django</footer>
</body>
</html>

A ideia da herança, em Python puro: o base tem buracos com nome, e a página filha diz o que vai em cada buraco. O que a filha não preencher fica com o texto padrão do base:

import re

BASE = """<title>[titulo: Meu site]</title>
<nav>Início | Contatos</nav>
<main>[conteudo: ]</main>
<footer>Feito com Python</footer>"""


def herdar(base, blocos):
    def troca(m):
        nome, padrao = m.group(1), m.group(2)
        return blocos.get(nome, padrao)
    return re.sub(r"\[(\w+): ?([^\]]*)\]", troca, base)


print(herdar(BASE, {"titulo": "Sobre", "conteudo": "<p>Feito por mim!</p>"}))
print("-----")
print(herdar(BASE, {"conteudo": "<p>Página sem título próprio</p>"}))

<title>Sobre</title>
<nav>Início | Contatos</nav>
<main><p>Feito por mim!</p></main>
<footer>Feito com Python</footer>
-----
<title>Meu site</title>
<nav>Início | Contatos</nav>
<main><p>Página sem título próprio</p></main>
<footer>Feito com Python</footer>

Dica: O {% extends %} tem de ser a primeira tag do template filho. E tudo o que a página filha escrever fora de um {% block %} é ignorado — se um texto "sumiu", veja se ele está dentro de um bloco.

Arquivos estáticos

CSS, JavaScript e imagens são arquivos estáticos: o servidor só entrega o arquivo como está, sem rodar Python. Coloque-os na pasta static do app, por exemplo contatos/static/css/estilo.css:

body { font-family: sans-serif; max-width: 40em; margin: auto; }
nav a { margin-right: 8px; }

No template, carregue a ferramenta com {% load static %} e use {% static 'css/estilo.css' %} no endereço, como no base.html. O Django troca por /static/css/estilo.css. Uma imagem em contatos/static/img/logo.png entra assim:

<img src="{% static 'img/logo.png' %}" alt="Logo do site">

Com DEBUG = True, o próprio runserver serve esses arquivos. Na aula 220 você verá como eles são servidos quando o site é publicado.

Atenção: Se aparecer Invalid block tag on line 6: 'static'. Did you forget to register or load this tag?, faltou o {% load static %} no topo daquele template. Ele vale só para o arquivo onde foi escrito: o filho que herda do base também precisa do seu próprio {% load static %} se usar {% static %}.
Pratique no DIGITAR: digite este trecho no modo Programar do app. 
{% for nome in contatos %}<li>{{ nome }}</li>{% endfor %}

Exercícios

1. Escreva o template contatos/sobre.html que herda de base.html, troca o título para "Sobre" e mostra um parágrafo.

Ver resposta 
{% extends "base.html" %}
{% block titulo %}Sobre{% endblock %}
{% block conteudo %}
  <p>Este site foi feito por mim, com Django!</p>

O menu e o rodapé aparecem sozinhos, porque vêm do base.html.

2. Uma view manda {"notas": [7, 9.5, 6]}. Escreva o trecho de template que lista as notas numeradas e mostra quantas são.

Ver resposta 
<ul>
  {% for nota in notas %}
    <li>{{ forloop.counter }}: {{ nota }}</li>
  {% endfor %}
</ul>
<p>Total de notas: {{ notas|length }}</p>

3. Escreva o trecho de template que mostra "Aprovado!" se media for maior ou igual a 7, "Recuperação" se for maior ou igual a 5, e "Reprovado" nos outros casos.

Ver resposta 
{% if media >= 7 %}
  <p>Aprovado!</p>
{% elif media >= 5 %}
  <p>Recuperação</p>
{% else %}
  <p>Reprovado</p>
{% endif %}

4. Use string.Template para montar o cartão "Aluno: NOME - Turma: TURMA" para três alunos guardados numa lista de dicionários.

Ver resposta 
from string import Template

cartao = Template("Aluno: $nome - Turma: $turma")
alunos = [
    {"nome": "Ana", "turma": "7A"},
    {"nome": "Caio", "turma": "7B"},
    {"nome": "Lia", "turma": "8A"},
]
for aluno in alunos:
    print(cartao.substitute(aluno))

Aluno: Ana - Turma: 7A
Aluno: Caio - Turma: 7B
Aluno: Lia - Turma: 8A

5. Usando html.escape, mostre como fica na página o comentário Eu <3 Python & Django. Por que o Django faz isso sozinho com as variáveis?

Ver resposta 
import html

print(html.escape("Eu <3 Python & Django"))

Eu &lt;3 Python &amp; Django

O < poderia ser entendido pelo navegador como o começo de uma tag. Escapando, ele aparece como texto. O Django escapa sozinho para proteger o site de quem tenta colocar código (<script>) nos dados — o ataque XSS.

6. A página dá TemplateDoesNotExist: contatos/lista.html, mas o arquivo existe em contatos/templates/lista.html. Qual é o problema e quais são as duas formas de consertar?

Ver resposta

O Django procura o caminho "contatos/lista.html" DENTRO da pasta templates,
ou seja, contatos/templates/contatos/lista.html.
Conserto 1: mover o arquivo para contatos/templates/contatos/lista.html (o jeito recomendado).
Conserto 2: na view, trocar para render(request, "lista.html", contexto).
