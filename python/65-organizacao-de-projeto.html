A ordem dentro de um arquivo

Um arquivo Python bem organizado costuma seguir esta ordem, de cima para baixo:

  • uma docstring curta dizendo o que o programa faz;
  • os import;
  • as constantes;
  • as funções (e classes);
  • a função main(), que coordena tudo, e a linha que a chama.
"""Calcula a média bimestral de um aluno."""

import statistics

MEDIA_PARA_PASSAR = 6.0


def calcular_media(notas):
    return statistics.mean(notas)


def situacao(media):
    return "aprovado" if media >= MEDIA_PARA_PASSAR else "recuperação"


def main():
    notas = [5.5, 7.0, 8.0]
    media = calcular_media(notas)
    print(f"Média {media:.1f}: {situacao(media)}")


main()

Média 6.8: aprovado

Dica: Nada de código "solto" espalhado entre as funções. Quem abre o arquivo deve achar tudo no lugar esperado.

if __name__ == "__main__"

Este assunto aparece com calma nas aulas 55 e 100; aqui vai o essencial para organizar o projeto. Todo arquivo Python tem uma variável especial chamada __name__. Quando você roda o arquivo diretamente, ela vale "__main__". Quando o arquivo é importado por outro, ela vale o nome do módulo.

Por isso, em vez de chamar main() direto, programadores escrevem assim. Rode este arquivo conversor.py:

"""Funções para converter temperaturas."""


def celsius_para_fahrenheit(c):
    return c * 9 / 5 + 32


def main():
    print("Testando o conversor:")
    print(celsius_para_fahrenheit(30))


if __name__ == "__main__":
    main()

Testando o conversor:
86.0

Agora, outro arquivo na mesma pasta importa o conversor. Repare que o teste de dentro dele não aparece, porque __name__ agora vale "conversor":

import conversor

print("Hoje faz", conversor.celsius_para_fahrenheit(25), "°F")
print(conversor.__name__)

Hoje faz 77.0 °F
conversor

Atenção: São dois sublinhados de cada lado: __name__ e "__main__". Com um só, o if nunca é verdadeiro e o programa não faz nada — sem mostrar erro.

Dividindo em módulos

Quando o programa cresce, separe por assunto. Cada arquivo .py é um módulo (você aprendeu a criar os seus na aula 55). Por exemplo, um módulo só com as perguntas de um quiz:

PERGUNTAS = [
    ("Qual é a capital do Brasil?", "brasília"),
    ("Quantos estados tem o Brasil?", "26"),
]

E o programa principal, que importa o que precisa:

from perguntas import PERGUNTAS


def corrigir(resposta, gabarito):
    return resposta.strip().lower() == gabarito


respostas_do_aluno = ["Brasília", "27"]
acertos = 0
for (pergunta, gabarito), resposta in zip(PERGUNTAS, respostas_do_aluno):
    if corrigir(resposta, gabarito):
        acertos += 1
print(f"Você acertou {acertos} de {len(PERGUNTAS)}.")

Você acertou 1 de 2.

Atenção: Não dê ao seu arquivo o nome de um módulo do Python, como random.py ou math.py. O import random passa a importar o seu arquivo e nada funciona.

A estrutura de pastas

Um projeto pequeno e bem organizado fica mais ou menos assim:

quiz-brasil/
├── README.md          explica o projeto e como rodar
├── requirements.txt   bibliotecas que o projeto usa
├── .gitignore         arquivos que o Git deve ignorar
├── quiz.py            programa principal (tem o main)
├── perguntas.py       módulo com os dados
└── tests/
    └── test_quiz.py   testes automáticos

O requirements.txt lista as bibliotecas instaladas com pip, uma por linha. Gere ele com pip freeze e instale tudo de uma vez em outro computador:

pip freeze > requirements.txt
pip install -r requirements.txt

Gere o requirements.txt com o ambiente virtual ativado (aula 60); assim ele lista só as bibliotecas deste projeto.

O README.md é a "capa" do projeto. Escreva pelo menos: o que ele faz, como instalar e como rodar.

# Quiz Brasil

Quiz de perguntas sobre o Brasil, no terminal.

## Como rodar

    python quiz.py

Funções pequenas e com um só trabalho

Cada função deve fazer uma coisa. Se o nome precisa de "e" (ler_e_calcular_e_mostrar), provavelmente são três funções. Funções pequenas são mais fáceis de testar, como você vai ver na aula 131.

def ler_precos(texto):
    return [float(p) for p in texto.split(";")]


def somar(precos):
    return sum(precos)


def formatar_reais(valor):
    return f"R$ {valor:.2f}".replace(".", ",")


total = somar(ler_precos("12.5;3.75;20"))
print(formatar_reais(total))

R$ 36,25

Compare com a versão "tudo junto", que faz as mesmas três tarefas numa função só. Funciona, mas não dá para reaproveitar só a parte de formatar em reais em outro lugar:

def ler_calcular_e_mostrar(texto):
    total = 0
    for p in texto.split(";"):
        total += float(p)
    print(f"R$ {total:.2f}".replace(".", ","))


ler_calcular_e_mostrar("12.5;3.75;20")

R$ 36,25

Com as funções separadas, dá para conferir cada parte sozinha, sem rodar o programa inteiro:

def ler_precos(texto):
    return [float(p) for p in texto.split(";")]


def formatar_reais(valor):
    return f"R$ {valor:.2f}".replace(".", ",")


print(ler_precos("2.5;1"))
print(formatar_reais(2.5))
print(formatar_reais(1234.5))

[2.5, 1.0]
R$ 2,50
R$ 1234,50

Essa é a ideia dos testes automáticos: verificar pedaços pequenos, um de cada vez.

4. Separe o código abaixo em três funções pequenas (ler, calcular, mostrar): ele recebe "8,7,9", calcula a média e mostra Média: 8.0.

Ver resposta 
def ler_notas(texto):
    return [float(n) for n in texto.split(",")]


def calcular_media(notas):
    return sum(notas) / len(notas)


def mostrar(media):
    print(f"Média: {media:.1f}")


mostrar(calcular_media(ler_notas("8,7,9")))
