O caminho de um pedido

Quando você digita http://127.0.0.1:8000/ola/ no navegador, acontece uma conversa em três passos:

  • o navegador envia um pedido (request) dizendo "quero o caminho /ola/";
  • o Django procura na lista de URLs qual função cuida desse caminho;
  • essa função, chamada view, monta e devolve uma resposta (response), que o navegador mostra.

Antes de abrir o Django, veja a ideia funcionando só com Python puro. O dicionário rotas faz o papel do urls.py e as funções fazem o papel das views:

def pagina_inicial(pedido):
    return "Bem-vindo ao meu site!"


def pagina_ola(pedido):
    return "Olá, visitante!"


rotas = {
    "/": pagina_inicial,
    "/ola/": pagina_ola,
}


def atender(caminho):
    view = rotas.get(caminho)
    if view is None:
        return "404 - Página não encontrada"
    return view({"caminho": caminho})


for caminho in ["/", "/ola/", "/sorvete/"]:
    print(caminho, "->", atender(caminho))

/ -> Bem-vindo ao meu site!
/ola/ -> Olá, visitante!
/sorvete/ -> 404 - Página não encontrada

O Django faz exatamente isso, só que com muito mais recursos: segurança, partes variáveis no caminho, formulários, cabeçalhos e tudo o que um site de verdade precisa.

Sua primeira view

Uma view é uma função comum que recebe o request e devolve um HttpResponse. Continue no projeto da aula 200 (projeto config, app contatos, já registrado em INSTALLED_APPS).

Arquivo contatos/views.py:

from django.http import HttpResponse


def ola(request):
    return HttpResponse("<h1>Olá do Django!</h1>")


def dobro(request, numero):
    return HttpResponse(f"O dobro de {numero} é {numero * 2}")

O texto dentro de HttpResponse é o que vai para o navegador. Como é HTML, o <h1> aparece como um título grande. Na aula 202 você vai trocar essas strings por arquivos HTML de verdade, os templates.

Atenção: Toda view precisa devolver uma resposta com return. Se você esquecer, o Django mostra o erro The view contatos.views.ola didn't return an HttpResponse object. It returned None instead.

Ligando as URLs

As views ainda não têm endereço. Cada app guarda as suas rotas num arquivo próprio, e o projeto junta tudo. Crie o arquivo contatos/urls.py:

from django.urls import path

from . import views

urlpatterns = [
    path("ola/", views.ola, name="ola"),
    path("dobro/<int:numero>/", views.dobro, name="dobro"),
]

Agora avise o projeto que essas rotas existem. Arquivo config/urls.py (ele já existe; acrescente o include):

from django.contrib import admin
from django.urls import include, path

urlpatterns = [
    path("admin/", admin.site.urls),
    path("", include("contatos.urls")),
]

Rode python manage.py runserver e abra http://127.0.0.1:8000/ola/. A página mostra:

Olá do Django!

Por que dois arquivos? Porque um projeto costuma ter vários apps. Cada app cuida das suas rotas, e o config/urls.py só diz "as rotas que começam com tal coisa ficam com tal app". O "" no include quer dizer "sem prefixo nenhum"; se fosse path("agenda/", include("contatos.urls")), a página viraria /agenda/ola/.

Dica: Termine as rotas com barra: "ola/". Se alguém digitar /ola sem a barra, o Django redireciona sozinho para /ola/ (é a configuração APPEND_SLASH, ligada por padrão). Não comece a rota com barra: "/ola/" não funciona.

Partes variáveis na URL

Seria impossível escrever uma rota para cada número. Por isso a rota pode ter um pedaço variável entre < e >. Em "dobro/<int:numero>/":

  • int é o conversor: só aceita dígitos e já transforma o texto em int;
  • numero é o nome do parâmetro que a view recebe.

Abrindo http://127.0.0.1:8000/dobro/21/, o Django chama dobro(request, numero=21):

O dobro de 21 é 42

Se você abrir /dobro/abc/, nenhuma rota combina (abc não é número) e a resposta é 404, página não encontrada. Os conversores mais usados são int, str (qualquer texto sem barra) e slug (letras, números, hífen e sublinhado, como bolo-de-cenoura).

Veja como um conversor funciona por dentro. Este mini-roteador transforma <int:numero> numa expressão regular (aulas 140 a 145):

import re

CONVERSORES = {"int": (r"\d+", int), "str": (r"[^/]+", str)}


def compilar(rota):
    tipos = {}

    def troca(m):
        tipo, nome = m.group(1), m.group(2)
        tipos[nome] = CONVERSORES[tipo][1]
        return f"(?P<{nome}>{CONVERSORES[tipo][0]})"

    padrao = re.sub(r"<(\w+):(\w+)>", troca, rota)
    return re.compile("^" + padrao + "$"), tipos


def dobro(numero):
    return f"O dobro de {numero} é {numero * 2}"


def saudacao(nome):
    return f"Oi, {nome}!"


rotas = [("dobro/<int:numero>/", dobro), ("oi/<str:nome>/", saudacao)]
compiladas = [(compilar(r), view) for r, view in rotas]


def atender(caminho):
    for (regex, tipos), view in compiladas:
        achou = regex.match(caminho)
        if achou:
            args = {k: tipos[k](v) for k, v in achou.groupdict().items()}
            return view(**args)
    return "404 - Página não encontrada"


for caminho in ["dobro/21/", "oi/Bia/", "dobro/abc/"]:
    print(caminho, "->", atender(caminho))

dobro/21/ -> O dobro de 21 é 42
oi/Bia/ -> Oi, Bia!
dobro/abc/ -> 404 - Página não encontrada

Repare que a view dobro recebeu o número já como int — por isso numero * 2 deu 42, e não "2121".

O que vem no request

O objeto request traz tudo sobre o pedido. Os mais usados no começo:

  • request.method: "GET" quando a pessoa só abre a página, "POST" quando envia um formulário (aula 205);
  • request.GET: os dados que vêm na URL depois do ?, como em /busca/?q=pastel&pagina=2;
  • request.user: quem está logado (aula 206).

Arquivo contatos/views.py (acrescente):

def busca(request):
    termo = request.GET.get("q", "")
    pagina = request.GET.get("pagina", "1")
    return HttpResponse(f"Você buscou: {termo} (página {pagina})")


def metodo(request):
    if request.method == "POST":
        return HttpResponse("Recebi dados enviados por um formulário")
    return HttpResponse("Você só abriu a página")

Você buscou: pastel (página 2)

Registre em contatos/urls.py com path("busca/", views.busca, name="busca") e path("metodo/", views.metodo, name="metodo"). Abrindo /busca/?q=pastel&pagina=2:

Use request.GET.get("q", ""), com um valor padrão, em vez de request.GET["q"]: se a pessoa abrir /busca/ sem o ?q=, o get devolve "" e o colchete daria erro.

A parte depois do ? se chama query string. O Python sabe separá-la sozinho com urllib.parse, e é isso que o Django faz para montar o request.GET:

from urllib.parse import urlsplit, parse_qs

endereco = "http://127.0.0.1:8000/busca/?q=pastel&pagina=2"
partes = urlsplit(endereco)
print("Caminho:", partes.path)
print("Query string:", partes.query)

dados = parse_qs(partes.query)
print(dados)
print("Termo:", dados.get("q", [""])[0])
print("Cor:", dados.get("cor", ["nenhuma"])[0])

Caminho: /busca/
Query string: q=pastel&pagina=2
{'q': ['pastel'], 'pagina': ['2']}
Termo: pastel
Cor: nenhuma

Os valores vêm em listas porque uma URL pode repetir o mesmo nome (?cor=azul&cor=verde). O request.GET.get do Django já devolve o último valor, sem lista.

Página não encontrada e nomes de rota

Quando a URL combina mas o dado não existe, a view deve responder 404. Para isso, levante a exceção Http404 (aula 53):

from django.http import Http404, HttpResponse

DIAS = {1: "segunda", 2: "terça", 3: "quarta", 4: "quinta", 5: "sexta"}


def dia(request, numero):
    if numero not in DIAS:
        raise Http404("Esse dia não existe")
    return HttpResponse(f"Dia {numero}: {DIAS[numero]}")

Dia 3: quarta

Com a rota path("dia/<int:numero>/", views.dia, name="dia"), abrir /dia/3/ mostra:

E /dia/9/ mostra a página de erro Page not found (404). Com DEBUG = True ela traz a mensagem "Esse dia não existe" para ajudar você; no site publicado, o visitante vê só uma página simples de "não encontrado".

O name="dia" de cada rota serve para gerar o endereço sem escrevê-lo à mão. Teste no python manage.py shell:

from django.urls import reverse

print(reverse("ola"))
print(reverse("dobro", args=[5]))

/ola/
/dobro/5/

Se um dia você mudar "dobro/" para "vezes-dois/", todo lugar que usa reverse("dobro") (ou {% url 'dobro' 5 %} nos templates) se atualiza sozinho.

Atenção: O erro NoReverseMatch aparece quando o nome da rota está escrito errado ou quando faltou passar o parâmetro: reverse("dobro") sem o número não tem como montar /dobro/<numero>/.
Pratique no DIGITAR: digite este trecho no modo Programar do app. 
path("dobro/<int:numero>/", views.dobro, name="dobro")
