Por que um banco de dados

Na aula 62 você salvou dados em JSON. Isso funciona bem para poucos dados e um só programa. Mas pense numa escola com milhares de alunos, notas e turmas, com a secretaria e os professores mexendo ao mesmo tempo. Ler o arquivo inteiro para achar um aluno fica lento, e duas pessoas gravando juntas podem estragar o arquivo.

Para isso existem os bancos de dados: programas especializados em guardar muitos dados, achar o que você pede rapidamente e não perder nada mesmo quando vários usuários mexem juntos.

Um banco relacional organiza tudo em tabelas, parecidas com planilhas:

  • cada coluna é um tipo de informação (nome, idade, turma);
  • cada linha (ou registro) é um item (um aluno);
  • a chave primária é a coluna que identifica cada linha sem nunca repetir (normalmente um número, o id).

O nome "relacional" vem de as tabelas poderem se relacionar umas com as outras — a aula 173 mostra como.

A linguagem SQL

Para conversar com o banco usamos o SQL (pronuncia-se "esse-quê-éle" ou "síquel"). Os comandos parecem frases em inglês: CREATE TABLE cria uma tabela, INSERT insere, SELECT busca.

O Python já vem com o SQLite, um banco pequeno e completo que guarda tudo num único arquivo — ou só na memória, com o nome especial ":memory:". É o banco que usaremos em todo o módulo:

import sqlite3

con = sqlite3.connect(":memory:")
con.execute("CREATE TABLE alunos (id INTEGER PRIMARY KEY, nome TEXT, idade INTEGER)")
con.execute("INSERT INTO alunos (nome, idade) VALUES ('Ana', 12)")
con.execute("INSERT INTO alunos (nome, idade) VALUES ('Caio', 13)")
for linha in con.execute("SELECT id, nome, idade FROM alunos"):
    print(linha)
con.close()

(1, 'Ana', 12)
(2, 'Caio', 13)

connect abre a conexão com o banco; execute manda um comando SQL; o SELECT devolve as linhas, e cada linha chega ao Python como uma tupla. Repare que o id foi preenchido sozinho: uma coluna INTEGER PRIMARY KEY é numerada automaticamente.

Dica: Na primeira vez que você roda um exemplo com sqlite3 aqui no site, o navegador baixa o módulo do SQLite. Pode levar alguns segundos; depois fica rápido.

SQL é declarativo

Em Python você diz como fazer: "percorra a lista, compare cada idade, guarde as que servem". Em SQL você diz o que quer — "os nomes dos alunos com 13 anos ou mais" — e o banco decide sozinho o jeito mais rápido de buscar. Por isso SQL é chamado de linguagem declarativa.

Compare as duas formas de responder à mesma pergunta:

import sqlite3

alunos = [("Ana", 12), ("Caio", 13), ("Duda", 14)]

# Python: você descreve o passo a passo
resposta = []
for nome, idade in alunos:
    if idade >= 13:
        resposta.append(nome)
print("Python:", resposta)

# SQL: você descreve o resultado que quer
con = sqlite3.connect(":memory:")
con.execute("CREATE TABLE alunos (nome TEXT, idade INTEGER)")
con.executemany("INSERT INTO alunos VALUES (?, ?)", alunos)
linhas = con.execute("SELECT nome FROM alunos WHERE idade >= 13").fetchall()
print("SQL:   ", [nome for (nome,) in linhas])
con.close()

Python: ['Caio', 'Duda']
SQL:    ['Caio', 'Duda']

executemany roda o mesmo INSERT para cada tupla da lista; cada ? é trocado por um valor (a aula 175 explica por que isso é importante). fetchall() pega todas as linhas do resultado de uma vez.

Dica: Escrever as palavras do SQL em MAIÚSCULAS (SELECT, FROM, WHERE) não é obrigatório, mas é o costume: ajuda a separar o que é comando do que é nome de tabela ou coluna.

Os tipos do SQLite

Cada coluna tem um tipo. O SQLite tem poucos e simples:

  • INTEGER — números inteiros (idade, quantidade);
  • REAL — números com vírgula (preço, nota);
  • TEXT — textos;
  • BLOB — dados binários, como o conteúdo de uma imagem;
  • NULL — não é bem um tipo: significa "sem valor", "não informado".

A função SQL typeof mostra o tipo de cada valor guardado:

import sqlite3

con = sqlite3.connect(":memory:")
con.execute("CREATE TABLE produtos (nome TEXT, preco REAL, estoque INTEGER)")
con.execute("INSERT INTO produtos VALUES ('Caderno', 18.5, 30)")
con.execute("INSERT INTO produtos VALUES ('Régua', NULL, 12)")
sql = "SELECT nome, typeof(nome), preco, typeof(preco), typeof(estoque) FROM produtos"
for linha in con.execute(sql):
    print(linha)
con.close()

('Caderno', 'text', 18.5, 'real', 'integer')
('Régua', 'text', None, 'null', 'integer')

O preço da régua não foi informado, então ficou NULL — e no Python o NULL vira None. NULL não é zero nem texto vazio: é a ausência de valor. Uma régua com preço 0 seria de graça; com preço NULL, ainda não sabemos o preço.

Atenção: Em SQL, textos vão entre aspas simples: 'Ana'. Aspas duplas no SQL indicam nome de coluna. Por isso, no Python, a string do comando costuma usar aspas duplas por fora e simples por dentro.

Chave primária: a identidade de cada linha

Por que não usar o nome como identificação? Porque dois alunos podem se chamar "Ana Souza". A chave primária precisa ser única e nunca mudar. O banco garante isso: tentar repetir uma chave dá erro.

import sqlite3

con = sqlite3.connect(":memory:")
con.execute("CREATE TABLE alunos (id INTEGER PRIMARY KEY, nome TEXT)")
con.execute("INSERT INTO alunos (id, nome) VALUES (1, 'Ana Souza')")
con.execute("INSERT INTO alunos (nome) VALUES ('Ana Souza')")
print(con.execute("SELECT * FROM alunos").fetchall())

try:
    con.execute("INSERT INTO alunos (id, nome) VALUES (1, 'Bruno')")
except sqlite3.IntegrityError as erro:
    print("O banco recusou:", erro)
con.close()

[(1, 'Ana Souza'), (2, 'Ana Souza')]
O banco recusou: UNIQUE constraint failed: alunos.id

As duas "Ana Souza" convivem sem problema, porque cada uma tem o seu id. Já o id 1 repetido foi barrado com IntegrityError, o erro de quem tenta quebrar uma regra do banco.

Banco na memória ou em arquivo

Com ":memory:", o banco some quando o programa termina — ótimo para aprender e testar. Com um nome de arquivo, como "escola.db", os dados ficam gravados no disco e continuam lá na próxima vez:

import sqlite3
from pathlib import Path

con = sqlite3.connect("escola.db")   # cria o arquivo se ele não existir
con.execute("CREATE TABLE IF NOT EXISTS recados (texto TEXT)")
con.execute("INSERT INTO recados VALUES ('Prova na sexta')")
con.commit()                          # grava as mudanças no arquivo
con.close()

print("Arquivo criado?", Path("escola.db").exists())
con = sqlite3.connect("escola.db")    # abrindo de novo, os dados continuam lá
print(con.execute("SELECT texto FROM recados").fetchall())
con.close()

Arquivo criado? True
[('Prova na sexta',)]

CREATE TABLE IF NOT EXISTS só cria a tabela se ela ainda não existir, para o programa poder rodar várias vezes. commit() confirma as mudanças; sem ele, o que você inseriu num banco em arquivo se perde ao fechar. A aula 171 volta a esse assunto.

Dica: Aqui no site, o arquivo escola.db fica num disco de mentira dentro do navegador e some ao recarregar a página. No seu computador, ele aparece de verdade na pasta do programa — e programas como o DB Browser for SQLite abrem esse arquivo para você ver as tabelas.

Bancos diferentes, a mesma ideia

Existem vários bancos relacionais: SQLite, MySQL, PostgreSQL, SQL Server. Os grandes rodam como um servidor separado, que vários computadores acessam pela rede; o SQLite é só um arquivo, perfeito para aplicativos, jogos e aprendizado. O SQL básico é quase igual em todos — o que você aprender neste módulo vale para os outros (a aula 176 mostra o MySQL).

import sqlite3

con = sqlite3.connect(":memory:")
versao = con.execute("SELECT sqlite_version()").fetchone()[0]
print("Versão do SQLite:", versao)
print(con.execute("SELECT 2 + 3, 'texto', 10 * 1.5, upper('sql')").fetchone())
con.close()

(exemplo — a sua saída pode ser diferente)
Versão do SQLite: 3.49.1
(5, 'texto', 15.0, 'SQL')

fetchone() pega só a primeira linha do resultado. Repare que dá para usar SELECT até sem tabela, como uma calculadora.

Pratique no DIGITAR: digite este trecho no modo Programar do app. 
con = sqlite3.connect(":memory:")

Exercícios

1. Crie uma tabela cidades com as colunas id, nome e estado, insira Salvador (BA) e Manaus (AM) e mostre todas as linhas.

Ver resposta 
import sqlite3

con = sqlite3.connect(":memory:")
con.execute("CREATE TABLE cidades (id INTEGER PRIMARY KEY, nome TEXT, estado TEXT)")
con.execute("INSERT INTO cidades (nome, estado) VALUES ('Salvador', 'BA')")
con.execute("INSERT INTO cidades (nome, estado) VALUES ('Manaus', 'AM')")
for linha in con.execute("SELECT * FROM cidades"):
    print(linha)
con.close()

(1, 'Salvador', 'BA')
(2, 'Manaus', 'AM')

O * no SELECT significa "todas as colunas".

2. Numa tabela de alunos, por que o nome não é uma boa chave primária?

Ver resposta

Porque dois alunos podem ter o mesmo nome, e a chave primária precisa ser única.
Além disso, o nome pode mudar (um erro de digitação corrigido, por exemplo).
Por isso usamos um número (id) que nunca se repete e nunca muda.

3. Que tipo do SQLite (INTEGER, REAL ou TEXT) você usaria para: a quantidade de figurinhas, o peso de uma pessoa, o CEP e o nome de um time? Pense no CEP com cuidado.

Ver resposta

quantidade de figurinhas -> INTEGER
peso                     -> REAL
CEP                      -> TEXT (não fazemos contas com CEP, e um CEP como
                            01310-100 perderia o zero da frente se fosse número)
nome de um time          -> TEXT

4. Crie uma tabela contatos (nome, telefone) e insira duas pessoas, uma delas sem telefone. Mostre as linhas e veja como o NULL aparece no Python.

Ver resposta 
import sqlite3

con = sqlite3.connect(":memory:")
con.execute("CREATE TABLE contatos (nome TEXT, telefone TEXT)")
con.execute("INSERT INTO contatos VALUES ('Lia', '71 99999-0000')")
con.execute("INSERT INTO contatos (nome) VALUES ('Davi')")
for nome, telefone in con.execute("SELECT nome, telefone FROM contatos"):
    print(nome, "->", telefone)
con.close()

Lia -> 71 99999-0000
Davi -> None

A coluna que não foi informada ficou NULL, que no Python aparece como None.

5. Use o SQLite como calculadora: com um único SELECT, mostre quanto é 7 vezes 8, a média de 6 e 9 e o texto 'python' em maiúsculas.

Ver resposta 
import sqlite3

con = sqlite3.connect(":memory:")
print(con.execute("SELECT 7 * 8, (6 + 9) / 2.0, upper('python')").fetchone())
con.close()

(56, 7.5, 'PYTHON')

Usamos 2.0 porque, diferente do Python, no SQLite a divisão de dois inteiros dá um inteiro: 15 / 2 daria 7.
