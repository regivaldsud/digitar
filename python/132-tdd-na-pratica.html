Módulo 6 · Testes automatizados

Aula 132 · TDD na prática: uma função do zero guiada por testes

Nesta aula você vai aprender

  • Aplicar o ciclo vermelho, verde e refatorar numa função de verdade
  • Crescer o código um teste de cada vez
  • Refatorar com segurança, sabendo que os testes avisam se algo quebrar
  • Transformar casos especiais em novos testes

O desafio

Vamos criar a função reais(valor), que transforma um número no jeito brasileiro de escrever dinheiro: reais(1234.5) deve dar "R$ 1.234,50". Parece simples, mas tem pegadinhas: a vírgula dos centavos, o ponto dos milhares e os números negativos.

Em vez de escrever tudo de uma vez, vamos seguir o TDD da aula 130: um teste, o código mínimo, melhorar, e de novo.

O primeiro teste é o caso mais simples: um valor redondo. A função ainda não existe de verdade, então o teste tem que falhar.

Passo 2 — verde

O código mais simples que passa: formatar com duas casas e trocar o ponto pela vírgula.

import unittest


def reais(valor):
    texto = f"{valor:.2f}"
    return "R$ " + texto.replace(".", ",")


class TestReais(unittest.TestCase):
    def test_valor_redondo(self):
        self.assertEqual(reais(5), "R$ 5,00")

    def test_centavos(self):
        self.assertEqual(reais(3.5), "R$ 3,50")


unittest.main(argv=[""], exit=False)

Passo 3 — vermelho de novo: os milhares

Próximo caso: reais(1234.5) deve dar "R$ 1.234,50". Com o código atual, sai "R$ 1234,50", sem o ponto. O novo teste falha (vermelho) e nos obriga a melhorar o código. O formato {valor:,.2f} coloca vírgula nos milhares e ponto nos centavos, o jeito americano: 1,234.50. Basta trocar um pelo outro, usando um caractere temporário:

import unittest


def reais(valor):
    americano = f"{valor:,.2f}"            # 1,234.50
    trocado = americano.replace(",", "#")  # 1#234.50
    trocado = trocado.replace(".", ",")    # 1#234,50
    trocado = trocado.replace("#", ".")    # 1.234,50
    return "R$ " + trocado


class TestReais(unittest.TestCase):
    def test_valor_redondo(self):
        self.assertEqual(reais(5), "R$ 5,00")

    def test_centavos(self):
        self.assertEqual(reais(3.5), "R$ 3,50")

    def test_milhar(self):
        self.assertEqual(reais(1234.5), "R$ 1.234,50")

    def test_milhao(self):
        self.assertEqual(reais(2500000), "R$ 2.500.000,00")


unittest.main(argv=[""], exit=False)

....

Atenção: Trocar "," por "." e depois "." por "," diretamente estraga tudo: no fim, todos viram vírgula. Por isso o # temporário. É exatamente o tipo de erro que um teste pega na hora.

Passo 4 — refatorar

Os testes estão verdes, então podemos deixar o código mais elegante sem medo. O método translate troca vários caracteres de uma vez, sem precisar do #:

import unittest

TROCA = str.maketrans(",.", ".,")


def reais(valor):
    return "R$ " + f"{valor:,.2f}".translate(TROCA)


class TestReais(unittest.TestCase):
    def test_valor_redondo(self):
        self.assertEqual(reais(5), "R$ 5,00")

    def test_centavos(self):
        self.assertEqual(reais(3.5), "R$ 3,50")

    def test_milhar(self):
        self.assertEqual(reais(1234.5), "R$ 1.234,50")

    def test_milhao(self):
        self.assertEqual(reais(2500000), "R$ 2.500.000,00")


unittest.main(argv=[""], exit=False)

....

OK

Quatro testes, todos verdes: a refatoração não quebrou nada.

Passo 5 — um caso especial vira teste

E os valores negativos, como um saldo devedor? Decidimos que reais(-80) deve dar "-R$ 80,00". Primeiro o teste (vermelho), depois o código (verde):

import unittest

TROCA = str.maketrans(",.", ".,")


def reais(valor):
    sinal = "-" if valor < 0 else ""
    return sinal + "R$ " + f"{abs(valor):,.2f}".translate(TROCA)


class TestReais(unittest.TestCase):
    def test_valor_redondo(self):
        self.assertEqual(reais(5), "R$ 5,00")

    def test_milhar(self):
        self.assertEqual(reais(1234.5), "R$ 1.234,50")

    def test_negativo(self):
        self.assertEqual(reais(-80), "-R$ 80,00")

    def test_zero(self):
        self.assertEqual(reais(0), "R$ 0,00")


unittest.main(argv=[""], exit=False)

4. Por que é importante ver o teste falhar (vermelho) antes de escrever o código?

Ver resposta

Porque prova que o teste é capaz de pegar um erro.
Se o teste passasse mesmo sem o código pronto, ele estaria testando errado
(por exemplo, comparando a coisa errada) e nunca avisaria de um bug.
