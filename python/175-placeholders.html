Aula 175 · Placeholders e como evitar SQL Injection

Nesta aula você vai aprender

  • Entender o que é SQL Injection e por que é tão perigoso

O perigo de montar SQL juntando textos

Um comando SQL é só um texto. Quando o programa monta esse texto colando pedaços que vieram do usuário, quem digita pode mudar o sentido do comando. Esse ataque se chama SQL Injection ("injeção de SQL") e há décadas está entre as falhas de segurança mais comuns da internet.

Veja o que acontece quando alguém digita um "nome" esperto numa busca montada com f-string:

import sqlite3

con = sqlite3.connect(":memory:")
con.execute("CREATE TABLE usuarios (nome TEXT, senha TEXT)")
con.execute("INSERT INTO usuarios VALUES ('ana', 'segredo123')")
con.execute("INSERT INTO usuarios VALUES ('caio', 'abacaxi')")

nome = "qualquer' OR '1'='1"
sql = f"SELECT * FROM usuarios WHERE nome = '{nome}'"
print(sql)
print("Linhas encontradas:", con.execute(sql).fetchall())
con.close()

SELECT * FROM usuarios WHERE nome = 'qualquer' OR '1'='1'
Linhas encontradas: [('ana', 'segredo123'), ('caio', 'abacaxi')]

O texto digitado fechou a aspa e acrescentou OR '1'='1', que é sempre verdadeiro. O banco obedeceu e devolveu todos os usuários, com as senhas.

Atenção: Os exemplos desta aula são só para entender o ataque no seu próprio banco de treino. Tentar isso em sites e sistemas de outras pessoas é crime.

Um login que pode ser enganado

O caso clássico é a tela de login. O programa monta o comando com o nome e a senha digitados:

import sqlite3

con = sqlite3.connect(":memory:")
con.execute("CREATE TABLE usuarios (nome TEXT, senha TEXT)")
con.execute("INSERT INTO usuarios VALUES ('ana', 'segredo123')")


def login_inseguro(nome, senha):
    sql = f"SELECT nome FROM usuarios WHERE nome = '{nome}' AND senha = '{senha}'"
    linha = con.execute(sql).fetchone()
    return linha is not None


print("Senha certa:  ", login_inseguro("ana", "segredo123"))
print("Senha errada: ", login_inseguro("ana", "chute"))
print("Ataque:       ", login_inseguro("ana", "x' OR '1'='1"))
con.close()

Senha certa:   True
Senha errada:  False
Ataque:        True

Com a "senha" x' OR '1'='1, o comando final fica ... AND senha = 'x' OR '1'='1'. Como o OR '1'='1' é sempre verdadeiro, o programa deixa a pessoa entrar sem saber a senha.

A solução: placeholders

Com o placeholder ?, o comando e os valores viajam separados até o banco. O banco primeiro entende o comando e depois encaixa cada valor no seu lugar, sempre como dado, nunca como parte do comando. Uma aspa dentro do valor vira só uma aspa, sem poder fechar nada.

import sqlite3

con = sqlite3.connect(":memory:")
con.execute("CREATE TABLE usuarios (nome TEXT, senha TEXT)")
con.execute("INSERT INTO usuarios VALUES (?, ?)", ("ana", "segredo123"))


def login_seguro(nome, senha):
    sql = "SELECT nome FROM usuarios WHERE nome = ? AND senha = ?"
    linha = con.execute(sql, (nome, senha)).fetchone()
    return linha is not None


print("Senha certa:  ", login_seguro("ana", "segredo123"))
print("Senha errada: ", login_seguro("ana", "chute"))
print("Ataque:       ", login_seguro("ana", "x' OR '1'='1"))

# de bônus: nomes com aspa, como D'Ávila, funcionam sem quebrar nada
con.execute("INSERT INTO usuarios VALUES (?, ?)", ("Pedro D'Ávila", "mangaba"))
print(con.execute("SELECT nome FROM usuarios WHERE nome = ?", ("Pedro D'Ávila",)).fetchone())
con.close()

Senha certa:   True
Senha errada:  False
Ataque:        False
("Pedro D'Ávila",)

Repare que o mesmo cuidado resolve outro problema: com f-string, um nome como D'Ávila quebraria o comando com erro de sintaxe. Com placeholder, ele entra normalmente.

Dica: Num sistema de verdade, a senha também nunca é guardada como texto puro: guarda-se um "resumo" dela (um hash, com bibliotecas como hashlib ou bcrypt). Aqui deixamos a senha visível só para o exemplo ficar curto.

Placeholders com nome

Quando há muitos valores, contar a posição de cada ? fica confuso. Use :nome no comando e passe um dicionário:

import sqlite3

con = sqlite3.connect(":memory:")
con.execute("CREATE TABLE contatos (nome TEXT, cidade TEXT, telefone TEXT)")
contato = {"nome": "Beto", "cidade": "Belém", "telefone": "(91) 90000-0000"}
con.execute("INSERT INTO contatos VALUES (:nome, :cidade, :telefone)", contato)

novos = [
    {"nome": "Lia", "cidade": "Recife", "telefone": "(81) 90000-0001"},
    {"nome": "Rui", "cidade": "Belém", "telefone": "(91) 90000-0002"},
]
con.executemany("INSERT INTO contatos VALUES (:nome, :cidade, :telefone)", novos)

for linha in con.execute("SELECT nome, telefone FROM contatos WHERE cidade = :c", {"c": "Belém"}):
    print(linha)
con.close()

('Beto', '(91) 90000-0000')
('Rui', '(91) 90000-0002')

executemany roda o mesmo comando uma vez para cada item da lista. Funciona com tuplas e ? ou com dicionários e :nome.

Atenção: O número de valores precisa bater com o número de placeholders. con.execute("... VALUES (?, ?)", ("Ana",)) dá ProgrammingError: Incorrect number of bindings supplied.

O que não pode ser placeholder

Placeholders servem só para valores (um texto, um número, uma data). Nomes de tabela e de coluna fazem parte do comando e não podem ser ?. Se o usuário pode escolher, por exemplo, por qual coluna ordenar, confira a escolha contra uma lista de nomes permitidos antes de montar o comando:

import sqlite3

con = sqlite3.connect(":memory:")
con.execute("CREATE TABLE alunos (nome TEXT, idade INTEGER, cidade TEXT)")
con.executemany("INSERT INTO alunos VALUES (?, ?, ?)",
                [("Ana", 13, "Natal"), ("Caio", 12, "Cuiabá"), ("Bia", 14, "Aracaju")])

PERMITIDAS = {"nome", "idade", "cidade"}


def listar_ordenado(coluna):
    if coluna not in PERMITIDAS:
        raise ValueError(f"Coluna não permitida: {coluna!r}")
    sql = f"SELECT nome, idade FROM alunos ORDER BY {coluna}"
    return con.execute(sql).fetchall()


print(listar_ordenado("idade"))
try:
    listar_ordenado("nome; DROP TABLE alunos")
except ValueError as erro:
    print(erro)
con.close()

[('Caio', 12), ('Ana', 13), ('Bia', 14)]
Coluna não permitida: 'nome; DROP TABLE alunos'

Aqui a f-string é aceitável só porque a coluna já foi conferida: ela é obrigatoriamente uma das três palavras da lista. Qualquer outra coisa é recusada antes de chegar ao banco.

Pratique no DIGITAR: digite este trecho no modo Programar do app. 
con.execute("SELECT * FROM usuarios WHERE nome = ?", (nome,))

for busca in ["' OR ''='", "Central do Brasil"]:

4. Escreva contar_por(coluna) que conta quantos alunos há em cada valor da coluna escolhida (cidade ou turma), recusando qualquer outra coluna com ValueError.

Ver resposta 
import sqlite3

con = sqlite3.connect(":memory:")
con.execute("CREATE TABLE alunos (nome TEXT, cidade TEXT, turma TEXT)")
con.executemany("INSERT INTO alunos VALUES (?, ?, ?)", [
    ("Ana", "Natal", "7A"), ("Caio", "Natal", "7B"), ("Bia", "Recife", "7A"),
])


def contar_por(coluna):
    if coluna not in {"cidade", "turma"}:
        raise ValueError("coluna não permitida")
    sql = f"SELECT {coluna}, COUNT(*) FROM alunos GROUP BY {coluna} ORDER BY {coluna}"
    return con.execute(sql).fetchall()


print(contar_por("cidade"))
print(contar_por("turma"))
try:
    contar_por("senha")
except ValueError as erro:
    print("Recusado:", erro)
con.close()

[('Natal', 2), ('Recife', 1)]
[('7A', 2), ('7B', 1)]
Recusado: coluna não permitida

5. Explique com suas palavras por que o placeholder impede o SQL Injection e a f-string não.

Ver resposta

Com f-string, o valor digitado é colado DENTRO do texto do comando antes de ele
chegar ao banco. Uma aspa no valor pode fechar o texto e o resto vira comando.
Com placeholder, o comando e os valores vão separados: o banco entende o comando
primeiro e depois encaixa cada valor como dado. O valor nunca vira comando.
