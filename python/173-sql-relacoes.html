Dividir para não repetir

Imagine uma tabela de pedidos que guardasse, em cada linha, o nome, o e-mail e o endereço do cliente. Um cliente com 50 pedidos teria os dados repetidos 50 vezes. Se ele mudasse de e-mail, seria preciso alterar 50 linhas — e se uma ficasse esquecida, o banco teria dois e-mails diferentes para a mesma pessoa.

A solução é separar: uma tabela clientes, com cada cliente uma única vez, e uma tabela pedidos que guarda só o número (id) do cliente. Essa coluna que aponta para a chave primária de outra tabela é a chave estrangeira (em inglês, *foreign key*).

import sqlite3

con = sqlite3.connect(":memory:")
con.executescript("""
    CREATE TABLE clientes (id INTEGER PRIMARY KEY, nome TEXT, email TEXT);
    CREATE TABLE pedidos (
        id INTEGER PRIMARY KEY,
        cliente_id INTEGER REFERENCES clientes(id),
        produto TEXT
    );
    INSERT INTO clientes (nome, email) VALUES ('Lia', 'lia@email.com');
    INSERT INTO pedidos (cliente_id, produto) VALUES (1, 'Fone'), (1, 'Capinha'), (1, 'Cabo');
""")
print("pedidos:", con.execute("SELECT * FROM pedidos").fetchall())

con.execute("UPDATE clientes SET email = 'lia.nova@email.com' WHERE id = 1")
print("e-mail trocado em um lugar só:", con.execute("SELECT email FROM clientes").fetchone())
con.close()

pedidos: [(1, 1, 'Fone'), (2, 1, 'Capinha'), (3, 1, 'Cabo')]
e-mail trocado em um lugar só: ('lia.nova@email.com',)

executescript roda vários comandos de uma vez, separados por ;. REFERENCES clientes(id) diz ao banco que cliente_id aponta para o id da tabela clientes. Os três pedidos guardam só o número 1, e o e-mail mudou num único lugar.

Tipos de relação

  • 1 para N (um para muitos): um cliente tem muitos pedidos, mas cada pedido é de um só cliente. A chave estrangeira fica no lado "muitos" (pedidos.cliente_id).
  • N para N (muitos para muitos): um aluno faz várias matérias e cada matéria tem vários alunos. Aqui não dá para pôr uma coluna só em nenhum dos lados; usamos uma terceira tabela, a tabela de ligação, que você verá mais adiante nesta aula.
  • 1 para 1: um aluno tem uma carteirinha. É mais raro; muitas vezes as colunas ficam na mesma tabela.

Juntando com INNER JOIN

Separar é ótimo para guardar, mas na hora de mostrar queremos o nome do cliente junto com cada pedido. O JOIN junta as tabelas na consulta, combinando as linhas pela condição do ON:

import sqlite3

con = sqlite3.connect(":memory:")
con.executescript("""
    CREATE TABLE clientes (id INTEGER PRIMARY KEY, nome TEXT);
    CREATE TABLE pedidos (
        id INTEGER PRIMARY KEY,
        cliente_id INTEGER REFERENCES clientes(id),
        produto TEXT,
        valor REAL
    );
    INSERT INTO clientes (nome) VALUES ('Lia'), ('Davi'), ('Rosa');
    INSERT INTO pedidos (cliente_id, produto, valor) VALUES
        (1, 'Fone', 89.9), (1, 'Capinha', 25.0), (2, 'Mouse', 59.0);
""")
sql = """
    SELECT clientes.nome, pedidos.produto, pedidos.valor
    FROM pedidos
    INNER JOIN clientes ON clientes.id = pedidos.cliente_id
    ORDER BY pedidos.id
"""
for nome, produto, valor in con.execute(sql):
    print(f"{nome:<5} comprou {produto:<8} R$ {valor:6.2f}")
con.close()

Lia   comprou Fone     R$  89.90
Lia   comprou Capinha  R$  25.00
Davi  comprou Mouse    R$  59.00

Para cada pedido, o banco procura o cliente cujo id é igual ao cliente_id e junta as colunas dos dois. Como as duas tabelas têm uma coluna id, escrevemos tabela.coluna para não haver confusão. Só JOIN significa o mesmo que INNER JOIN.

Atenção: Esquecer o ON é um erro clássico: sem ele, o banco combina cada pedido com cada cliente (3 pedidos × 3 clientes = 9 linhas sem sentido). Se o resultado veio com linhas demais, confira o ON.

LEFT JOIN: incluindo quem não tem par

A Rosa não fez pedidos, por isso não apareceu acima: o INNER JOIN só mostra as linhas que têm par nas duas tabelas. O LEFT JOIN mantém todas as linhas da tabela da esquerda (a do FROM), mesmo sem par; as colunas da outra tabela vêm como NULL:

import sqlite3

con = sqlite3.connect(":memory:")
con.executescript("""
    CREATE TABLE clientes (id INTEGER PRIMARY KEY, nome TEXT);
    CREATE TABLE pedidos (id INTEGER PRIMARY KEY, cliente_id INTEGER, produto TEXT);
    INSERT INTO clientes (nome) VALUES ('Lia'), ('Davi'), ('Rosa');
    INSERT INTO pedidos (cliente_id, produto) VALUES (1, 'Fone'), (1, 'Capinha'), (2, 'Mouse');
""")
sql = """
    SELECT c.nome, p.produto
    FROM clientes AS c
    LEFT JOIN pedidos AS p ON p.cliente_id = c.id
    ORDER BY c.nome, p.produto
"""
for linha in con.execute(sql):
    print(linha)

print("Clientes sem nenhum pedido:")
sql = """
    SELECT c.nome FROM clientes AS c
    LEFT JOIN pedidos AS p ON p.cliente_id = c.id
    WHERE p.id IS NULL
"""
print(con.execute(sql).fetchall())
con.close()

('Davi', 'Mouse')
('Lia', 'Capinha')
('Lia', 'Fone')
('Rosa', None)
Clientes sem nenhum pedido:
[('Rosa',)]

AS c dá um apelido curto à tabela, para não repetir o nome inteiro. O truque LEFT JOIN ... WHERE p.id IS NULL é o jeito clássico de achar "quem não tem nenhum".

JOIN com GROUP BY: relatórios

Juntar e agrupar ao mesmo tempo responde perguntas como "quantos pedidos e quanto gastou cada cliente?":

import sqlite3

con = sqlite3.connect(":memory:")
con.executescript("""
    CREATE TABLE clientes (id INTEGER PRIMARY KEY, nome TEXT);
    CREATE TABLE pedidos (id INTEGER PRIMARY KEY, cliente_id INTEGER, valor REAL);
    INSERT INTO clientes (nome) VALUES ('Lia'), ('Davi'), ('Rosa');
    INSERT INTO pedidos (cliente_id, valor) VALUES (1, 89.9), (1, 25.0), (2, 59.0);
""")
sql = """
    SELECT c.nome, COUNT(p.id) AS qtd, COALESCE(SUM(p.valor), 0) AS total
    FROM clientes AS c
    LEFT JOIN pedidos AS p ON p.cliente_id = c.id
    GROUP BY c.id
    ORDER BY total DESC
"""
for nome, qtd, total in con.execute(sql):
    print(f"{nome}: {qtd} pedido(s), R$ {total:.2f}")
con.close()

Lia: 2 pedido(s), R$ 114.90
Davi: 1 pedido(s), R$ 59.00
Rosa: 0 pedido(s), R$ 0.00

COUNT(p.id) conta só os pedidos que existem (o NULL da Rosa não conta), por isso ela aparece com 0. COALESCE(x, 0) troca o vazio (NULL) por 0 — sem ele, o total da Rosa seria None.

Dica: Ao montar um JOIN difícil, vá por partes: primeiro rode só o JOIN e confira as linhas; depois acrescente o GROUP BY e as somas.

Garantindo as ligações: PRAGMA foreign_keys

A chave estrangeira também serve para o banco proteger as ligações: não deixar criar um pedido de um cliente que não existe, nem apagar um cliente que ainda tem pedidos. Mas, no SQLite, essa checagem vem desligada por padrão. Ligue com PRAGMA foreign_keys = ON logo depois de conectar:

import sqlite3

con = sqlite3.connect(":memory:")
con.execute("PRAGMA foreign_keys = ON")
con.executescript("""
    CREATE TABLE clientes (id INTEGER PRIMARY KEY, nome TEXT);
    CREATE TABLE pedidos (id INTEGER PRIMARY KEY,
                          cliente_id INTEGER NOT NULL REFERENCES clientes(id));
    INSERT INTO clientes (nome) VALUES ('Lia');
    INSERT INTO pedidos (cliente_id) VALUES (1);
""")
tentativas = {
    "pedido do cliente 99": "INSERT INTO pedidos (cliente_id) VALUES (99)",
    "apagar a Lia": "DELETE FROM clientes WHERE id = 1",
}
for descricao, comando in tentativas.items():
    try:
        con.execute(comando)
    except sqlite3.IntegrityError as erro:
        print(f"Barrado ({descricao}): {erro}")
con.close()

Barrado (pedido do cliente 99): FOREIGN KEY constraint failed
Barrado (apagar a Lia): FOREIGN KEY constraint failed

Os dois comandos foram recusados: o cliente 99 não existe, e a Lia ainda tem um pedido ligado a ela.

Atenção: O PRAGMA foreign_keys = ON vale por conexão: cada vez que o programa conecta ao banco, precisa rodar o comando de novo. Sem ele, o SQLite aceita cliente_id inválidos em silêncio.

N para N e ON DELETE CASCADE

Para a relação "alunos fazem matérias", criamos a tabela de ligação matriculas, com uma chave estrangeira para cada lado. Cada linha dela diz "este aluno faz esta matéria". Com ON DELETE CASCADE, quando um aluno é apagado, as matrículas dele somem junto, em vez de o banco recusar o DELETE:

import sqlite3

con = sqlite3.connect(":memory:")
con.execute("PRAGMA foreign_keys = ON")
con.executescript("""
    CREATE TABLE alunos (id INTEGER PRIMARY KEY, nome TEXT);
    CREATE TABLE materias (id INTEGER PRIMARY KEY, nome TEXT);
    CREATE TABLE matriculas (
        aluno_id INTEGER REFERENCES alunos(id) ON DELETE CASCADE,
        materia_id INTEGER REFERENCES materias(id) ON DELETE CASCADE,
        PRIMARY KEY (aluno_id, materia_id)
    );
    INSERT INTO alunos (nome) VALUES ('Ana'), ('Caio'), ('Duda');
    INSERT INTO materias (nome) VALUES ('Robótica'), ('Xadrez'), ('Teatro');
    INSERT INTO matriculas VALUES (1, 1), (1, 2), (2, 1), (3, 3), (3, 2);
""")
sql = """
    SELECT m.nome, GROUP_CONCAT(a.nome, ', ')
    FROM matriculas AS mt
    JOIN alunos AS a ON a.id = mt.aluno_id
    JOIN materias AS m ON m.id = mt.materia_id
    GROUP BY m.id
    ORDER BY m.nome
"""
for materia, alunos in con.execute(sql):
    print(f"{materia}: {alunos}")

con.execute("DELETE FROM alunos WHERE nome = 'Ana'")
print("Matrículas depois de apagar a Ana:",
      con.execute("SELECT COUNT(*) FROM matriculas").fetchone()[0])
con.close()

Robótica: Ana, Caio
Teatro: Duda
Xadrez: Ana, Duda
Matrículas depois de apagar a Ana: 3

Dá para encadear vários JOIN: aqui, cada matrícula ganha o nome do aluno e o nome da matéria. A chave primária (aluno_id, materia_id) é formada por duas colunas e impede matricular o mesmo aluno duas vezes na mesma matéria. GROUP_CONCAT junta os nomes de cada grupo num texto só. Das 5 matrículas sobraram 3, porque as 2 da Ana foram apagadas em cascata.

Pratique no DIGITAR: digite este trecho no modo Programar do app. 
JOIN clientes ON clientes.id = pedidos.cliente_id

Exercícios

1. Crie as tabelas turmas (id, nome) e alunos (id, nome, turma_id) e mostre cada aluno com o nome da sua turma.

Ver resposta 
import sqlite3

con = sqlite3.connect(":memory:")
con.executescript("""
    CREATE TABLE turmas (id INTEGER PRIMARY KEY, nome TEXT);
    CREATE TABLE alunos (id INTEGER PRIMARY KEY, nome TEXT, turma_id INTEGER REFERENCES turmas(id));
    INSERT INTO turmas (nome) VALUES ('7º A'), ('8º B');
    INSERT INTO alunos (nome, turma_id) VALUES ('Ana', 1), ('Caio', 2), ('Duda', 1);
""")
sql = """
    SELECT alunos.nome, turmas.nome FROM alunos
    JOIN turmas ON turmas.id = alunos.turma_id
    ORDER BY alunos.nome
"""
for aluno, turma in con.execute(sql):
    print(aluno, "-", turma)
con.close()

Ana - 7º A
Caio - 8º B
Duda - 7º A

2. Com PRAGMA foreign_keys = ON, o que acontece ao inserir um pedido com cliente_id 99, que não existe? Teste.

Ver resposta 
import sqlite3

con = sqlite3.connect(":memory:")
con.execute("PRAGMA foreign_keys = ON")
con.execute("CREATE TABLE clientes (id INTEGER PRIMARY KEY, nome TEXT)")
con.execute("CREATE TABLE pedidos (id INTEGER PRIMARY KEY, cliente_id INTEGER REFERENCES clientes(id))")
try:
    con.execute("INSERT INTO pedidos (cliente_id) VALUES (99)")
except sqlite3.IntegrityError as e:
    print("Erro:", e)
con.close()

Erro: FOREIGN KEY constraint failed

O banco recusa com IntegrityError. Sem o PRAGMA, o pedido seria aceito e ficaria apontando para um cliente que não existe.

3. Mostre quantos alunos tem cada turma, incluindo uma turma que ainda não tem nenhum aluno.

Ver resposta 
import sqlite3

con = sqlite3.connect(":memory:")
con.executescript("""
    CREATE TABLE turmas (id INTEGER PRIMARY KEY, nome TEXT);
    CREATE TABLE alunos (id INTEGER PRIMARY KEY, nome TEXT, turma_id INTEGER REFERENCES turmas(id));
    INSERT INTO turmas (nome) VALUES ('7º A'), ('8º B'), ('9º C');
    INSERT INTO alunos (nome, turma_id) VALUES ('Ana', 1), ('Caio', 2), ('Duda', 1);
""")
sql = """
    SELECT t.nome, COUNT(a.id)
    FROM turmas AS t
    LEFT JOIN alunos AS a ON a.turma_id = t.id
    GROUP BY t.id
    ORDER BY t.nome
"""
for turma, qtd in con.execute(sql):
    print(f"{turma}: {qtd} aluno(s)")
con.close()

7º A: 2 aluno(s)
8º B: 1 aluno(s)
9º C: 0 aluno(s)

Com INNER JOIN, o 9º C sumiria do resultado; o LEFT JOIN mantém todas as turmas.

4. Uma biblioteca tem livros e autores, e um livro pode ter vários autores. Que tabelas você criaria? Monte-as e mostre os autores de cada livro.

Ver resposta 
import sqlite3

con = sqlite3.connect(":memory:")
con.execute("PRAGMA foreign_keys = ON")
con.executescript("""
    CREATE TABLE livros (id INTEGER PRIMARY KEY, titulo TEXT);
    CREATE TABLE autores (id INTEGER PRIMARY KEY, nome TEXT);
    CREATE TABLE livro_autor (
        livro_id INTEGER REFERENCES livros(id),
        autor_id INTEGER REFERENCES autores(id),
        PRIMARY KEY (livro_id, autor_id)
    );
    INSERT INTO livros (titulo) VALUES ('Contos da Floresta'), ('Robôs na Escola');
    INSERT INTO autores (nome) VALUES ('Bia Rocha'), ('Tomás Lima'), ('Iara Melo');
    INSERT INTO livro_autor VALUES (1, 1), (2, 2), (2, 3);
""")
sql = """
    SELECT l.titulo, a.nome
    FROM livro_autor AS la
    JOIN livros AS l ON l.id = la.livro_id
    JOIN autores AS a ON a.id = la.autor_id
    ORDER BY l.titulo, a.nome
"""
for titulo, autor in con.execute(sql):
    print(f"{titulo} - {autor}")
con.close()

Contos da Floresta - Bia Rocha
Robôs na Escola - Iara Melo
Robôs na Escola - Tomás Lima

É uma relação N para N: além de livros e autores, é preciso a tabela de ligação livro_autor, com uma linha para cada par livro-autor.

5. Liste os clientes que nunca fizeram um pedido.

Ver resposta 
import sqlite3

con = sqlite3.connect(":memory:")
con.executescript("""
    CREATE TABLE clientes (id INTEGER PRIMARY KEY, nome TEXT);
    CREATE TABLE pedidos (id INTEGER PRIMARY KEY, cliente_id INTEGER REFERENCES clientes(id));
    INSERT INTO clientes (nome) VALUES ('Lia'), ('Davi'), ('Rosa'), ('Téo');
    INSERT INTO pedidos (cliente_id) VALUES (1), (1), (3);
""")
sql = """
    SELECT c.nome FROM clientes AS c
    LEFT JOIN pedidos AS p ON p.cliente_id = c.id
    WHERE p.id IS NULL
    ORDER BY c.nome
"""
print([nome for (nome,) in con.execute(sql)])
con.close()

['Davi', 'Téo']

O LEFT JOIN traz todos os clientes; os que não têm pedido ficam com p.id em NULL, e o WHERE p.id IS NULL separa justamente esses.
