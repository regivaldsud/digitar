Por que a janela "congela"

Lembra do app.exec() da aula 190? Ele liga o laço de eventos: uma repetição que pega, um por um, os acontecimentos da fila (um clique, uma tecla, "redesenhe a janela") e chama o código certo para cada um.

O laço só atende o próximo evento quando o anterior termina. Se o seu slot demora 10 segundos (baixando um arquivo, contando palavras de um livro inteiro), durante esses 10 segundos ninguém redesenha a janela nem atende cliques. O Windows mostra "Não respondendo". Este laço de mentira mostra o problema:

eventos = ["desenhar a janela", "clique em Começar", "mover o mouse", "redesenhar a barra"]
duracao = {"clique em Começar": 10}  # o clique dispara uma tarefa de 10 segundos

relogio = 0
for evento in eventos:
    print(f"t={relogio:>2}s  atendendo: {evento}")
    relogio += duracao.get(evento, 0)
print(f"t={relogio:>2}s  fila vazia")

t= 0s  atendendo: desenhar a janela
t= 0s  atendendo: clique em Começar
t=10s  atendendo: mover o mouse
t=10s  atendendo: redesenhar a barra
t=10s  fila vazia

O movimento do mouse aconteceu logo depois do clique, mas só foi atendido 10 segundos depois. Para o usuário, o programa travou.

Atenção: Colocar time.sleep() ou um laço demorado dentro de um slot é a causa número um de janelas travadas. O laço de eventos precisa ficar livre o tempo todo.

Uma saída simples: dividir o trabalho em pedaços

Uma ideia é fazer a tarefa em pedacinhos e devolver a vez para o laço de eventos entre um pedaço e outro. Um gerador (aula 52) faz isso bem: cada yield é uma pausa.

def tarefa_longa():
    for parte in range(1, 6):
        yield f"parte {parte} de 5 pronta"


tarefa = tarefa_longa()
outros_eventos = ["mouse", "tecla", "redesenhar"]

for passo in tarefa:
    print("trabalho:", passo)
    if outros_eventos:
        print("   janela atende:", outros_eventos.pop(0))

trabalho: parte 1 de 5 pronta
   janela atende: mouse
trabalho: parte 2 de 5 pronta
   janela atende: tecla
trabalho: parte 3 de 5 pronta
   janela atende: redesenhar
trabalho: parte 4 de 5 pronta
trabalho: parte 5 de 5 pronta

No Qt, esse revezamento é feito com um QTimer que chama um pedaço da tarefa de tempos em tempos. Funciona para tarefas que dá para cortar em partes. Quando não dá (uma única operação demorada, como esperar a resposta da internet), a solução é uma thread.

Threads: duas linhas de execução

Uma thread é uma linha de execução: um caminho que o computador vai percorrendo no seu código. Todo programa começa com uma, a thread principal, que é a da janela. Você pode criar outras para rodar trabalho ao mesmo tempo.

O módulo threading da biblioteca padrão mostra a ideia. A outra thread não conversa direto com a principal: ela coloca recados numa queue.Queue (uma fila segura para threads), e a principal lê os recados.

Salve como threads.py e rode com python threads.py (o navegador deste site não consegue criar threads, por isso este bloco não tem o botão Executar):

import queue
import threading
import time


def trabalhador(recados):
    for i in range(1, 6):
        time.sleep(0.1)          # finge um trabalho demorado
        recados.put(i * 20)      # avisa o progresso
    recados.put(None)            # avisa que terminou


recados = queue.Queue()
t = threading.Thread(target=trabalhador, args=(recados,))
t.start()
print("A thread principal continua livre!")

while True:
    valor = recados.get()
    if valor is None:
        break
    print(f"progresso: {valor}%")

t.join()
print("Trabalho terminado.")

A thread principal continua livre!
progresso: 20%
progresso: 40%
progresso: 60%
progresso: 80%
progresso: 100%
Trabalho terminado.

  • Thread(target=..., args=...) prepara a thread com a função que ela vai rodar;
  • start() começa a rodar; a linha seguinte do programa já roda junto, sem esperar;
  • join() espera a thread acabar.
Dica: Repare que a frase "A thread principal continua livre!" apareceu antes do progresso. É exatamente isso que queremos numa janela: o trabalho anda numa thread e a tela continua respondendo na outra.

Sinais: como um trabalhador avisa a janela

No Qt, o jeito certo de uma thread dar recados para a janela é com sinais (aula 192). Por dentro, um sinal é simples: uma lista de funções que são chamadas quando alguém "emite". Esta versão de brinquedo roda aqui:

class Sinal:
    def __init__(self):
        self.slots = []

    def connect(self, funcao):
        self.slots.append(funcao)

    def emit(self, *valores):
        for funcao in self.slots:
            funcao(*valores)


progresso = Sinal()
progresso.connect(lambda v: print(f"barra em {v}%"))
progresso.connect(lambda v: print("  título: Copiando...", v))

for v in (25, 50, 100):
    progresso.emit(v)

barra em 25%
  título: Copiando... 25
barra em 50%
  título: Copiando... 50
barra em 100%
  título: Copiando... 100

O Qt faz uma coisa a mais, que a versão de brinquedo não faz: quando o sinal é emitido numa thread e o slot pertence a um widget da thread principal, o Qt coloca o recado na fila do laço de eventos em vez de chamar o slot na hora. Assim, quem mexe na barra é sempre a thread da janela.

O padrão trabalhador + QThread

Juntando tudo: um objeto trabalhador (QObject) com sinais próprios, movido para um QThread. Instale o PySide6 no ambiente virtual (pip install pyside6), salve como progresso.py e rode com python progresso.py:

import sys
import time
from PySide6.QtCore import QObject, QThread, Signal
from PySide6.QtWidgets import (QApplication, QWidget, QVBoxLayout,
                               QPushButton, QProgressBar, QLabel)


class Trabalhador(QObject):
    progresso = Signal(int)
    terminou = Signal()

    def rodar(self):
        for i in range(1, 101):
            time.sleep(0.05)  # finge um trabalho demorado
            self.progresso.emit(i)
        self.terminou.emit()


class Janela(QWidget):
    def __init__(self):
        super().__init__()
        self.setWindowTitle("Tarefa longa")
        self.barra = QProgressBar()
        self.aviso = QLabel("Clique em Começar e tente mexer na janela.")
        self.botao = QPushButton("Começar")
        self.botao.clicked.connect(self.comecar)
        layout = QVBoxLayout(self)
        layout.addWidget(self.aviso)
        layout.addWidget(self.barra)
        layout.addWidget(self.botao)

    def comecar(self):
        self.botao.setEnabled(False)
        self.thread = QThread()
        self.trabalhador = Trabalhador()
        self.trabalhador.moveToThread(self.thread)
        self.thread.started.connect(self.trabalhador.rodar)
        self.trabalhador.progresso.connect(self.barra.setValue)
        self.trabalhador.terminou.connect(self.thread.quit)
        self.thread.finished.connect(self.acabou)
        self.thread.start()

    def acabou(self):
        self.aviso.setText("Pronto!")
        self.botao.setEnabled(True)


app = QApplication(sys.argv)
janela = Janela()
janela.show()
sys.exit(app.exec())

(abre a janela "Tarefa longa"; ao clicar em Começar, a barra vai de 0% a 100% em uns 5 segundos)
(durante esse tempo dá para arrastar e redimensionar a janela normalmente)
(no fim, o texto muda para "Pronto!" e o botão volta a funcionar)

Passo a passo do que acontece no comecar:

  • moveToThread diz que o trabalhador vai viver na thread nova;
  • thread.started → trabalhador.rodar: quando a thread começar, ela roda o trabalho;
  • progresso → barra.setValue: cada número emitido vira um recado para a janela;
  • terminou → thread.quit e finished → acabou: no fim, a thread para e a janela se arruma.
Atenção: Nunca altere um widget de dentro da outra thread (por exemplo, self.barra.setValue(i) direto dentro de rodar). Isso pode travar ou fechar o programa sem nenhuma mensagem. A outra thread só emite sinais.
Dica: Guarde a thread e o trabalhador em self.thread e self.trabalhador. Se forem variáveis locais, o Python os apaga quando o método comecar termina, com a thread ainda rodando, e o programa fecha com QThread: Destroyed while thread is still running.

Cancelando no meio

A outra thread não pode ser "arrancada" à força. O jeito educado é ela olhar, a cada volta, se alguém pediu para parar. Uma variável combinada entre as duas partes resolve, como neste ensaio em Python puro:

class Trabalhador:
    def __init__(self):
        self.cancelado = False

    def rodar(self, avisar):
        for i in range(1, 11):
            if self.cancelado:
                print("Parei no passo", i)
                return
            avisar(i)


t = Trabalhador()


def avisar(i):
    print("passo", i)
    if i == 3:
        t.cancelado = True  # é o que o botão "Cancelar" faria


t.rodar(avisar)

passo 1
passo 2
passo 3
Parei no passo 4

No programa de verdade, o botão Cancelar só faz self.trabalhador.cancelado = True, e o laço de rodar termina na próxima volta.
