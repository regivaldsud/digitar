CRUD: as quatro operações

Quase todo sistema — a agenda do celular, uma loja, um jogo com ranking — faz quatro coisas com os dados. Os programadores chamam isso de CRUD:

  • Create (criar) → INSERT
  • Read (ler) → SELECT
  • Update (atualizar) → UPDATE
  • Delete (apagar) → DELETE

Antes de tudo, porém, é preciso criar a tabela com CREATE TABLE. É isso que você vai aprender nesta aula.

Criando a tabela com regras

No CREATE TABLE você dá o nome de cada coluna, o tipo e, se quiser, regras que o banco vai garantir sozinho:

  • NOT NULL — a coluna é obrigatória;
  • DEFAULT valor — o valor usado quando nada é informado;
  • UNIQUE — não pode haver dois valores iguais nessa coluna (bom para e-mail, CPF, nome de usuário).
import sqlite3

con = sqlite3.connect(":memory:")
con.execute("""
    CREATE TABLE produtos (
        id INTEGER PRIMARY KEY,
        nome TEXT NOT NULL UNIQUE,
        preco REAL NOT NULL,
        estoque INTEGER DEFAULT 0
    )
""")
con.execute("INSERT INTO produtos (nome, preco, estoque) VALUES ('Caderno', 18.5, 30)")
con.execute("INSERT INTO produtos (nome, preco) VALUES ('Mochila', 120.0)")
for p in con.execute("SELECT * FROM produtos"):
    print(p)

try:
    con.execute("INSERT INTO produtos (nome, preco) VALUES ('Caderno', 20.0)")
except sqlite3.IntegrityError as erro:
    print("Recusado:", erro)
con.close()

(1, 'Caderno', 18.5, 30)
(2, 'Mochila', 120.0, 0)
Recusado: UNIQUE constraint failed: produtos.nome

As aspas triplas """ deixam escrever o comando em várias linhas, bem mais fácil de ler. A mochila ficou com estoque 0 por causa do DEFAULT, e o segundo caderno foi barrado pelo UNIQUE.

Dica: Por que deixar o banco cuidar das regras, se o Python também poderia conferir? Porque o banco protege os dados sempre, mesmo que outro programa, ou você daqui a seis meses, esqueça de conferir.

INSERT: uma ou várias linhas

O INSERT INTO tabela (colunas) VALUES (valores) cria uma linha. Para inserir dados que estão em variáveis, use ? no lugar de cada valor e passe uma tupla. Para muitas linhas, executemany recebe uma lista de tuplas:

import sqlite3

con = sqlite3.connect(":memory:")
con.execute("CREATE TABLE produtos (id INTEGER PRIMARY KEY, nome TEXT, preco REAL)")

nome, preco = "Lápis", 1.2
cur = con.execute("INSERT INTO produtos (nome, preco) VALUES (?, ?)", (nome, preco))
print("id do lápis:", cur.lastrowid)

novos = [("Borracha", 2.0), ("Régua", 4.5), ("Cola", 6.9)]
cur = con.executemany("INSERT INTO produtos (nome, preco) VALUES (?, ?)", novos)
print("linhas inseridas:", cur.rowcount)

print(con.execute("SELECT COUNT(*) FROM produtos").fetchone()[0], "produtos no total")
con.close()

id do lápis: 1
linhas inseridas: 3
4 produtos no total

O execute devolve um cursor, um objeto com informações sobre o comando: lastrowid é o id da linha recém-criada e rowcount é quantas linhas o comando afetou.

Atenção: Nunca monte o comando juntando textos, como "... VALUES ('" + nome + "')". Um nome com apóstrofo, como D'Ávila, já quebra o comando — e coisa pior pode acontecer. Use sempre ?; a aula 175 mostra o perigo em detalhes.

SELECT: lendo os dados

O SELECT escolhe quais colunas mostrar; o * significa todas. Pegar só as colunas necessárias deixa o resultado mais limpo e a busca mais rápida:

import sqlite3

con = sqlite3.connect(":memory:")
con.execute("CREATE TABLE produtos (id INTEGER PRIMARY KEY, nome TEXT, preco REAL, estoque INTEGER)")
con.executemany("INSERT INTO produtos (nome, preco, estoque) VALUES (?, ?, ?)", [
    ("Caderno", 18.5, 30), ("Lápis", 1.2, 200), ("Mochila", 120.0, 5),
])

print(con.execute("SELECT * FROM produtos").fetchall())

print("--- tabela de preços ---")
for nome, preco in con.execute("SELECT nome, preco FROM produtos"):
    print(f"{nome:<10} R$ {preco:>7.2f}")

print("--- um produto só ---")
print(con.execute("SELECT nome, estoque FROM produtos WHERE id = 3").fetchone())
con.close()

[(1, 'Caderno', 18.5, 30), (2, 'Lápis', 1.2, 200), (3, 'Mochila', 120.0, 5)]
--- tabela de preços ---
Caderno    R$   18.50
Lápis      R$    1.20
Mochila    R$  120.00
--- um produto só ---
('Mochila', 5)

fetchall() devolve uma lista com todas as linhas; fetchone() devolve só a próxima linha (ou None se não houver nenhuma). Também dá para percorrer o resultado direto com for, desempacotando as colunas.

UPDATE e DELETE: mudando e apagando

O UPDATE muda valores de linhas que já existem; o DELETE apaga linhas. Os dois quase sempre vêm com WHERE, que diz quais linhas mexer:

import sqlite3

con = sqlite3.connect(":memory:")
con.execute("CREATE TABLE produtos (id INTEGER PRIMARY KEY, nome TEXT, preco REAL, estoque INTEGER)")
con.executemany("INSERT INTO produtos (nome, preco, estoque) VALUES (?, ?, ?)", [
    ("Caderno", 18.5, 30), ("Lápis", 1.2, 200), ("Borracha", 2.0, 0),
])

cur = con.execute("UPDATE produtos SET preco = 20.0 WHERE nome = 'Caderno'")
print("atualizados:", cur.rowcount)

cur = con.execute("UPDATE produtos SET estoque = estoque - 10 WHERE id = 2")
print("vendemos 10 lápis:", cur.rowcount, "linha")

cur = con.execute("DELETE FROM produtos WHERE estoque = 0")
print("apagados:", cur.rowcount)

for p in con.execute("SELECT * FROM produtos"):
    print(p)
con.close()

atualizados: 1
vendemos 10 lápis: 1 linha
apagados: 1
(1, 'Caderno', 20.0, 30)
(2, 'Lápis', 1.2, 190)

SET estoque = estoque - 10 usa o valor antigo para calcular o novo, como estoque -= 10 no Python. O rowcount é ótimo para conferir: se der 0, o WHERE não encontrou ninguém.

Atenção: UPDATE ou DELETE sem WHERE mudam ou apagam a tabela inteira! UPDATE produtos SET preco = 0 deixa todos os produtos de graça. Antes de rodar, leia o comando e confira o WHERE — e, na dúvida, rode antes um SELECT com o mesmo WHERE para ver quais linhas serão afetadas.

Salvando de verdade: commit

O banco agrupa as mudanças numa transação: elas ficam pendentes até você confirmar com con.commit() — ou desistir de todas com con.rollback(). Isso protege os dados: se o programa der erro no meio, nada fica pela metade.

Usar a conexão num with faz isso sozinho: se o bloco termina bem, ele faz o commit; se dá erro, desfaz tudo.

import sqlite3

con = sqlite3.connect("loja.db")
with con:
    con.execute("DROP TABLE IF EXISTS clientes")
    con.execute("CREATE TABLE clientes (id INTEGER PRIMARY KEY, nome TEXT NOT NULL)")
    con.execute("INSERT INTO clientes (nome) VALUES ('Joana')")

try:
    with con:
        con.execute("INSERT INTO clientes (nome) VALUES ('Pedro')")
        con.execute("INSERT INTO clientes (nome) VALUES (NULL)")   # quebra o NOT NULL
except sqlite3.IntegrityError as erro:
    print("Deu erro, nada foi salvo:", erro)

print(con.execute("SELECT nome FROM clientes").fetchall())
con.close()

Deu erro, nada foi salvo: NOT NULL constraint failed: clientes.nome
[('Joana',)]

O Pedro não ficou na tabela: como o segundo INSERT falhou, o with desfez o bloco inteiro. DROP TABLE IF EXISTS apaga a tabela (se ela existir), útil para começar do zero quando o exemplo roda várias vezes.

Dica: O with con: faz commit ou rollback, mas não fecha a conexão. Continue chamando con.close() no fim.

Exercícios

1. Crie uma tabela filmes (id, titulo, ano), insira três filmes com executemany, mude o ano de um deles e apague outro. Mostre o resultado.

Ver resposta 
import sqlite3

con = sqlite3.connect(":memory:")
con.execute("CREATE TABLE filmes (id INTEGER PRIMARY KEY, titulo TEXT, ano INTEGER)")
con.executemany("INSERT INTO filmes (titulo, ano) VALUES (?, ?)", [
    ("Central do Brasil", 1998),
    ("O Auto da Compadecida", 2001),
    ("Cidade de Deus", 2000),
])
con.execute("UPDATE filmes SET ano = 2002 WHERE titulo = 'Cidade de Deus'")
con.execute("DELETE FROM filmes WHERE id = 1")
for f in con.execute("SELECT * FROM filmes"):
    print(f)
con.close()

(2, 'O Auto da Compadecida', 2001)
(3, 'Cidade de Deus', 2002)

2. O que acontece com o comando DELETE FROM produtos, sem WHERE? E com DROP TABLE produtos?

Ver resposta

DELETE FROM produtos apaga TODAS as linhas; a tabela continua existindo, mas vazia.
DROP TABLE produtos apaga a tabela inteira: as linhas, as colunas e as regras.
Depois do DROP, um SELECT nela dá erro "no such table".

5. Explique o que o programa abaixo mostra e por quê: dentro de um with con:, ele insere 'Mel' e depois tenta inserir um id repetido.

Ver resposta 
import sqlite3

con = sqlite3.connect(":memory:")
con.execute("CREATE TABLE pets (id INTEGER PRIMARY KEY, nome TEXT)")
con.execute("INSERT INTO pets VALUES (1, 'Rex')")
con.commit()
try:
    with con:
        con.execute("INSERT INTO pets VALUES (2, 'Mel')")
        con.execute("INSERT INTO pets VALUES (1, 'Bob')")
except sqlite3.IntegrityError:
    print("Falhou no meio")
print(con.execute("SELECT nome FROM pets").fetchall())
con.close()

Falhou no meio
[('Rex',)]

Só o Rex aparece. O segundo INSERT falhou (id 1 repetido), então o with fez rollback de todo o bloco, e a Mel também foi desfeita. Ou o bloco inteiro dá certo, ou nada muda.
