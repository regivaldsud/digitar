Aula para fazer no computador: o assunto desta aula precisa do seu computador. Os códigos sem o botão Executar devem ser copiados para um arquivo .py no VS Code e rodados no seu computador, como mostrado na aula 03.

O que é o Git

Sabe quando você salva trabalho.docx, depois trabalho_final.docx, depois trabalho_final_AGORA_VAI.docx? O Git resolve isso. Ele é um controle de versão: guarda fotos (chamadas commits) do seu projeto ao longo do tempo. Dá para ver o que mudou, quando e por quê — e voltar atrás se algo quebrar.

O GitHub é um site que guarda seus projetos Git na internet. Serve de backup, para mostrar seus trabalhos (um portfólio!) e para programar junto com outras pessoas.

Dica: O Git funciona todo no terminal, então esta aula é cheia de comandos para digitar. Ótimo treino de digitação!

Instalando e configurando

Baixe o Git em git-scm.com, instale com as opções padrão e abra um terminal novo. Confira:

git --version

git version 2.47.1.windows.1

Antes do primeiro commit, diga ao Git seu nome e e-mail (use o mesmo e-mail da conta do GitHub). Isso é feito uma vez só por computador:

git config --global user.name "Ana Souza"
git config --global user.email "ana@exemplo.com"
git config --global init.defaultBranch main

O ciclo básico: status, add, commit

Entre na pasta do projeto (a curso-python que você criou na aula 03) e transforme-a num repositório Git:

cd curso-python
git init
git status

Initialized empty Git repository in C:/Users/Ana/Documents/curso-python/.git/
On branch main
 
No commits yet
 
Untracked files:
  (use "git add <file>..." to include in what will be committed)
        ola.py
 
nothing added to commit but untracked files present (use "git add" to track)

Salvar uma versão tem dois passos. Primeiro, git add escolhe os arquivos que entram na foto. Depois, git commit tira a foto com uma mensagem explicando o que mudou:

git add ola.py
git commit -m "Primeiro programa: olá mundo"

[main (root-commit) 3f2a9c1] Primeiro programa: olá mundo
 1 file changed, 2 insertions(+)
 create mode 100644 ola.py

Para adicionar todos os arquivos alterados de uma vez, use git add . (o ponto é "tudo desta pasta").

Dica: Escreva mensagens de commit que expliquem a mudança: "Adiciona placar ao jogo" é ótimo; "mudanças" ou "asdf" não ajudam ninguém (nem você daqui a um mês).

Vendo o histórico

git log --oneline

a81c0d4 Adiciona placar ao jogo
3f2a9c1 Primeiro programa: olá mundo

Cada commit tem um código (o "hash", como a81c0d4). O mais novo aparece em cima.

Arquivos que o Git deve ignorar

Algumas coisas não devem ir para o repositório: o ambiente virtual .venv (aula 60), as pastas __pycache__ que o Python cria sozinho e arquivos com senhas. Crie um arquivo chamado .gitignore na pasta do projeto, com um padrão por linha:

.venv/
__pycache__/
*.pyc
.env

Você também pode criar esse arquivo com um pequeno script Python, rodado na pasta do projeto:

from pathlib import Path

padroes = [".venv/", "__pycache__/", "*.pyc", ".env"]
Path(".gitignore").write_text("\n".join(padroes) + "\n", encoding="utf-8")
print(Path(".gitignore").read_text(encoding="utf-8"))

.venv/
__pycache__/
*.pyc
.env

Atenção: Nunca faça commit de senhas ou chaves de acesso. Mesmo que você apague depois, elas continuam no histórico do Git. Guarde-as num arquivo .env listado no .gitignore.

Enviando para o GitHub

  • Crie uma conta grátis em github.com.
  • Clique em New repository, dê um nome (por exemplo curso-python) e clique em Create repository, sem marcar a opção de criar README.
  • O GitHub mostra o endereço do repositório. No terminal, ligue seu projeto a ele e envie:
git remote add origin https://github.com/ana-souza/curso-python.git
git push -u origin main

Na primeira vez, o Windows abre uma janela para você entrar na sua conta do GitHub. Depois, para enviar novos commits, basta git push.

Dica: Para publicar uma página HTML de graça (como a landing page da aula 243), envie o projeto para o GitHub e ative Settings › Pages no repositório, escolhendo a branch main.

Baixando: clone e pull

Para baixar um projeto do GitHub para outro computador (o da escola, por exemplo), use clone. Para trazer as novidades de um projeto que você já baixou, use pull:

git clone https://github.com/ana-souza/curso-python.git
cd curso-python
git pull

Uma rotina saudável: git pull ao começar, git add e git commit a cada passo que funcionou, git push ao terminar.

Pratique no DIGITAR: digite este trecho no modo Programar do app. 
git commit -m "Adiciona placar ao jogo"

Exercícios

Ver resposta

2. Você mudou o arquivo jogo.py. Quais comandos mostram o que mudou, salvam a nova versão e enviam para o GitHub?

Ver resposta 
git status
git add jogo.py
git commit -m "Corrige a contagem de pontos"
git push

3. Escreva um .gitignore para um projeto Python que tem um ambiente virtual na pasta .venv, arquivos __pycache__ e um arquivo senhas.txt.

Ver resposta 
.venv/
__pycache__/
senhas.txt

4. Qual é a diferença entre git clone e git pull?

Ver resposta

git clone baixa um repositório inteiro pela primeira vez, criando a pasta do projeto.
git pull traz para um projeto que você já tem as mudanças novas que estão no GitHub.
