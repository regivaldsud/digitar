Aula 177 · Senhas fora do código com .env

Nesta aula você vai aprender

  • Entender por que senha escrita no código é um problema sério

  • Entender o formato do arquivo .env e como ele é lido
  • Usar python-dotenv, o .gitignore e o arquivo .env.example

Aula para fazer no computador: o assunto desta aula precisa do seu computador. Os códigos sem o botão Executar devem ser copiados para um arquivo .py no VS Code e rodados no seu computador, como mostrado na aula 03.

O problema

Na aula 176, a senha do MySQL ficou escrita no código: password="troque_esta_senha". Se esse projeto for para o GitHub, qualquer pessoa pode ler. E não é exagero: existem robôs que vasculham repositórios públicos o dia inteiro procurando senhas e chaves de serviços pagos, e usam o que acham em minutos.

Além disso, a senha do seu computador não é a mesma do servidor de produção. Se ela estiver no código, você precisa mudar o código toda vez que muda de lugar.

A regra é: segredos ficam fora do código. O código só diz o nome do segredo; o valor fica guardado em outro lugar.

Variáveis de ambiente

Todo sistema operacional guarda variáveis de ambiente: pares NOME=valor que qualquer programa pode ler. No Python, elas ficam em os.environ, que funciona como um dicionário de textos:

import os

os.environ["MODO"] = "teste"
print(os.environ["MODO"])
print(os.environ.get("MODO"))
print(os.environ.get("SENHA_DO_BANCO"))
print(os.environ.get("SENHA_DO_BANCO", "não definida"))
print("MODO" in os.environ)

teste
teste
None
não definida
True

  • os.environ["NOME"] dá KeyError se a variável não existir;
  • os.environ.get("NOME") devolve None, e os.environ.get("NOME", padrão) devolve o padrão.

Neste exemplo nós mesmos criamos a variável MODO dentro do programa. Na vida real, quem cria é o terminal, o servidor ou o arquivo .env.

Atenção: Variáveis de ambiente são sempre texto. os.environ.get("PORTA", "3306") devolve "3306", não 3306. Converta com int(...) quando precisar de número, e cuidado com "False": qualquer texto não vazio é verdadeiro num if.

Padrão para configurações: obrigatórias e opcionais

Um bom programa decide o que fazer quando falta uma configuração. As opcionais ganham um valor padrão. As obrigatórias, como a senha do banco, devem parar o programa logo no começo com uma mensagem clara, em vez de dar um erro confuso lá no meio:

import os

os.environ["DB_SENHA"] = "s3nh4_de_treino"
os.environ["DB_PORTA"] = "3307"


def obrigatoria(nome):
    valor = os.environ.get(nome)
    if not valor:
        raise RuntimeError(f"Falta a variável {nome}. Confira o seu arquivo .env")
    return valor


host = os.environ.get("DB_HOST", "localhost")
porta = int(os.environ.get("DB_PORTA", "3306"))
debug = os.environ.get("DEBUG", "nao").lower() in ("1", "sim", "true")
senha = obrigatoria("DB_SENHA")

print("host:", host, "| porta:", porta, "| debug:", debug)
print("senha carregada com", len(senha), "caracteres")
try:
    chave = obrigatoria("API_CHAVE")
except RuntimeError as erro:
    print(erro)

host: localhost | porta: 3307 | debug: False
senha carregada com 15 caracteres
Falta a variável API_CHAVE. Confira o seu arquivo .env

Dica: Nunca mostre o segredo na tela nem no log. Para conferir se ele foi carregado, mostre só o tamanho, como acima, ou os primeiros caracteres seguidos de ***.

O arquivo .env

Criar as variáveis no terminal toda vez é chato e fácil de esquecer. Por isso se usa um arquivo chamado .env (com ponto no começo e sem nada antes) na pasta do projeto:

# configurações do banco (este arquivo NÃO vai para o GitHub)
DB_HOST=localhost
DB_USUARIO=root
DB_SENHA=troque_esta_senha
DEBUG=sim

Cada linha é NOME=valor, sem espaços em volta do = e, em geral, sem aspas. Linhas que começam com # são comentários.

Para entender o que uma biblioteca faz com esse arquivo, aqui está um leitor simplificado feito só com a biblioteca padrão. Para rodar no navegador, o "arquivo" é um texto dentro de um io.StringIO:

import io
import os

arquivo_env = io.StringIO("""# configurações do banco
DB_HOST=localhost
DB_SENHA=troque_esta_senha
DEBUG=sim

LINHA QUEBRADA SEM IGUAL
""")


def carregar_env(arquivo):
    for linha in arquivo:
        linha = linha.strip()
        if not linha or linha.startswith("#") or "=" not in linha:
            continue
        nome, valor = linha.split("=", 1)
        os.environ.setdefault(nome.strip(), valor.strip())


os.environ["DEBUG"] = "nao"
carregar_env(arquivo_env)
print(os.environ["DB_HOST"])
print(os.environ["DEBUG"])
print(len(os.environ["DB_SENHA"]), "caracteres na senha")

localhost
nao
17 caracteres na senha

O setdefault só cria a variável se ela ainda não existir. Por isso o DEBUG continuou nao: o valor que já estava no ambiente vale mais que o do arquivo. A biblioteca python-dotenv faz o mesmo por padrão.

python-dotenv na prática

No computador, use a biblioteca pronta, que entende aspas, comentários no fim da linha e outros detalhes. Dentro do ambiente virtual (aula 60):

py -m pip install python-dotenv
python3 -m pip install python-dotenv

Crie o .env da seção anterior na pasta do projeto e, ao lado dele, o config.py. Rode com python config.py:

import os
from dotenv import load_dotenv

load_dotenv()  # procura o arquivo .env e carrega as variáveis

host = os.environ.get("DB_HOST", "localhost")
senha = os.environ.get("DB_SENHA")
if not senha:
    raise SystemExit("Falta DB_SENHA no arquivo .env")

print("Conectando em", host)
print("Senha carregada com", len(senha), "caracteres")

Conectando em localhost
Senha carregada com 17 caracteres

Agora a conexão da aula 176 fica sem nenhum segredo no código:

import os
import pymysql
from dotenv import load_dotenv

load_dotenv()
con = pymysql.connect(
    host=os.environ.get("DB_HOST", "localhost"),
    user=os.environ["DB_USUARIO"],
    password=os.environ["DB_SENHA"],
    database=os.environ.get("DB_NOME", "escola"),
)
print("Conectado!")
con.close()

Conectado!

Atenção: O load_dotenv() procura o .env a partir da pasta do arquivo .py. Se ele não achar o arquivo, não dá erro: as variáveis simplesmente não existem e o os.environ["DB_SENHA"] dá KeyError. Confira o nome do arquivo (é .env, não env.txt nem .env.txt; no Windows, ative a opção de mostrar extensões).

Não envie o .env: .gitignore e .env.example

Para o Git ignorar o arquivo, ponha o nome dele no .gitignore (aula 244) antes do primeiro commit:

# .gitignore
.env
.venv/
__pycache__/

Mas quem baixar o seu projeto precisa saber quais variáveis criar. Para isso existe o .env.example: uma cópia do .env com os nomes, mas sem os valores verdadeiros. Esse arquivo pode, e deve, ir para o GitHub:

# .env.example — copie para .env e preencha
DB_HOST=localhost
DB_USUARIO=
DB_SENHA=
DEBUG=nao

Quem baixa o projeto faz uma cópia com copy .env.example .env (Windows) ou cp .env.example .env (Linux e macOS) e preenche os valores.

Esse mesmo truque permite configurações diferentes por ambiente: no seu computador, o .env aponta para o banco de treino com DEBUG=sim; no servidor, as variáveis apontam para o banco de verdade com DEBUG=nao. O código é o mesmo nos dois lugares.

E se a senha vazou?

Se uma senha ou chave já foi enviada para o GitHub, apagar o arquivo depois não resolve: ela continua no histórico do Git e pode já ter sido copiada. O que fazer, nesta ordem:

  • troque a senha ou gere uma chave nova imediatamente, e desative a antiga;
  • coloque o .env no .gitignore e tire o arquivo do Git com git rm --cached .env;
  • confira se a chave antiga foi usada (muitos serviços mostram um histórico de uso).
Dica: O GitHub tem uma proteção chamada secret scanning, que avisa quando reconhece uma chave conhecida num commit. Ela ajuda, mas não substitui o cuidado de nunca pôr o segredo no código.
Pratique no DIGITAR: digite este trecho no modo Programar do app. 
senha = os.environ.get("DB_SENHA", "")

2. Leia a variável TAMANHO_PAGINA como número inteiro, com padrão 20 quando ela não existir. Teste primeiro sem a variável e depois com os.environ["TAMANHO_PAGINA"] = "50".

Ver resposta 
import os


def tamanho_pagina():
    return int(os.environ.get("TAMANHO_PAGINA", "20"))


os.environ.pop("TAMANHO_PAGINA", None)
print(tamanho_pagina())
os.environ["TAMANHO_PAGINA"] = "50"

O int(...) é necessário porque variáveis de ambiente são sempre texto; sem ele, "50" + 1 daria erro.

3. Melhore o leitor de .env da aula para também tirar aspas em volta do valor: a linha NOME="Ana Lima" deve virar Ana Lima.

Ver resposta 
import io
import os


def carregar_env(arquivo):
    for linha in arquivo:
        linha = linha.strip()
        if not linha or linha.startswith("#") or "=" not in linha:
            continue
        nome, valor = linha.split("=", 1)
        valor = valor.strip()
        if len(valor) >= 2 and valor[0] == valor[-1] and valor[0] in "\"'":
            valor = valor[1:-1]
        os.environ.setdefault(nome.strip(), valor)


carregar_env(io.StringIO('NOME="Ana Lima"\nCIDADE=\'São Luís\'\nIDADE=13\n'))

print(os.environ["IDADE"])

13
