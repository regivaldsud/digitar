O que é uma API

Uma API é um site feito para programas, não para pessoas. Em vez de devolver uma página HTML bonita, ela devolve dados, quase sempre em JSON (aula 62). O aplicativo do celular, um site feito em JavaScript ou outro programa Python (aula 111, com requests) conversam com ela.

No estilo REST, cada endereço representa um recurso (as tarefas, uma tarefa) e o método do HTTP diz o que fazer com ele:

  • GET /api/tarefas/ lista as tarefas; GET /api/tarefas/5/ mostra a tarefa 5;
  • POST /api/tarefas/ cria uma tarefa nova com os dados enviados;
  • PUT /api/tarefas/5/ altera a tarefa 5;
  • DELETE /api/tarefas/5/ apaga a tarefa 5.

Repare: o endereço é sempre um substantivo (tarefas), nunca um verbo como /apagar-tarefa/. Quem diz a ação é o método.

Os códigos de status

Toda resposta HTTP vem com um número que diz como foi. Numa página, a pessoa lê a mensagem; numa API, o programa do outro lado olha o número para decidir o que fazer. O módulo http da biblioteca padrão tem todos eles com nome:

from http import HTTPStatus

for codigo in [200, 201, 204, 400, 404, 405, 500]:
    status = HTTPStatus(codigo)
    print(codigo, status.phrase)

print(HTTPStatus.NOT_FOUND.value)

200 OK
201 Created
204 No Content
400 Bad Request
404 Not Found
405 Method Not Allowed
500 Internal Server Error
404

  • 2xx deu certo: 200 (ok), 201 (criado), 204 (feito, sem nada para mostrar — comum ao apagar);
  • 4xx o erro foi de quem pediu: 400 (dados errados), 404 (não existe), 405 (método não permitido);
  • 5xx o erro foi do servidor: 500 é uma exceção no seu código.

JSON: a língua da conversa

O pedido e a resposta viajam como texto. Quem envia transforma o dicionário em texto JSON (json.dumps); quem recebe faz o contrário (json.loads). Se o texto não for um JSON válido, o loads levanta JSONDecodeError — e a API deve responder 400, não quebrar:

import json

tarefa = {"id": 1, "titulo": "Estudar Python", "feita": False}
texto = json.dumps(tarefa, ensure_ascii=False)
print("Viaja assim:", texto)
print("Tipo:", type(texto).__name__)

de_volta = json.loads('{"titulo": "Ler um livro", "feita": true}')
print("Chega assim:", de_volta, "->", type(de_volta).__name__)

try:
    json.loads("{titulo: sem aspas}")
except json.JSONDecodeError as erro:
    print("JSON inválido:", erro.msg)

Viaja assim: {"id": 1, "titulo": "Estudar Python", "feita": false}
Tipo: str
Chega assim: {'titulo': 'Ler um livro', 'feita': True} -> dict
JSON inválido: Expecting property name enclosed in double quotes

Note que o false do JSON vira False no Python, e true vira True.

Uma API de mentira, em Python puro

Antes do Django, veja a ideia inteira funcionando aqui no navegador. Uma API é, no fundo, um "roteador": olha o método e o caminho e chama a função certa, que devolve um status e um corpo:

import json
from http import HTTPStatus

tarefas = {1: {"id": 1, "titulo": "Estudar Python", "feita": False}}


def listar():
    return HTTPStatus.OK, list(tarefas.values())


def criar(corpo):
    dados = json.loads(corpo)
    if not dados.get("titulo"):
        return HTTPStatus.BAD_REQUEST, {"erro": "o campo 'titulo' é obrigatório"}
    novo_id = max(tarefas, default=0) + 1
    tarefas[novo_id] = {"id": novo_id, "titulo": dados["titulo"], "feita": False}
    return HTTPStatus.CREATED, tarefas[novo_id]


def detalhe(tarefa_id):
    if tarefa_id not in tarefas:
        return HTTPStatus.NOT_FOUND, {"erro": "tarefa não encontrada"}
    return HTTPStatus.OK, tarefas[tarefa_id]


def api(metodo, caminho, corpo=""):
    partes = caminho.strip("/").split("/")          # "/api/tarefas/1/" -> ["api", "tarefas", "1"]
    if partes[:2] != ["api", "tarefas"]:
        return HTTPStatus.NOT_FOUND, {"erro": "endereço desconhecido"}
    if len(partes) == 2:
        if metodo == "GET":
            return listar()
        if metodo == "POST":
            return criar(corpo)
    elif len(partes) == 3 and metodo == "GET":
        return detalhe(int(partes[2]))
    return HTTPStatus.METHOD_NOT_ALLOWED, {"erro": f"{metodo} não é permitido aqui"}


pedidos = [
    ("GET", "/api/tarefas/", ""),
    ("POST", "/api/tarefas/", '{"titulo": "Lavar a louça"}'),
    ("POST", "/api/tarefas/", '{"titulo": ""}'),
    ("GET", "/api/tarefas/2/", ""),
    ("GET", "/api/tarefas/9/", ""),
    ("DELETE", "/api/tarefas/", ""),
]
for metodo, caminho, corpo in pedidos:
    status, resposta = api(metodo, caminho, corpo)
    print(f"{metodo} {caminho} -> {status.value} {json.dumps(resposta, ensure_ascii=False)}")

GET /api/tarefas/ -> 200 [{"id": 1, "titulo": "Estudar Python", "feita": false}]
POST /api/tarefas/ -> 201 {"id": 2, "titulo": "Lavar a louça", "feita": false}
POST /api/tarefas/ -> 400 {"erro": "o campo 'titulo' é obrigatório"}
GET /api/tarefas/2/ -> 200 {"id": 2, "titulo": "Lavar a louça", "feita": false}
GET /api/tarefas/9/ -> 404 {"erro": "tarefa não encontrada"}
DELETE /api/tarefas/ -> 405 {"erro": "DELETE não é permitido aqui"}

O Django vai fazer o papel desse roteador (com o urls.py), do banco (com os models) e da conversão para texto (com o JsonResponse). O resto é a mesma lógica.

Passo 1: o app e o model

Num projeto Django (aula 200), crie um app só para as tarefas:

from django.db import models


class Tarefa(models.Model):
    titulo = models.CharField(max_length=100)
    feita = models.BooleanField(default=False)
    criada_em = models.DateTimeField(auto_now_add=True)

    def __str__(self):

Passo 2: as views da API

Crie o arquivo tarefas/api.py. Ele tem duas views: uma para a coleção (/api/tarefas/) e outra para uma tarefa só (/api/tarefas/5/):

# tarefas/api.py
import json

from django.http import JsonResponse
from django.views.decorators.csrf import csrf_exempt
from django.views.decorators.http import require_http_methods

from .models import Tarefa


def para_dict(tarefa):
    return {
        "id": tarefa.pk,
        "titulo": tarefa.titulo,
        "feita": tarefa.feita,
        "criada_em": tarefa.criada_em.isoformat(),
    }


def ler_json(request):
    """Devolve (dados, None) ou (None, resposta_de_erro)."""
    try:
        dados = json.loads(request.body)
    except json.JSONDecodeError:
        return None, JsonResponse({"erro": "JSON inválido"}, status=400)
    if not isinstance(dados, dict):
        return None, JsonResponse({"erro": "envie um objeto JSON"}, status=400)
    return dados, None


def validar_titulo(dados):
    titulo = str(dados.get("titulo", "")).strip()
    if not titulo:
        return None, JsonResponse({"erro": "o campo 'titulo' é obrigatório"}, status=400)
    if len(titulo) > 100:
        return None, JsonResponse({"erro": "título com mais de 100 letras"}, status=400)
    return titulo, None


@csrf_exempt  # só para estudo: veja o aviso logo abaixo
@require_http_methods(["GET", "POST"])
def lista_tarefas(request):
    if request.method == "GET":
        dados = [para_dict(t) for t in Tarefa.objects.all()]
        return JsonResponse(dados, safe=False)
    dados, erro = ler_json(request)
    if erro:
        return erro
    titulo, erro = validar_titulo(dados)
    if erro:
        return erro
    nova = Tarefa.objects.create(titulo=titulo, feita=bool(dados.get("feita", False)))
    return JsonResponse(para_dict(nova), status=201)


@csrf_exempt
@require_http_methods(["GET", "PUT", "DELETE"])
def detalhe_tarefa(request, pk):
    tarefa = Tarefa.objects.filter(pk=pk).first()
    if tarefa is None:
        return JsonResponse({"erro": "tarefa não encontrada"}, status=404)
    if request.method == "GET":
        return JsonResponse(para_dict(tarefa))
    if request.method == "DELETE":
        tarefa.delete()
        return JsonResponse({}, status=204)
    dados, erro = ler_json(request)
    if erro:
        return erro
    titulo, erro = validar_titulo(dados)
    if erro:
        return erro
    tarefa.titulo = titulo
    tarefa.feita = bool(dados.get("feita", tarefa.feita))
    tarefa.save()
    return JsonResponse(para_dict(tarefa))

(sem saída: as views rodam quando um programa chama a API)

  • JsonResponse transforma o dicionário em JSON e já põe o cabeçalho Content-Type: application/json. Para devolver uma lista, é preciso safe=False.
  • request.body traz o corpo do pedido como bytes; o json.loads aceita bytes direto.
  • @require_http_methods responde 405 sozinho a qualquer método fora da lista.
  • Para "não encontrado", usamos um 404 em JSON. O get_object_or_404 também funcionaria, mas devolveria uma página HTML, que o programa do outro lado não sabe ler.
Atenção: O @csrf_exempt desliga a proteção CSRF (aula 205), porque um programa não tem como mandar o csrf_token de um formulário. Isso só é aceitável numa API com autenticação (por exemplo, um token secreto em cada pedido). Uma API sem login, aberta na internet, deixaria qualquer um criar e apagar as suas tarefas. Aqui é só para estudo, no seu computador.

Ligue os endereços em tarefas/urls.py:

# tarefas/urls.py
from django.urls import path
from . import api

urlpatterns = [
    path("api/tarefas/", api.lista_tarefas, name="api_tarefas"),
    path("api/tarefas/<int:pk>/", api.detalhe_tarefa, name="api_tarefa"),
]

(dois endereços: a coleção e cada tarefa)

E inclua no config/urls.py, dentro de urlpatterns: path("", include("tarefas.urls")),.

Dica: Por padrão, o JsonResponse troca acentos por códigos como á ("Lavar a louça"). É JSON válido e qualquer programa entende, mas, para ler melhor, use JsonResponse(dados, json_dumps_params={"ensure_ascii": False}).

Passo 4: testes automáticos da API

O Client do Django (aula 211) faz pedidos de mentira, sem servidor, e é a melhor forma de garantir que a API continua respondendo certo. Coloque em tarefas/tests.py:

# tarefas/tests.py
from django.test import TestCase


class ApiTarefasTeste(TestCase):
    def criar(self, corpo):
        return self.client.post("/api/tarefas/", corpo, content_type="application/json")

    def test_criar_listar_alterar_apagar(self):
        resposta = self.criar({"titulo": "Estudar Python"})
        self.assertEqual(resposta.status_code, 201)
        tarefa_id = resposta.json()["id"]
        self.assertEqual(len(self.client.get("/api/tarefas/").json()), 1)
        resposta = self.client.put(f"/api/tarefas/{tarefa_id}/",
                                   {"titulo": "Estudar Django", "feita": True},
                                   content_type="application/json")
        self.assertEqual(resposta.json()["feita"], True)
        self.assertEqual(self.client.delete(f"/api/tarefas/{tarefa_id}/").status_code, 204)
        self.assertEqual(self.client.get(f"/api/tarefas/{tarefa_id}/").status_code, 404)

    def test_erros(self):
        self.assertEqual(self.criar({"titulo": ""}).status_code, 400)
        self.assertEqual(self.criar("isto não é json").status_code, 400)
        self.assertEqual(self.client.delete("/api/tarefas/").status_code, 405)
        self.assertEqual(self.client.get("/api/tarefas/999/").json(), {"erro": "tarefa não encontrada"})

O Django REST Framework

Repare quanto código foi preciso só para uma tabela: converter para dicionário, ler o JSON, validar, responder cada erro. Em APIs maiores, quase todo mundo usa o Django REST Framework (DRF), que faz essas partes repetitivas e ainda traz login por token, paginação e uma página para testar a API no navegador:

pip install djangorestframework

Com "rest_framework" em INSTALLED_APPS, a mesma API de tarefas fica assim:

# tarefas/serializers.py
from rest_framework import serializers
from .models import Tarefa


class TarefaSerializer(serializers.ModelSerializer):
    class Meta:
        model = Tarefa
        fields = ["id", "titulo", "feita", "criada_em"]
        read_only_fields = ["criada_em"]
# tarefas/drf.py
from rest_framework import routers, viewsets
from .models import Tarefa
from .serializers import TarefaSerializer


class TarefaViewSet(viewsets.ModelViewSet):
    queryset = Tarefa.objects.all()
    serializer_class = TarefaSerializer


roteador = routers.DefaultRouter()
roteador.register("v2/tarefas", TarefaViewSet)

# config/urls.py: path("api/", include(roteador.urls)),

GET /api/v2/tarefas/  ->  [{"id": 1, "titulo": "Estudar Python", "feita": false, "criada_em": "..."}]

O serializer faz a conversão e a validação (título obrigatório, até 100 letras, já tirados do model); o viewset cria sozinho listar, mostrar, criar, alterar e apagar, com os códigos de status certos; o router gera as URLs. Entender a versão "na mão" desta aula é o que faz o DRF deixar de parecer mágica.

3. Escreva em Python puro a função validar(dados), que devolve uma lista de erros: o título é obrigatório e tem até 100 letras, e feita, se vier, precisa ser True ou False. Teste com três dicionários.

def validar(dados):
    erros = []
    titulo = str(dados.get("titulo", "")).strip()
    if not titulo:
        erros.append("titulo: obrigatório")
    elif len(titulo) > 100:
        erros.append("titulo: até 100 letras")
    if "feita" in dados and not isinstance(dados["feita"], bool):
        erros.append("feita: use true ou false")
    return erros

def lista_tarefas(request):

from http import HTTPStatus

tarefas = {1: {"id": 1, "titulo": "Estudar Python"}, 2: {"id": 2, "titulo": "Ler"}}


def apagar(tarefa_id):
    if tarefas.pop(tarefa_id, None) is None:
        return HTTPStatus.NOT_FOUND, {"erro": "tarefa não encontrada"}
    return HTTPStatus.NO_CONTENT, {}


def api(metodo, caminho):
    partes = caminho.strip("/").split("/")
    if partes[:2] == ["api", "tarefas"] and len(partes) == 3 and metodo == "DELETE":

    return HTTPStatus.METHOD_NOT_ALLOWED, {"erro": "não permitido"}


for caminho in ["/api/tarefas/1/", "/api/tarefas/1/", "/api/tarefas/2/"]:
