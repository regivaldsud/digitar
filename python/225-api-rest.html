O que é uma API

Uma API é um site feito para programas, não para pessoas: em vez de HTML, ela devolve dados, quase sempre em JSON (aula 62). Um aplicativo de celular, por exemplo, busca os contatos numa API. No estilo REST, cada endereço representa um recurso e o método diz a ação:

  • GET /api/contatos/ lista; GET /api/contatos/5/ mostra um;
  • POST /api/contatos/ cria; PUT altera; DELETE apaga.

Uma API com JsonResponse

# contatos/api.py
import json
from django.http import JsonResponse
from django.shortcuts import get_object_or_404
from django.views.decorators.csrf import csrf_exempt
from django.views.decorators.http import require_http_methods
from .models import Contato


def para_dict(contato):
    return {"id": contato.pk, "nome": contato.nome, "telefone": contato.telefone}


@csrf_exempt  # só para estudo: numa API real, use autenticação por token
@require_http_methods(["GET", "POST"])
def contatos(request):
    if request.method == "GET":
        dados = [para_dict(c) for c in Contato.objects.all()]
        return JsonResponse(dados, safe=False)
    corpo = json.loads(request.body)
    novo = Contato.objects.create(nome=corpo["nome"], telefone=corpo["telefone"])
    return JsonResponse(para_dict(novo), status=201)


def contato(request, pk):
    return JsonResponse(para_dict(get_object_or_404(Contato, pk=pk)))

GET /api/contatos/
[{"id": 1, "nome": "Ana", "telefone": "81 99999-0000"}]

safe=False é necessário para devolver uma lista; por padrão o JsonResponse só aceita dicionários. O status 201 significa "criado".

Atenção: O @csrf_exempt desliga a proteção CSRF (aula 205). Use só para aprender; uma API de verdade precisa de autenticação.

Testando a API

Com o servidor rodando, teste num outro terminal com o curl (já vem no Windows 10 e 11):

curl http://127.0.0.1:8000/api/contatos/
curl -X POST http://127.0.0.1:8000/api/contatos/ -H "Content-Type: application/json" -d "{\"nome\": \"Bia\", \"telefone\": \"11 95555-0000\"}"

O formato dos dados é JSON comum, e dá para conferir aqui como o Python transforma o dicionário em texto:

import json

contato = {"id": 2, "nome": "Bia", "telefone": "11 95555-0000"}
print(json.dumps(contato, ensure_ascii=False))

{"id": 2, "nome": "Bia", "telefone": "11 95555-0000"}

Dica: Para APIs maiores, use o Django REST Framework (pip install djangorestframework): ele traz serializers, autenticação, paginação e uma página para testar a API no navegador.
Pratique no DIGITAR: digite este trecho no modo Programar do app. 
return JsonResponse(dados, safe=False)

Exercícios

1. Crie a função para_dict que também inclua o campo favorito, e teste a ideia com uma classe simples no lugar do model.

Ver resposta 
class ContatoFalso:
    def __init__(self, pk, nome, telefone, favorito):
        self.pk = pk
        self.nome = nome
        self.telefone = telefone
        self.favorito = favorito


def para_dict(contato):
    return {"id": contato.pk, "nome": contato.nome,
            "telefone": contato.telefone, "favorito": contato.favorito}


print(para_dict(ContatoFalso(3, "Caio", "21 94444-0000", True)))

{'id': 3, 'nome': 'Caio', 'telefone': '21 94444-0000', 'favorito': True}

2. Qual método HTTP e qual endereço você usaria para apagar o contato de id 7 nessa API REST?

Ver resposta 
curl -X DELETE http://127.0.0.1:8000/api/contatos/7/

DELETE no endereço do recurso. Para funcionar, a view contato precisaria tratar request.method == "DELETE".
