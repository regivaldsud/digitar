Para que servem os padrões estruturais

Os padrões criacionais (aula 151) cuidam de criar objetos. Os estruturais cuidam de encaixá-los: como fazer peças que não foram pensadas juntas funcionarem juntas, como montar estruturas grandes a partir de peças pequenas e como colocar uma "camada" entre quem usa e quem faz o trabalho.

Quase todos usam a mesma ferramenta: um objeto que guarda outro dentro de si (composição, aula 75) e repassa os pedidos para ele, às vezes mudando alguma coisa no caminho.

Adapter: o adaptador de tomada

Problema: seu programa espera objetos com um certo método, mas você recebe uma classe pronta (de uma biblioteca, de um colega) com outro formato. Como um carregador de três pinos numa tomada de dois, você precisa de um adaptador.

class TocadorMP3:
    def tocar(self, musica):
        print(f"MP3 tocando {musica}")


class ServicoDeStreaming:            # biblioteca pronta: não podemos mudar
    def reproduzir_faixa(self, faixa_id, qualidade):
        print(f"Streaming: faixa {faixa_id} em {qualidade}")


class AdaptadorStreaming:
    def __init__(self, servico):
        self.servico = servico

    def tocar(self, musica):          # o formato que o programa espera
        self.servico.reproduzir_faixa(musica.lower().replace(" ", "-"), "alta")


def tocar_playlist(tocador, musicas):
    for m in musicas:
        tocador.tocar(m)


tocar_playlist(TocadorMP3(), ["Asa Branca"])
tocar_playlist(AdaptadorStreaming(ServicoDeStreaming()), ["Asa Branca", "Garota de Ipanema"])

MP3 tocando Asa Branca
Streaming: faixa asa-branca em alta
Streaming: faixa garota-de-ipanema em alta

tocar_playlist não precisou mudar; o adaptador traduz tocar(musica) para reproduzir_faixa(id, qualidade).

Composite: um e muitos do mesmo jeito

Problema: algumas coisas formam árvores — pastas com arquivos e outras pastas, um cardápio com seções e pratos, uma equipe com subequipes. Você quer perguntar "qual o tamanho?" sem se importar se é um item ou um grupo.

No Composite, o item simples e o grupo têm o mesmo método; o grupo só repassa a pergunta para os filhos e soma:

class Arquivo:
    def __init__(self, nome, tamanho):
        self.nome = nome
        self.tamanho_kb = tamanho

    def tamanho(self):
        return self.tamanho_kb

    def mostrar(self, nivel=0):
        print("  " * nivel + f"{self.nome} ({self.tamanho()} KB)")


class Pasta:
    def __init__(self, nome, *itens):
        self.nome = nome
        self.itens = list(itens)

    def tamanho(self):
        return sum(item.tamanho() for item in self.itens)

    def mostrar(self, nivel=0):
        print("  " * nivel + f"{self.nome}/ ({self.tamanho()} KB)")
        for item in self.itens:
            item.mostrar(nivel + 1)


escola = Pasta("escola",
               Arquivo("horario.pdf", 120),
               Pasta("matematica", Arquivo("lista1.pdf", 300), Arquivo("lista2.pdf", 250)),
               Pasta("artes", Pasta("fotos", Arquivo("quadro.jpg", 900))))
escola.mostrar()

escola/ (1570 KB)
  horario.pdf (120 KB)
  matematica/ (550 KB)
    lista1.pdf (300 KB)
    lista2.pdf (250 KB)
  artes/ (900 KB)
    fotos/ (900 KB)
      quadro.jpg (900 KB)

Repare na recursão (aula 59): Pasta.tamanho chama tamanho dos filhos, que podem ser outras pastas.

Decorator (o padrão): embrulhar para acrescentar

Problema: você quer acrescentar extras a um objeto — leite e chantili no café, borda na pizza, registro de log numa mensagem — em qualquer combinação. Criar uma classe para cada combinação (CafeComLeite, CafeComLeiteEChantili…) explodiria.

O padrão Decorator embrulha o objeto num outro que tem os mesmos métodos, faz o seu extra e repassa o resto. Dá para embrulhar várias vezes:

class Cafe:
    def preco(self):
        return 5.00

    def descricao(self):
        return "café"


class ComLeite:
    def __init__(self, bebida):
        self.bebida = bebida

    def preco(self):
        return self.bebida.preco() + 1.50

    def descricao(self):
        return self.bebida.descricao() + " + leite"


class ComChantili:
    def __init__(self, bebida):
        self.bebida = bebida

    def preco(self):
        return self.bebida.preco() + 2.00

    def descricao(self):
        return self.bebida.descricao() + " + chantili"


pedidos = [Cafe(), ComLeite(Cafe()), ComChantili(ComLeite(Cafe())), ComChantili(ComChantili(Cafe()))]
for p in pedidos:
    print(f"{p.descricao():<32} R$ {p.preco():.2f}")

café                             R$ 5.00
café + leite                     R$ 6.50
café + leite + chantili          R$ 8.50
café + chantili + chantili       R$ 9.00

Dica: O @decorador da aula 56 é a mesma ideia aplicada a funções: ele embrulha uma função numa outra que faz algo a mais e chama a original. O padrão Decorator faz isso com objetos, enquanto o programa roda.
import functools


def com_aviso(funcao):
    @functools.wraps(funcao)
    def embrulho(*args):
        print(f"[chamando {funcao.__name__}{args}]")
        return funcao(*args)
    return embrulho


@com_aviso
def somar(a, b):
    return a + b


print(somar(2, 3))

[chamando somar(2, 3)]
5

Facade: uma porta da frente simples

Problema: para fazer uma tarefa, você precisa chamar várias partes de um sistema na ordem certa. Ligar o "modo cinema" em casa exige apagar luzes, ligar a TV, ligar o som, escolher a entrada… Quem usa não quer saber de nada disso.

A fachada é uma classe com poucos métodos simples que coordena tudo por trás:

class Luzes:
    def apagar(self):
        print("Luzes apagadas")


class TV:
    def ligar(self):
        print("TV ligada")

    def entrada(self, nome):
        print(f"TV na entrada {nome}")


class Som:
    def ligar(self):
        print("Som ligado")

    def volume(self, valor):
        print(f"Volume em {valor}")


class CasaInteligente:
    def __init__(self):
        self.luzes, self.tv, self.som = Luzes(), TV(), Som()

    def modo_cinema(self):
        self.luzes.apagar()
        self.tv.ligar()
        self.tv.entrada("HDMI 1")
        self.som.ligar()
        self.som.volume(30)


CasaInteligente().modo_cinema()

Luzes apagadas
TV ligada
TV na entrada HDMI 1
Som ligado
Volume em 30

As partes continuam existindo para quem precisar delas; a fachada só oferece um caminho curto para o uso mais comum.

Proxy: um intermediário que controla o acesso

Problema: o objeto de verdade é caro de criar (uma imagem enorme), lento (busca na internet) ou precisa de proteção (só o professor pode ver as notas). O Proxy fica no lugar dele, com os mesmos métodos, e decide quando e se repassa o pedido.

class BoletimReal:
    def __init__(self):
        print("(carregando boletim do banco de dados...)")
        self.notas = {"Ana": 9.0, "Caio": 6.5}

    def nota(self, aluno):
        return self.notas[aluno]


class BoletimProtegido:
    def __init__(self, usuario):
        self.usuario = usuario
        self._real = None                 # só cria quando precisar

    def nota(self, aluno):
        if self.usuario != "professora" and self.usuario != aluno:
            return "acesso negado"
        if self._real is None:
            self._real = BoletimReal()
        return self._real.nota(aluno)


print("Caio vê a nota da Ana:", BoletimProtegido("Caio").nota("Ana"))
prof = BoletimProtegido("professora")
print("Professora vê a da Ana:", prof.nota("Ana"))
print("Professora vê a do Caio:", prof.nota("Caio"))

Caio vê a nota da Ana: acesso negado
(carregando boletim do banco de dados...)
Professora vê a da Ana: 9.0
Professora vê a do Caio: 6.5

Esse proxy faz duas coisas: protege (nega acesso) e adia a criação (o boletim só é carregado uma vez, no primeiro pedido permitido). Um proxy que guarda resultados para não repetir buscas lentas se chama cache; em Python, functools.lru_cache faz isso para funções.

Flyweight: compartilhar o que é igual

Problema: um jogo tem 10 000 árvores na floresta. Se cada árvore guardar sua própria cópia da textura, da cor e do nome da espécie, a memória acaba. Mas só a posição muda de uma árvore para outra!

O Flyweight ("peso-mosca") separa a parte que se repete (guardada uma vez e compartilhada) da parte que muda (guardada em cada objeto):

class Especie:
    def __init__(self, nome, cor):
        self.nome = nome
        self.cor = cor


class FabricaDeEspecies:
    def __init__(self):
        self._cache = {}

    def pegar(self, nome, cor):
        chave = (nome, cor)
        if chave not in self._cache:
            self._cache[chave] = Especie(nome, cor)
        return self._cache[chave]


class Arvore:
    __slots__ = ("x", "y", "especie")   # cada árvore guarda só isto

    def __init__(self, x, y, especie):
        self.x, self.y, self.especie = x, y, especie


fabrica = FabricaDeEspecies()
floresta = []
for i in range(10_000):
    nome = ["ipê", "jatobá", "pau-brasil"][i % 3]
    floresta.append(Arvore(i % 100, i // 100, fabrica.pegar(nome, "verde")))

print("Árvores:", len(floresta))
print("Espécies guardadas na memória:", len(fabrica._cache))
print("Mesma espécie compartilhada?", floresta[0].especie is floresta[3].especie)

Árvores: 10000
Espécies guardadas na memória: 3
Mesma espécie compartilhada? True

O Python faz algo parecido sozinho com textos curtos e números pequenos, que ele reaproveita em vez de criar de novo (por isso is às vezes dá True com eles, como viu na aula 21).

Bridge: duas variações separadas

Problema: você tem duas coisas que variam ao mesmo tempo. Controles remotos (simples, avançado) e aparelhos (TV, rádio). Com herança, seriam quatro classes: ControleSimplesTV, ControleSimplesRadio, ControleAvancadoTV… Com três aparelhos e três controles, nove!

O Bridge ("ponte") separa as duas hierarquias: o controle guarda um aparelho e conversa com ele por métodos simples. Qualquer controle funciona com qualquer aparelho:

class TV:
    def __init__(self):
        self.volume = 10

    def nome(self):
        return "TV"


class Radio:
    def __init__(self):
        self.volume = 5

    def nome(self):
        return "Rádio"


class ControleSimples:
    def __init__(self, aparelho):
        self.aparelho = aparelho          # a "ponte"

    def mais_volume(self):
        self.aparelho.volume += 1
        print(f"{self.aparelho.nome()}: volume {self.aparelho.volume}")


class ControleAvancado(ControleSimples):
    def mudo(self):
        self.aparelho.volume = 0
        print(f"{self.aparelho.nome()}: mudo")


ControleSimples(TV()).mais_volume()
ControleSimples(Radio()).mais_volume()
avancado = ControleAvancado(Radio())
avancado.mais_volume()
avancado.mudo()

TV: volume 11
Rádio: volume 6
Rádio: volume 6
Rádio: mudo

Agora são 2 controles + 2 aparelhos = 4 classes, e cada novo aparelho funciona com todos os controles.

Parecidos, mas diferentes

Adapter, Decorator, Proxy e Facade "embrulham" um objeto. A diferença está na intenção:

  • Adapter muda o formato (os nomes dos métodos) para encaixar.
  • Decorator mantém o formato e acrescenta comportamento; pode embrulhar várias vezes.
  • Proxy mantém o formato e controla o acesso (protege, adia, guarda em cache).
  • Facade cria uma porta nova e mais simples para um conjunto de objetos.
Atenção: Não crie camadas "por precaução". Cada embrulho é mais um lugar para o leitor seguir. Use esses padrões quando o problema aparecer: uma biblioteca com formato diferente, combinações que explodem, acesso que precisa de controle.
Pratique no DIGITAR: digite este trecho no modo Programar do app. 
pedido = ComChantili(ComLeite(Cafe()))

1. Você tem uma função mostrar_temperatura(sensor) que chama sensor.celsius(). Um sensor importado só tem o método fahrenheit(). Escreva um adaptador para usá-lo sem mudar a função. (Fórmula: C = (F − 32) × 5 / 9.)

Ver resposta 
class SensorAmericano:
    def fahrenheit(self):
        return 86.0


class AdaptadorCelsius:
    def __init__(self, sensor):
        self.sensor = sensor

    def celsius(self):
        return (self.sensor.fahrenheit() - 32) * 5 / 9


def mostrar_temperatura(sensor):
    print(f"Temperatura: {sensor.celsius():.1f} °C")


mostrar_temperatura(AdaptadorCelsius(SensorAmericano()))

Temperatura: 30.0 °C

2. Use Composite para um cardápio: Prato(nome, preco) e Combo(nome, *itens), ambos com preco(). O combo custa a soma dos itens com 10% de desconto. Mostre o preço de um combo com hambúrguer (R$ 25), batata (R$ 12) e um combo interno de refri (R$ 8) e sorvete (R$ 10).

Ver resposta 
class Prato:
    def __init__(self, nome, preco):
        self.nome = nome
        self._preco = preco

    def preco(self):
        return self._preco


class Combo:
    def __init__(self, nome, *itens):
        self.nome = nome
        self.itens = itens

    def preco(self):
        return sum(i.preco() for i in self.itens) * 0.9


sobremesa = Combo("Refri e sorvete", Prato("Refri", 8), Prato("Sorvete", 10))
grande = Combo("Combo grande", Prato("Hambúrguer", 25), Prato("Batata", 12), sobremesa)
print(f"{grande.nome}: R$ {grande.preco():.2f}")

Combo grande: R$ 47.88

O combo interno já tem desconto e, dentro do combo grande, recebe mais 10%.

4. Escreva um proxy de cache para uma busca lenta: BuscaDeCep conta quantas vezes foi chamada; BuscaComCache guarda os resultados num dicionário. Busque o mesmo CEP três vezes e mostre que a busca real só aconteceu uma vez.

Ver resposta 
class BuscaDeCep:
    def __init__(self):
        self.chamadas = 0

    def cidade(self, cep):
        self.chamadas += 1
        return {"40000-000": "Salvador", "69000-000": "Manaus"}.get(cep, "?")


class BuscaComCache:
    def __init__(self, real):
        self.real = real
        self.cache = {}

    def cidade(self, cep):
        if cep not in self.cache:
            self.cache[cep] = self.real.cidade(cep)
        return self.cache[cep]


real = BuscaDeCep()
busca = BuscaComCache(real)
for _ in range(3):
    print(busca.cidade("40000-000"))
print("Buscas reais:", real.chamadas)

Salvador
Salvador
Buscas reais: 1

5. Qual é a diferença de intenção entre Adapter, Decorator e Facade?

Ver resposta

Adapter: troca o formato de um objeto para ele encaixar onde se espera outro formato.
Decorator: mantém o mesmo formato e acrescenta comportamento, podendo embrulhar várias vezes.
Facade: oferece uma porta nova e simples para usar várias partes de um sistema de uma vez.
