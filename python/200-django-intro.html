O que é o Django

Um site tem muitas partes que se repetem em todo projeto: receber o pedido do navegador, descobrir qual página foi pedida, falar com o banco de dados, montar o HTML, cuidar de login e de segurança.

O Django é um framework web: um conjunto de peças prontas, em Python, que resolve essas partes. Você escreve só o que é próprio do seu site. Sites grandes, como o Instagram, começaram com Django.

Neste módulo você vai construir sites de verdade: uma agenda de contatos (aula 207), um blog (aula 211) e uma loja (aula 215). Um site precisa de um servidor rodando, então os códigos do Django são feitos no seu computador. Os exemplos com o botão Executar mostram as ideias com Python puro.

Como um site funciona: pedido e resposta

Quando você digita um endereço, o navegador manda um pedido (request) ao servidor dizendo qual caminho quer, como /contatos/. O servidor procura esse caminho numa lista de rotas (as URLs), chama a função responsável (a view) e devolve uma resposta (response) com o HTML e um código de status: 200 quer dizer "deu certo" e 404 quer dizer "não encontrei".

O Django faz exatamente isso. Esta versão em miniatura, com um dicionário de rotas, roda aqui:

def inicio():
    return 200, "<h1>Bem-vindo!</h1>"


def contatos():
    return 200, "<ul><li>Ana</li><li>Caio</li></ul>"


rotas = {
    "/": inicio,
    "/contatos/": contatos,
}


def atender(caminho):
    view = rotas.get(caminho)
    if view is None:
        return 404, "<h1>Página não encontrada</h1>"
    return view()


for pedido in ["/", "/contatos/", "/fotos/"]:
    status, html = atender(pedido)
    print(f"{pedido:<12} -> {status} {html}")

/            -> 200 <h1>Bem-vindo!</h1>
/contatos/   -> 200 <ul><li>Ana</li><li>Caio</li></ul>
/fotos/      -> 404 <h1>Página não encontrada</h1>

No Django, o dicionário rotas vira o arquivo urls.py, as funções inicio e contatos vão para o views.py, e o próprio Django faz o papel do atender. A aula 201 mostra isso em detalhes.

Dica: Guarde esta imagem: URL → view → resposta. Quase todo erro no Django é uma dessas três partes: a URL não bate, a view tem um erro, ou a resposta não é a esperada.

Instalando e criando o projeto

Abra o terminal (aula 03) e crie uma pasta para o site, com um ambiente virtual próprio (aula 60). No Windows:

mkdir meusite
cd meusite
py -m venv .venv
.venv\Scripts\activate
pip install django
django-admin startproject config .
python manage.py runserver

No Linux e no macOS, troque as linhas do ambiente virtual por python3 -m venv .venv e source .venv/bin/activate; o resto é igual.

└── config/

Para ver que é uma estrutura comum de pastas e arquivos, este exemplo monta a mesma árvore numa pasta temporária com pathlib (aula 103) e a desenha:

import tempfile
from pathlib import Path

with tempfile.TemporaryDirectory() as tmp:
    raiz = Path(tmp) / "meusite"
    for arquivo in ["manage.py", "config/__init__.py", "config/settings.py",
                    "config/urls.py", "config/asgi.py", "config/wsgi.py"]:
        caminho = raiz / arquivo
        caminho.parent.mkdir(parents=True, exist_ok=True)
        caminho.touch()

    print(raiz.name + "/")
    for item in sorted(raiz.rglob("*")):
        nivel = len(item.relative_to(raiz).parts) - 1
        nome = item.name + ("/" if item.is_dir() else "")
        print("    " * nivel + "├── " + nome)

    ├── asgi.py
    ├── settings.py
    ├── urls.py
    ├── wsgi.py
├── manage.py

O arquivo que você mais vai abrir no começo é o settings.py. Vale ajustar logo o idioma e o fuso, para as mensagens do Django aparecerem em português e as horas no horário de Brasília:

# config/settings.py (trecho)
LANGUAGE_CODE = "pt-br"
TIME_ZONE = "America/Sao_Paulo"
USE_I18N = True
USE_TZ = True

(salve e recarregue a página do foguete: os textos dela aparecem em português)

O manage.py, seu controle remoto

O manage.py roda os comandos do projeto. Sempre rode na pasta onde ele está, com o ambiente virtual ativado:

  • python manage.py runserver liga o servidor de desenvolvimento;
  • python manage.py startapp nome cria um app;
  • python manage.py check procura erros de configuração sem ligar o servidor;
  • python manage.py migrate cria ou atualiza as tabelas do banco (aula 203);
  • python manage.py createsuperuser cria o usuário administrador (aula 203);
  • python manage.py shell abre o Python já com o projeto carregado (aula 204).

Por dentro, o manage.py é um arquivo Python bem curto, gerado pelo Django. Ele só diz onde estão as configurações e passa o comando adiante:

# manage.py (gerado pelo Django; resumido)
import os
import sys


def main():
    os.environ.setdefault("DJANGO_SETTINGS_MODULE", "config.settings")
    from django.core.management import execute_from_command_line
    execute_from_command_line(sys.argv)


if __name__ == "__main__":
    main()
python manage.py check

System check identified no issues (0 silenced).

Repare no if __name__ == "__main__" da aula 100 e no sys.argv da aula 110: o manage.py usa coisas que você já conhece.

Apps: as partes do site

Um projeto Django é dividido em apps, e cada app cuida de uma parte do site: contatos, blog, loja, usuários. Assim, cada parte fica numa pasta própria e pode até ser reaproveitada em outro projeto.

Crie o app contatos, que vai crescer ao longo do módulo até virar a agenda da aula 207:

python manage.py startapp contatos

contatos/
├── migrations/   <- histórico das mudanças no banco
├── __init__.py
├── admin.py      <- o que aparece na área administrativa
├── apps.py
├── models.py     <- as tabelas (aula 203)
├── tests.py      <- os testes (módulo 6)
└── views.py      <- as views (aula 201)

Criar a pasta não basta: é preciso registrar o app no settings.py, acrescentando o nome dele no fim da lista INSTALLED_APPS:

# config/settings.py (trecho)
INSTALLED_APPS = [
    "django.contrib.admin",
    "django.contrib.auth",
    "django.contrib.contenttypes",
    "django.contrib.sessions",
    "django.contrib.messages",
    "django.contrib.staticfiles",
    "contatos",
]

(rode python manage.py check de novo: continua sem problemas)

Os seis primeiros itens são apps que já vêm com o Django: a área administrativa, os usuários e senhas, as sessões e outros.

Atenção: Esquecer de pôr o app em INSTALLED_APPS é um erro clássico: o Django não encontra os models nem os templates dele, e os erros aparecem só mais tarde, parecendo não ter nada a ver.
Pratique no DIGITAR: digite este trecho no modo Programar do app. 
python manage.py startapp contatos

Exercícios

1. Quais comandos criam um projeto config na pasta atual e um app chamado receitas? O que falta fazer depois?

Ver resposta 
django-admin startproject config .
python manage.py startapp receitas

Depois, acrescente "receitas" no fim da lista INSTALLED_APPS, em config/settings.py.

2. No mini-servidor da aula, acrescente uma view sobre para o caminho /sobre/ que devolve <p>Site feito em Python</p> e teste os caminhos /sobre/ e /Sobre/.

Ver resposta 
def inicio():
    return 200, "<h1>Bem-vindo!</h1>"


def sobre():
    return 200, "<p>Site feito em Python</p>"


rotas = {"/": inicio, "/sobre/": sobre}


def atender(caminho):
    view = rotas.get(caminho)
    if view is None:
        return 404, "<h1>Página não encontrada</h1>"
    return view()


for pedido in ["/sobre/", "/Sobre/"]:
    print(pedido, "->", atender(pedido))

/sobre/ -> (200, '<p>Site feito em Python</p>')
/Sobre/ -> (404, '<h1>Página não encontrada</h1>')

Os caminhos diferenciam maiúsculas de minúsculas: /Sobre/ não é a mesma rota que /sobre/ e dá 404. No Django acontece o mesmo.

3. O servidor mostrou Error: That port is already in use. O que aconteceu e como resolver?

Ver resposta 
python manage.py runserver 8001

Outro programa (talvez outro terminal com o seu servidor) já usa a porta 8000. Feche-o com Ctrl+C ou rode em outra porta, como 8001, e abra http://127.0.0.1:8001/.

4. Em qual arquivo você muda o idioma do site para português? E em qual ficam os endereços do site?

Ver resposta

O idioma fica em config/settings.py, na linha LANGUAGE_CODE = "pt-br".
Os endereços (as rotas) ficam em config/urls.py.

5. Você digitou python manage.py runserver e apareceu can't open file 'manage.py': No such file or directory. O que está errado?

Ver resposta

O terminal não está na pasta do projeto (a que tem o manage.py).
Use cd para entrar na pasta meusite e rode o comando de novo.
