Aula para fazer no computador: o assunto desta aula precisa do seu computador. Os códigos sem o botão Executar devem ser copiados para um arquivo .py no VS Code e rodados no seu computador, como mostrado na aula 03.

Para que serve o Docker

"Na minha máquina funciona!" — o Docker resolve essa frase. Ele empacota o programa com tudo de que precisa (Python, bibliotecas, configurações) numa imagem. Um container é uma imagem rodando. Quem tiver Docker roda igualzinho, em qualquer computador.

No Windows, instale o Docker Desktop (docker.com), que usa o WSL2. Confira:

docker --version
docker compose version

O Dockerfile

# Dockerfile (na pasta do projeto, sem extensão)
FROM python:3.12-slim
ENV PYTHONDONTWRITEBYTECODE=1 PYTHONUNBUFFERED=1
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
CMD ["python", "manage.py", "runserver", "0.0.0.0:8000"]

O requirements.txt (aula 60) lista django e psycopg[binary], o driver do PostgreSQL.

Atenção: Dentro do container use 0.0.0.0:8000, não 127.0.0.1. Com 127.0.0.1, o servidor só aceita conexões de dentro do próprio container e o navegador do seu computador não consegue abrir.

Docker Compose: vários containers

# compose.yaml
services:
  db:
    image: postgres:16
    environment:
      POSTGRES_DB: agenda
      POSTGRES_USER: agenda
      POSTGRES_PASSWORD: troque-esta-senha
    volumes:
      - dados_db:/var/lib/postgresql/data
  web:
    build: .
    ports:
      - "8000:8000"
    env_file: .env
    depends_on:
      - db
volumes:
  dados_db:

No settings.py, o banco aponta para o serviço db:

import os

DATABASES = {
    "default": {
        "ENGINE": "django.db.backends.postgresql",
        "NAME": os.environ.get("POSTGRES_DB", "agenda"),
        "USER": os.environ.get("POSTGRES_USER", "agenda"),
        "PASSWORD": os.environ.get("POSTGRES_PASSWORD", ""),
        "HOST": "db",
        "PORT": "5432",
    }
}
docker compose up --build
docker compose exec web python manage.py migrate
docker compose down
Dica: O volume dados_db guarda os dados do banco: você pode parar e subir os containers de novo sem perder nada. Senhas de verdade ficam no .env (aula 177), fora do Git.
Pratique no DIGITAR: digite este trecho no modo Programar do app. 
docker compose exec web python manage.py migrate

Exercícios

1. Qual comando cria um superusuário do Django rodando dentro do container web?

Ver resposta 
docker compose exec web python manage.py createsuperuser

2. Você mudou o requirements.txt e acrescentou uma biblioteca. O que precisa fazer para ela entrar no container?

Ver resposta 
docker compose up --build

A imagem precisa ser reconstruída, porque o pip install acontece no build.
