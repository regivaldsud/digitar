Padrões de projeto

Um padrão de projeto é uma solução conhecida para um problema que aparece muitas vezes. Os 23 padrões clássicos foram reunidos em 1994 num livro de quatro autores (a "Gangue dos Quatro", GoF). Os criacionais tratam de uma pergunta: como criar objetos sem espalhar if e detalhes pelo programa?

Factory Method e Abstract Factory

Uma fábrica é uma função ou método que decide qual classe criar. Quem pede o objeto não precisa conhecer as classes:

class Pix:
    def pagar(self, valor):
        return f"Pix de R$ {valor:.2f} enviado"


class Boleto:
    def pagar(self, valor):
        return f"Boleto de R$ {valor:.2f} gerado"


def criar_pagamento(tipo):
    tipos = {"pix": Pix, "boleto": Boleto}
    return tipos[tipo]()


for tipo in ["pix", "boleto"]:
    print(criar_pagamento(tipo).pagar(49.9))

Pix de R$ 49.90 enviado
Boleto de R$ 49.90 gerado

A Abstract Factory vai um passo além: uma fábrica cria uma família inteira de objetos que combinam entre si (por exemplo, botão e janela do tema claro, ou botão e janela do tema escuro).

class TemaClaro:
    def botao(self):
        return "[botão branco]"

    def fundo(self):
        return "fundo branco"


class TemaEscuro:
    def botao(self):
        return "[botão preto]"

    def fundo(self):
        return "fundo preto"


def montar_tela(fabrica):
    print(fabrica.fundo(), "com", fabrica.botao())


montar_tela(TemaClaro())
montar_tela(TemaEscuro())

fundo branco com [botão branco]
fundo preto com [botão preto]

Builder: montando passo a passo

Quando um objeto tem muitas partes opcionais, o Builder monta aos poucos. Cada método devolve self, e por isso dá para encadear as chamadas:

class Pizza:
    def __init__(self):
        self.sabor = "mussarela"
        self.borda = "simples"
        self.extras = []

    def __str__(self):
        extras = ", ".join(self.extras) or "nenhum"
        return f"Pizza de {self.sabor}, borda {self.borda}, extras: {extras}"


class MontadorDePizza:
    def __init__(self):
        self.pizza = Pizza()

    def sabor(self, s):
        self.pizza.sabor = s
        return self

    def borda(self, b):
        self.pizza.borda = b
        return self

    def extra(self, e):
        self.pizza.extras.append(e)
        return self

    def pronta(self):
        return self.pizza


p = MontadorDePizza().sabor("calabresa").borda("catupiry").extra("cebola").pronta()
print(p)

Pizza de calabresa, borda catupiry, extras: cebola

Singleton e Prototype

O Singleton garante um único objeto de uma classe (por exemplo, a configuração do programa). Em Python, o jeito mais simples é usar um módulo, porque cada módulo é carregado uma vez só. Já o Prototype cria objetos novos copiando um modelo pronto, com copy.deepcopy:

import copy


class Configuracao:
    _unica = None

    def __new__(cls):
        if cls._unica is None:
            cls._unica = super().__new__(cls)
            cls._unica.idioma = "pt-BR"
        return cls._unica


a = Configuracao()
b = Configuracao()
print(a is b)

modelo = {"turma": "7º A", "alunos": ["Ana", "Rui"]}
nova = copy.deepcopy(modelo)
nova["turma"] = "7º B"
nova["alunos"].append("Lia")
print(modelo)
print(nova)

True
{'turma': '7º A', 'alunos': ['Ana', 'Rui']}
{'turma': '7º B', 'alunos': ['Ana', 'Rui', 'Lia']}

Atenção: O Singleton cria um "estado global" escondido, o que dificulta testes. Use só quando realmente precisar de um objeto único.
Pratique no DIGITAR: digite este trecho no modo Programar do app. 
pagamento = criar_pagamento("pix")
