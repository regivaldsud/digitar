O caminho de um formulário

Um formulário é a forma de a pessoa mandar dados para o site: cadastrar um contato, fazer login, escrever um comentário. No HTML, ele é a tag <form>, com campos <input> e um botão.

Cada campo tem um name. Quando a pessoa aperta o botão, o navegador junta tudo num texto do tipo nome=Ana&telefone=81+99999-0000 e manda para o servidor.

  • Com method="get", esse texto vai no endereço, depois do ?. Serve para buscas: /?q=ana.
  • Com method="post", o texto vai escondido no corpo do pedido. Serve para tudo que grava, muda ou apaga dados.

O Django lê esse texto para você e entrega um dicionário: request.GET ou request.POST. Veja como esse texto é desmontado, usando só a biblioteca padrão:

from urllib.parse import parse_qs

corpo = "nome=Ana+Souza&telefone=81+99999-0000&favorito=on&email="
dados = parse_qs(corpo, keep_blank_values=True)
print(dados)
print("Nome:", dados["nome"][0])
print("Favorito marcado?", "favorito" in dados)
print("E-mail vazio?", dados["email"][0] == "")

{'nome': ['Ana Souza'], 'telefone': ['81 99999-0000'], 'favorito': ['on'], 'email': ['']}
Nome: Ana Souza
Favorito marcado? True
E-mail vazio? True

Repare que o + virou espaço e que cada valor vem numa lista (um campo pode aparecer mais de uma vez). Uma caixa de seleção (checkbox) desmarcada simplesmente não é enviada — por isso testamos com in.

Atenção: Tudo o que chega de um formulário é texto, até a idade e o preço. E pode vir qualquer coisa: vazio, letras no lugar de números, um texto gigante. Nunca grave no banco sem validar.

Validar: um formulário feito à mão

Antes de ver o jeito do Django, vale montar um validador pequeno em Python puro. Ele faz o mesmo trabalho que um formulário do Django: confere cada campo, guarda os erros por campo e, se tudo estiver certo, entrega os dados já limpos e convertidos em cleaned_data.

class FormularioContato:
    def __init__(self, dados):
        self.dados = dados
        self.errors = {}
        self.cleaned_data = {}

    def is_valid(self):
        nome = self.dados.get("nome", "").strip()
        if len(nome) < 2:
            self.errors["nome"] = "O nome precisa de pelo menos 2 letras."
        else:
            self.cleaned_data["nome"] = nome.title()

        telefone = self.dados.get("telefone", "")
        digitos = "".join(c for c in telefone if c.isdigit())
        if len(digitos) < 10:
            self.errors["telefone"] = "Informe o DDD e o número."
        else:
            self.cleaned_data["telefone"] = digitos

        self.cleaned_data["favorito"] = "favorito" in self.dados
        return not self.errors


ruim = FormularioContato({"nome": " a", "telefone": "9999-0000"})
print(ruim.is_valid(), ruim.errors)

bom = FormularioContato({"nome": "  ana souza ", "telefone": "(81) 99999-0000", "favorito": "on"})
print(bom.is_valid(), bom.cleaned_data)

False {'nome': 'O nome precisa de pelo menos 2 letras.', 'telefone': 'Informe o DDD e o número.'}
True {'nome': 'Ana Souza', 'telefone': '81999990000', 'favorito': True}

Essa é a ideia central de todo formulário: dados crus entram, dados limpos ou uma lista de erros saem. O Django faz isso com muito mais campos prontos, mensagens em português e proteção contra ataques.

forms.Form: o formulário do Django

No Django, um formulário é uma classe que herda de forms.Form. Cada atributo é um campo, com o tipo e as regras dele. Crie o arquivo contatos/forms.py:

# contatos/forms.py
from django import forms


class InscricaoForm(forms.Form):
    nome = forms.CharField(max_length=100)
    email = forms.EmailField()
    idade = forms.IntegerField(min_value=8, max_value=120)

Teste no shell (python manage.py shell), sem precisar de página nenhuma:

from contatos.forms import InscricaoForm

form = InscricaoForm({"nome": "Ana", "email": "ana@exemplo", "idade": "5"})
print(form.is_valid())
for campo, erros in form.errors.items():
    print(campo, "->", erros[0])

form = InscricaoForm({"nome": "Ana", "email": "ana@exemplo.com", "idade": "12"})
print(form.is_valid())
print(form.cleaned_data)

False
email -> Informe um endereço de email válido.
idade -> Certifique-se que este valor seja maior ou igual a 8.
True
{'nome': 'Ana', 'email': 'ana@exemplo.com', 'idade': 12}

As mensagens saem em português porque o projeto usa LANGUAGE_CODE = "pt-br" no settings.py. Repare que, em cleaned_data, a idade já virou o número 12, não o texto "12".

Atenção: cleaned_data só existe depois de chamar is_valid(). Escrever form.cleaned_data["nome"] antes disso dá AttributeError. A ordem é sempre: criar o formulário com os dados, chamar is_valid(), e só então ler cleaned_data.

ModelForm: o formulário que nasce do model

Quando o formulário serve para salvar um model, não precisa repetir os campos: o ModelForm lê o model Contato (aula 203) e cria os campos, os tipos e as validações básicas sozinho. Ele ainda ganha o método save(), que grava no banco.

# contatos/forms.py
from django import forms
from .models import Contato


class ContatoForm(forms.ModelForm):
    class Meta:
        model = Contato
        fields = ["nome", "telefone", "email", "nascimento", "favorito"]
        widgets = {"nascimento": forms.DateInput(attrs={"type": "date"})}

    def clean_nome(self):
        nome = self.cleaned_data["nome"].strip()
        if len(nome) < 2:
            raise forms.ValidationError("O nome precisa de pelo menos 2 letras.")
        return nome

    def clean_telefone(self):
        telefone = self.cleaned_data["telefone"]
        digitos = "".join(c for c in telefone if c.isdigit())
        if len(digitos) < 10:
            raise forms.ValidationError("Informe o DDD e o número.")
        return telefone

(não imprime nada: este arquivo só define a classe ContatoForm)

  • fields diz quais campos do model aparecem. Campos automáticos, como criado_em, ficam de fora.
  • widgets troca o jeito de desenhar um campo; type="date" mostra um calendário no navegador.
  • Um método clean_<campo> valida um campo: lance ValidationError com a mensagem que o usuário vai ver, ou devolva o valor (pode devolver arrumado, como o nome sem espaços).
Dica: Para uma regra que envolve dois campos juntos (por exemplo, "senha" e "confirme a senha" iguais), use o método clean(self): ele roda depois dos clean_<campo> e enxerga todo o cleaned_data. Para marcar o erro num campo, use self.add_error("campo", "mensagem").

A view: mostrar no GET, receber no POST

A mesma view atende duas situações. Na primeira visita (GET) ela mostra o formulário vazio. Quando a pessoa envia (POST), ela valida: se estiver tudo certo, salva e redireciona; se não, mostra o formulário de novo, com o que foi digitado e as mensagens de erro.

# contatos/views.py
from django.shortcuts import redirect, render
from .forms import ContatoForm


def novo(request):
    if request.method == "POST":
        form = ContatoForm(request.POST)
        if form.is_valid():
            form.save()
            return redirect("lista")
    else:
        form = ContatoForm()
    return render(request, "contatos/form.html", {"form": form})

GET  /novo/  -> 200, formulário vazio
POST /novo/ com telefone "123"  -> 200, formulário de volta com "Informe o DDD e o número."
POST /novo/ com dados certos  -> 302, redireciona para a lista

E o template contatos/templates/contatos/form.html:

{% extends "base.html" %}
{% block conteudo %}
<form method="post">
  {% csrf_token %}
  {{ form.as_p }}
  <button type="submit">Salvar</button>
</form>
{% endblock %}

{{ form.as_p }} desenha cada campo dentro de um <p>, já com o rótulo e os erros. Se quiser controlar o desenho, percorra os campos:

{% for campo in form %}
  <p>
    {{ campo.label_tag }} {{ campo }}
    {% for erro in campo.errors %}<span class="erro">{{ erro }}</span>{% endfor %}
  </p>
{% endfor %}
Dica: Depois de salvar, sempre faça redirect. Se a view devolvesse a página direto, a pessoa que apertasse F5 reenviaria o formulário e criaria um contato repetido. Esse costume tem até nome: Post/Redirect/Get.

csrf_token: a proteção contra envios falsos

Imagine que você está logado na sua agenda e abre um site mal-intencionado. Esse site pode ter um formulário escondido que envia um POST para a sua agenda — e o seu navegador manda junto o seu login! Esse ataque se chama CSRF (falsificação de pedido entre sites).

A defesa é um código secreto: o Django coloca no formulário um campo escondido com um valor que só a página dele conhece. No POST, ele confere o código; o site falso não tem como saber esse valor. A ideia, em Python puro:

import hmac
import secrets

token_da_sessao = secrets.token_urlsafe(16)          # o Django guarda isso para você
pagina = f'<input type="hidden" name="csrfmiddlewaretoken" value="{token_da_sessao}">'


def post_aceito(token_enviado):
    return hmac.compare_digest(token_enviado, token_da_sessao)


print("Pedido da página verdadeira:", post_aceito(token_da_sessao))
print("Pedido do site falso:", post_aceito("chute-qualquer"))
print("Tamanho do código:", len(token_da_sessao), "caracteres")

Pedido da página verdadeira: True
Pedido do site falso: False
Tamanho do código: 22 caracteres

Atenção: Sem {% csrf_token %} dentro do <form method="post">, o Django recusa o envio com 403 Forbidden — CSRF verification failed. Se aparecer esse erro, a primeira coisa a conferir é se a tag está dentro do <form>. Formulários com method="get" não precisam dela, porque não devem mudar nada.
Pratique no DIGITAR: digite este trecho no modo Programar do app. 
if form.is_valid(): form.save()

4. Acrescente ao FormularioContato feito à mão um campo idade opcional: se vier vazio, cleaned_data["idade"] fica None; se vier, precisa ser um número de 0 a 120.

Ver resposta 
class FormularioContato:
    def __init__(self, dados):
        self.dados = dados
        self.errors = {}
        self.cleaned_data = {}

    def is_valid(self):
        nome = self.dados.get("nome", "").strip()
        if len(nome) < 2:
            self.errors["nome"] = "O nome precisa de pelo menos 2 letras."
        else:
            self.cleaned_data["nome"] = nome
        idade = self.dados.get("idade", "").strip()
        if idade == "":
            self.cleaned_data["idade"] = None

        else:
            self.cleaned_data["idade"] = int(idade)
        return not self.errors

5. Num formulário de cadastro com os campos senha e confirmacao, escreva o método clean que avisa quando as duas são diferentes.

Ver resposta 
from django import forms


class CadastroForm(forms.Form):
    senha = forms.CharField(widget=forms.PasswordInput)
    confirmacao = forms.CharField(widget=forms.PasswordInput)

    def clean(self):
        dados = super().clean()
        if dados.get("senha") != dados.get("confirmacao"):
            self.add_error("confirmacao", "As senhas não são iguais.")
        return dados

Use dados.get(...) e não dados[...]: se um dos campos já falhou na sua própria validação, ele não está em cleaned_data.

6. Você criou um formulário com method="post", preencheu, apertou Salvar e apareceu "403 Forbidden — CSRF verification failed". O que provavelmente faltou e por que o Django faz isso?

Ver resposta

Faltou {% csrf_token %} dentro do <form method="post">.
