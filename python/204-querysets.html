A ORM: Python no lugar do SQL

A ORM (mapeamento objeto-relacional) é a parte do Django que traduz código Python em SQL. Em vez de escrever SELECT * FROM contatos_contato WHERE favorito = 1, você escreve Contato.objects.filter(favorito=True). Toda busca começa pelo objects do model, o gerenciador.

O resultado de uma busca é um QuerySet: uma "lista" de registros que ainda pode ser refinada com mais filtros. Ele é preguiçoso: montar o QuerySet não vai ao banco. A consulta só acontece quando você usa os resultados — num for, num print, com count(), list() ou no template.

Os exemplos usam o model Contato da aula 203. Abra o shell do projeto:

python manage.py shell

Criar, ler, alterar e apagar

Digite no shell, linha por linha:

from contatos.models import Contato

Contato.objects.create(nome="Ana", telefone="81 99999-0000", email="ana@email.com", favorito=True)
Contato.objects.create(nome="Bruno", telefone="11 98888-1111")
Contato.objects.create(nome="Carla", telefone="81 97777-3333", email="carla@email.com")
Contato.objects.create(nome="Davi", telefone="11 96666-4444", favorito=True)
Contato.objects.create(nome="Beatriz", telefone="21 95555-5555", favorito=True)

print(Contato.objects.count())
print(Contato.objects.all())
print(Contato.objects.filter(favorito=True))

Os contatos vêm em ordem alfabética por causa do ordering = ["nome"] do model. Para alterar, pegue o registro, mude o atributo e chame save(). Para apagar, use delete():

from contatos.models import Contato

ana = Contato.objects.get(nome="Ana")
ana.telefone = "81 90000-2222"
ana.save()
print(Contato.objects.get(nome="Ana").telefone)

print(Contato.objects.filter(nome="Bruno").delete())
print(Contato.objects.count())

print(Contato.objects.filter(telefone__startswith="81").update(favorito=True))

81 90000-2222
(1, {'contatos.Contato': 1})
4
2

O delete() conta quantos registros apagou. O update() altera de uma vez todos os registros do QuerySet, direto no banco, e devolve quantos mudou — aqui, Ana e Carla viraram favoritas.

Atenção: Sem o save(), a mudança fica só na variável do Python e se perde. E cuidado: Contato.objects.all().delete() apaga todos os contatos, sem pedir confirmação.

get ou filter?

  • filter(...) devolve um QuerySet com zero, um ou muitos registros. Nunca dá erro por não achar: devolve um QuerySet vazio.
  • get(...) devolve um registro. Se não achar nenhum, levanta Contato.DoesNotExist; se achar mais de um, Contato.MultipleObjectsReturned.
from contatos.models import Contato

try:
    Contato.objects.get(nome="Zeca")
except Contato.DoesNotExist as erro:
    print("Não achei:", erro)

try:
    Contato.objects.get(favorito=True)
except Contato.MultipleObjectsReturned as erro:
    print("Achei demais:", erro)

print(Contato.objects.filter(nome="Zeca").first())
print(Contato.objects.filter(nome="Zeca").exists())

Não achei: Contato matching query does not exist.
Achei demais: get() returned more than one Contato -- it returned 4!
None
False

Use get para buscar por algo único, como o id. Numa view, troque o get por get_object_or_404 (de django.shortcuts): se o contato não existir, o visitante recebe a página 404 em vez de um erro 500. A view def detalhe(request, id) ficaria contato = get_object_or_404(Contato, id=id).

A mesma lógica, em Python puro, sobre uma lista de dicionários. É assim que você pode imaginar um filter, um exclude e um get:

contatos = [
    {"id": 1, "nome": "Ana", "telefone": "81 99999-0000", "favorito": True},
    {"id": 2, "nome": "Bruno", "telefone": "11 98888-1111", "favorito": False},
    {"id": 3, "nome": "Carla", "telefone": "81 97777-3333", "favorito": False},
    {"id": 4, "nome": "Davi", "telefone": "11 96666-4444", "favorito": True},
]


def filtrar(lista, **condicoes):
    return [c for c in lista if all(c[k] == v for k, v in condicoes.items())]


def excluir(lista, **condicoes):
    return [c for c in lista if not all(c[k] == v for k, v in condicoes.items())]


def pegar(lista, **condicoes):
    achados = filtrar(lista, **condicoes)
    if len(achados) == 0:
        raise LookupError("nenhum registro encontrado")
    if len(achados) > 1:
        raise LookupError(f"achei {len(achados)} registros")
    return achados[0]


print([c["nome"] for c in filtrar(contatos, favorito=True)])
print([c["nome"] for c in excluir(contatos, favorito=True)])
print(pegar(contatos, id=3)["nome"])
try:
    pegar(contatos, favorito=True)
except LookupError as erro:
    print("Erro:", erro)

['Ana', 'Davi']
['Bruno', 'Carla']
Carla
Erro: achei 2 registros

Buscas com dois sublinhados

Para comparar de outros jeitos além de "igual a", o nome do campo ganha um sufixo depois de dois sublinhados (__). Os mais usados:

  • nome__icontains="a": contém "a", sem ligar para maiúsculas (o i vem de *insensitive*);
  • nome__startswith="B" e nome__endswith="a": começa ou termina com;
  • id__gte=3, id__gt, id__lte, id__lt: maior ou igual, maior, menor ou igual, menor;
  • nome__in=["Ana", "Davi"]: está na lista.

Com os quatro contatos que sobraram (Ana, Beatriz, Carla e Davi):

from contatos.models import Contato

print(Contato.objects.filter(nome__icontains="a"))
print(Contato.objects.filter(nome__startswith="B"))
print(Contato.objects.exclude(email=""))
print(Contato.objects.filter(nome__in=["Ana", "Davi"]))
print(Contato.objects.filter(nome__icontains="a").query)

<QuerySet [<Contato: Ana>, <Contato: Beatriz>, <Contato: Carla>, <Contato: Davi>]>
<QuerySet [<Contato: Beatriz>]>
<QuerySet [<Contato: Ana>, <Contato: Carla>]>
<QuerySet [<Contato: Ana>, <Contato: Davi>]>
SELECT "contatos_contato"."id", "contatos_contato"."nome", (...) FROM "contatos_contato" WHERE "contatos_contato"."nome" LIKE %a% ESCAPE '\' ORDER BY "contatos_contato"."nome" ASC

O .query mostra o SQL que o Django montou: o __icontains virou um LIKE (aula 172). Colocar dois filtros no mesmo filter, separados por vírgula, exige os dois ao mesmo tempo: filter(favorito=True, nome__startswith="B").

Atenção: São dois sublinhados: nome__icontains. Com um só (nome_icontains), o Django procura um campo com esse nome e dá FieldError: Cannot resolve keyword 'nome_icontains' into field.

Q, ordenação e fatias

Vírgulas no filter significam "e". Para "ou" e "não", use o objeto Q: | é ou, & é e, ~ é não. Para ordenar, order_by("campo") vai do menor para o maior e order_by("-campo"), com o sinal de menos, inverte. E fatias (aula 20) limitam a quantidade — o Django transforma [:2] num LIMIT 2 no SQL.

from django.db.models import Q
from contatos.models import Contato

print(Contato.objects.filter(Q(telefone__startswith="21") | Q(nome="Davi")))
print(Contato.objects.filter(Q(favorito=True) & ~Q(telefone__startswith="11")))
print(Contato.objects.order_by("-nome"))
print(Contato.objects.order_by("-criado_em")[:2])

<QuerySet [<Contato: Beatriz>, <Contato: Davi>]>
<QuerySet [<Contato: Ana>, <Contato: Beatriz>, <Contato: Carla>]>
<QuerySet [<Contato: Davi>, <Contato: Carla>, <Contato: Beatriz>, <Contato: Ana>]>
<QuerySet [<Contato: Beatriz>, <Contato: Davi>]>

A última linha traz os dois contatos criados por último (Beatriz foi a quinta, Davi o quarto). Em Python puro, o "ou" é um or dentro da comprehension e o order_by("-nome") é um sorted com reverse=True:

contatos = [
    {"nome": "Ana", "telefone": "81 90000-2222", "favorito": True, "ordem": 1},
    {"nome": "Carla", "telefone": "81 97777-3333", "favorito": True, "ordem": 3},
    {"nome": "Davi", "telefone": "11 96666-4444", "favorito": True, "ordem": 4},
    {"nome": "Beatriz", "telefone": "21 95555-5555", "favorito": True, "ordem": 5},
]

ou = [c["nome"] for c in contatos if c["telefone"].startswith("21") or c["nome"] == "Davi"]
print("Q(...) | Q(...):", sorted(ou))

decrescente = sorted(contatos, key=lambda c: c["nome"], reverse=True)
print("order_by('-nome'):", [c["nome"] for c in decrescente])

recentes = sorted(contatos, key=lambda c: c["ordem"], reverse=True)[:2]
print("order_by('-criado_em')[:2]:", sorted(c["nome"] for c in recentes))

Q(...) | Q(...): ['Beatriz', 'Davi']
order_by('-nome'): ['Davi', 'Carla', 'Beatriz', 'Ana']
order_by('-criado_em')[:2]: ['Beatriz', 'Davi']

Dica: Os filtros podem ser encadeados: Contato.objects.filter(favorito=True).exclude(email="").order_by("nome"). Cada passo devolve um novo QuerySet, e o banco só é consultado uma vez, no fim.

Paginação

Com mil contatos, ninguém quer uma página gigante. O Paginator divide os resultados em páginas e diz qual é a atual, se existe próxima e quantas são no total.

Arquivo contatos/views.py:

from django.core.paginator import Paginator
from django.shortcuts import render

from .models import Contato


def lista_paginada(request):
    paginador = Paginator(Contato.objects.order_by("nome"), 2)
    pagina = paginador.get_page(request.GET.get("page"))
    return render(request, "contatos/paginada.html", {"pagina": pagina})

Arquivo contatos/templates/contatos/paginada.html:

{% for contato in pagina %}<p>{{ contato.nome }}</p>{% endfor %}
<p>Página {{ pagina.number }} de {{ pagina.paginator.num_pages }}</p>
{% if pagina.has_previous %}<a href="?page={{ pagina.previous_page_number }}">Anterior</a>{% endif %}
{% if pagina.has_next %}<a href="?page={{ pagina.next_page_number }}">Próxima</a>{% endif %}

Com a rota path("paginada/", views.lista_paginada, name="paginada") e os quatro contatos, abrir /paginada/ mostra Ana e Beatriz, "Página 1 de 2" e o link Próxima; /paginada/?page=2 mostra Carla e Davi, "Página 2 de 2" e o link Anterior.

Por dentro, uma página é só uma fatia. A página n, com t itens por página, vai do item (n - 1) * t até n * t:

import math

nomes = [f"Aluno {i}" for i in range(1, 24)]
por_pagina = 10
total_paginas = math.ceil(len(nomes) / por_pagina)
print("Páginas:", total_paginas)


def pagina(numero):
    numero = max(1, min(numero, total_paginas))
    inicio = (numero - 1) * por_pagina
    return nomes[inicio:inicio + por_pagina]


print("Página 3:", pagina(3))
print("Página 99 vira a última:", pagina(99))
print("Tem próxima depois da 2?", 2 < total_paginas)

Páginas: 3
Página 3: ['Aluno 21', 'Aluno 22', 'Aluno 23']
Página 99 vira a última: ['Aluno 21', 'Aluno 22', 'Aluno 23']
Tem próxima depois da 2? True

Dica: O get_page é tolerante como a função acima: se o número da página for inválido (?page=abc) ou grande demais (?page=50), ele devolve a primeira ou a última página em vez de dar erro. Já o paginador.page(50) levanta EmptyPage.
Pratique no DIGITAR: digite este trecho no modo Programar do app. 
Contato.objects.filter(nome__icontains="a").order_by("nome")
