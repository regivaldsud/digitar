Como a web conversa

Quando você abre um site, o navegador manda uma requisição HTTP para um servidor, e o servidor devolve uma resposta. É como pedir um lanche no balcão: você faz o pedido, e o atendente devolve o lanche (ou avisa que acabou).

Toda requisição tem um método, que diz o que você quer fazer. Os dois mais usados são GET (buscar algo) e POST (enviar dados, como um formulário).

Toda resposta traz um código de status, um número de três dígitos que diz como foi o pedido. O primeiro dígito já conta muito:

  • 2xx deu certo (200 OK, 201 criado);
  • 3xx o endereço mudou de lugar (redirecionamento);
  • 4xx o erro foi de quem pediu (404 não encontrado, 401 sem permissão);
  • 5xx o erro foi do servidor (500 erro interno).

O Python já conhece todos esses códigos no módulo http:

from http import HTTPStatus

for codigo in [200, 201, 301, 404, 500]:
    status = HTTPStatus(codigo)
    print(codigo, status.phrase)

200 OK
201 Created
301 Moved Permanently
404 Not Found
500 Internal Server Error

Uma API é um endereço feito para programas, e não para pessoas: em vez de uma página bonita, ela devolve dados, quase sempre em JSON (aula 105).

As partes de um endereço

Um endereço da web (URL) tem várias partes. Entender cada uma ajuda muito a usar APIs, porque é no endereço que você diz o que quer:

from urllib.parse import urlparse, parse_qs

url = "https://loja.exemplo.com.br/busca?produto=chinelo&tamanho=38"
partes = urlparse(url)

print("Protocolo:", partes.scheme)
print("Servidor:", partes.netloc)
print("Caminho:", partes.path)
print("Parâmetros:", parse_qs(partes.query))

Protocolo: https
Servidor: loja.exemplo.com.br
Caminho: /busca
Parâmetros: {'produto': ['chinelo'], 'tamanho': ['38']}

Os parâmetros vêm depois do ?, no formato nome=valor, separados por &. Espaços e acentos não podem ir direto no endereço: eles são trocados por códigos. O urlencode faz isso para você:

from urllib.parse import urlencode

base = "https://receitas.exemplo.com.br/busca"
parametros = {"q": "pão de queijo", "pagina": 2}

print(base + "?" + urlencode(parametros))

https://receitas.exemplo.com.br/busca?q=p%C3%A3o+de+queijo&pagina=2

Dica: Nunca monte parâmetros "na mão", juntando textos com +. Um espaço ou um & dentro do valor quebra o endereço. Use urlencode ou, com a biblioteca requests, o argumento params, que faz a mesma coisa.

Instalando a biblioteca requests

O Python traz o módulo urllib.request para fazer requisições, mas ele é chato de usar. Quase todo mundo usa a biblioteca requests, que não vem com o Python. Instale dentro do seu ambiente virtual (aula 60):

# Windows
py -m pip install requests

# Linux e macOS
python3 -m pip install requests

Os exemplos com requests precisam de internet e rodam no seu computador: copie para um arquivo .py no VS Code e rode com py arquivo.py (Windows) ou python3 arquivo.py.

Buscando dados com GET

Este exemplo consulta um CEP no ViaCEP, um serviço público brasileiro que responde em JSON:

import requests

resposta = requests.get("https://viacep.com.br/ws/01001000/json/", timeout=10)
print("Status:", resposta.status_code)

if resposta.status_code == 200:
    dados = resposta.json()          # transforma o JSON em dicionário
    print(dados["logradouro"], "-", dados["localidade"], "/", dados["uf"])
else:
    print("Algo deu errado.")

Status: 200
Praça da Sé - São Paulo / SP

  • requests.get(url) faz a requisição e devolve um objeto resposta;
  • resposta.status_code é o código de status;
  • resposta.text é o corpo da resposta como texto, e resposta.json() já transforma esse texto em dicionário.

Para APIs que recebem parâmetros, passe um dicionário em params. Aqui buscamos, na API do GitHub, os três repositórios de Python com mais estrelas:

import requests

url = "https://api.github.com/search/repositories"
parametros = {"q": "language:python", "sort": "stars", "per_page": 3}

resposta = requests.get(url, params=parametros, timeout=10)
print(resposta.url)
for repo in resposta.json()["items"]:
    print(repo["full_name"], "-", repo["stargazers_count"], "estrelas")

https://api.github.com/search/repositories?q=language%3Apython&sort=stars&per_page=3
(depois, três linhas com o nome de cada repositório e o número de estrelas, que muda todo dia)

Repare que o próprio requests montou o endereço com ?, & e o : trocado por %3A.

Lendo o JSON da resposta

A parte mais trabalhosa costuma ser achar o dado certo dentro do JSON, que muitas vezes tem dicionários dentro de listas dentro de dicionários. Dá para treinar sem internet, com uma resposta de exemplo guardada num texto — é exatamente o que o resposta.json() faria:

import json

texto = """
{
  "cidade": "Recife",
  "previsao": [
    {"dia": "segunda", "max": 31, "min": 24},
    {"dia": "terça", "max": 29, "min": 23},
    {"dia": "quarta", "max": 30, "min": 24}
  ]
}
"""

dados = json.loads(texto)
print("Previsão para", dados["cidade"])
for dia in dados["previsao"]:
    print(f"  {dia['dia']:<8} {dia['min']}°C a {dia['max']}°C")

mais_quente = max(dados["previsao"], key=lambda d: d["max"])
print("Dia mais quente:", mais_quente["dia"])

Previsão para Recife
  segunda  24°C a 31°C
  terça    23°C a 29°C
  quarta   24°C a 30°C
Dia mais quente: segunda

Dica: Quando não souber o formato de uma API, abra o endereço no navegador ou rode print(resposta.json()) uma vez para ver o que vem. Depois escreva o código que navega até o dado.

Quando algo dá errado

Na internet muita coisa pode falhar: o Wi-Fi cai, o servidor demora, o endereço está errado. Um programa bem feito trata cada caso em vez de quebrar com um erro enorme:

import requests

try:
    resposta = requests.get("https://viacep.com.br/ws/123/json/", timeout=10)
    resposta.raise_for_status()      # vira exceção se o status for 4xx ou 5xx
    print(resposta.json())
except requests.Timeout:
    print("O servidor demorou demais para responder.")
except requests.ConnectionError:
    print("Sem conexão. Confira sua internet.")
except requests.HTTPError as erro:
    print("O servidor recusou o pedido:", erro.response.status_code)

O servidor recusou o pedido: 400

O CEP 123 tem o formato errado, e o ViaCEP responde 400 (pedido inválido). O raise_for_status() transforma esse código em uma exceção HTTPError, que o except trata (aula 53).

Atenção: Sempre passe timeout. Sem ele, se o servidor não responder, seu programa pode ficar esperando para sempre. E lembre: um status 404 ou 500 não gera erro sozinho — resposta.json() pode até funcionar, mas com dados de erro. Confira o status ou use raise_for_status().

Enviando dados com POST

Para enviar dados (um cadastro, uma mensagem, uma nota), usa-se POST. Com json=, o requests transforma o dicionário em JSON e avisa o servidor que o corpo é JSON:

import requests

aluno = {"nome": "Bia", "nota": 9.5}
resposta = requests.post("http://127.0.0.1:8000/notas", json=aluno, timeout=10)
print(resposta.status_code)
print(resposta.json())

201
{'recebido': {'nome': 'Bia', 'nota': 9.5}}

Esse endereço 127.0.0.1 é o seu próprio computador. Para o exemplo funcionar, você precisa do servidor da próxima seção rodando.

Um servidor no seu computador

O Python traz um servidor web simples. Entre numa pasta com um arquivo index.html e rode:

# Windows
py -m http.server 8000

# Linux e macOS
python3 -m http.server 8000

Agora abra http://localhost:8000 no navegador: a página é servida pelo seu computador. Aperte Ctrl+C no terminal para parar. É ótimo para testar sites estáticos, como os das aulas 241 a 243.

Com o mesmo módulo dá para criar uma API de brinquedo, para entender o outro lado da conversa. Salve como servidor_api.py, rode num terminal e deixe aberto:

import json
from http.server import BaseHTTPRequestHandler, HTTPServer


class Atendente(BaseHTTPRequestHandler):
    def responder(self, status, dados):
        corpo = json.dumps(dados, ensure_ascii=False).encode("utf-8")
        self.send_response(status)
        self.send_header("Content-Type", "application/json; charset=utf-8")
        self.end_headers()
        self.wfile.write(corpo)

    def do_GET(self):
        if self.path == "/placar":
            self.responder(200, {"time": "Bahia", "gols": 2})
        else:
            self.responder(404, {"erro": "endereço não existe"})

    def do_POST(self):
        tamanho = int(self.headers["Content-Length"])
        recebido = json.loads(self.rfile.read(tamanho))
        self.responder(201, {"recebido": recebido})


servidor = HTTPServer(("127.0.0.1", 8000), Atendente)
print("Servidor em http://127.0.0.1:8000 (Ctrl+C para parar)")
servidor.serve_forever()

Servidor em http://127.0.0.1:8000 (Ctrl+C para parar)

Abra http://127.0.0.1:8000/placar no navegador e você verá o JSON. Em outro terminal, rode o exemplo do POST da seção anterior: o servidor devolve o que recebeu, com status 201. Cada pedido aparece também no terminal do servidor.

Dica: localhost e 127.0.0.1 querem dizer "este computador". Só você consegue abrir esse endereço; não é um site público. O http.server serve para estudar e testar, não para colocar um site no ar (veja a aula 220).
Pratique no DIGITAR: digite este trecho no modo Programar do app. 
resposta = requests.get(url, timeout=10)

1. Escreva uma função descrever_status(codigo) que devolve "sucesso" para códigos de 200 a 299, "redirecionamento" de 300 a 399, "erro de quem pediu" de 400 a 499 e "erro do servidor" de 500 em diante. Teste com 200, 301, 404 e 503, mostrando também o nome do código com HTTPStatus.

Ver resposta 
from http import HTTPStatus


def descrever_status(codigo):
    if 200 <= codigo <= 299:
        return "sucesso"
    if 300 <= codigo <= 399:
        return "redirecionamento"
    if 400 <= codigo <= 499:
        return "erro de quem pediu"
    return "erro do servidor"


for c in [200, 301, 404, 503]:
    print(c, HTTPStatus(c).phrase, "->", descrever_status(c))

200 OK -> sucesso
301 Moved Permanently -> redirecionamento
404 Not Found -> erro de quem pediu
503 Service Unavailable -> erro do servidor

4. Modifique o exemplo do ViaCEP para pedir um CEP ao usuário com input, avisar quando o CEP não existir e tratar falta de internet.

Ver resposta 
import requests

cep = input("CEP (só números): ").strip()
try:
    resposta = requests.get(f"https://viacep.com.br/ws/{cep}/json/", timeout=10)
    resposta.raise_for_status()
    dados = resposta.json()
    if "erro" in dados:
        print("CEP não encontrado.")
    else:
        print(dados["logradouro"], "-", dados["localidade"])
except requests.HTTPError:
    print("Formato de CEP inválido. Digite 8 números.")
except requests.RequestException:
    print("Não consegui conectar. Confira sua internet.")

Quando o CEP tem 8 números mas não existe, o ViaCEP responde 200 com {"erro": "true"}. Quando o formato está errado, responde 400. RequestException é a "mãe" de todos os erros do requests, por isso vem por último.

5. Qual é a diferença entre GET e POST? E por que o status 404 não faz o requests.get dar erro sozinho?

Ver resposta

GET serve para buscar dados; os parâmetros vão no próprio endereço, depois do ?.
POST serve para enviar dados (um cadastro, uma mensagem); os dados vão no corpo da requisição.
O 404 é uma resposta válida do servidor ("não achei"), e não uma falha de conexão.
Por isso o requests só levanta erro se você chamar resposta.raise_for_status().
