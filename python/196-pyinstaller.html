Aula para fazer no computador: o assunto desta aula precisa do seu computador. Os códigos sem o botão Executar devem ser copiados para um arquivo .py no VS Code e rodados no seu computador, como mostrado na aula 03.

Para que serve

Para usar a sua calculadora da aula 193, um amigo precisaria instalar o Python, criar um ambiente virtual e instalar o PySide6. Quase ninguém vai fazer isso.

O PyInstaller junta o seu código, o próprio Python e as bibliotecas que você usou num pacote que roda sozinho. No Windows, o resultado é um .exe: a pessoa dá dois cliques e o programa abre.

O PyInstaller não "traduz" o Python para outra linguagem. Ele empacota o interpretador junto com o seu código; por isso até um programa pequeno vira um arquivo de dezenas de megabytes.

Instalando e gerando o executável

No ambiente virtual do projeto (o mesmo em que o PySide6 está instalado):

pip install pyinstaller
pyinstaller --onefile --windowed --name Calculadora --icon icone.ico calculadora.py
  • --onefile gera um único arquivo .exe; sem ela, sai uma pasta com o .exe e vários arquivos ao lado, que abre mais rápido;
  • --windowed (ou --noconsole) não abre a janela preta do terminal junto com o programa;
  • --name escolhe o nome do executável;
  • --icon usa um ícone no formato .ico (o PyInstaller converte um .png se o pacote Pillow estiver instalado).

...
INFO: Building EXE from EXE-00.toc completed successfully.

A primeira vez demora um ou dois minutos. As próximas são mais rápidas.

Dica: Antes de empacotar, rode o programa normalmente com python calculadora.py e confira que tudo funciona. O PyInstaller não conserta erros: ele empacota o erro junto.

O que aparece nas pastas

calculadora/
├── calculadora.py
├── icone.ico
├── Calculadora.spec   <- a "receita" do empacotamento
├── build/             <- rascunhos do PyInstaller (pode apagar)
└── dist/
    └── Calculadora.exe   <- é este que você entrega

Só o conteúdo de dist vai para o seu amigo. As pastas build e dist devem ir para o .gitignore (aula 244), porque são geradas de novo a cada empacotamento.

O Calculadora.spec é um arquivo Python que guarda todas as opções que você passou. Depois da primeira vez, você pode empacotar só com pyinstaller Calculadora.spec. Um trecho dele:

# Calculadora.spec (trecho; gerado pelo PyInstaller)
a = Analysis(
    ["calculadora.py"],
    datas=[("tela.ui", ".")],
    hiddenimports=[],
)
exe = EXE(
    pyz,
    a.scripts,
    name="Calculadora",
    console=False,
    icon=["icone.ico"],
)

(este arquivo não roda sozinho: é o PyInstaller que lê as suas opções)

console=False é o mesmo que --windowed, e datas é a lista de arquivos extras, que você vai ver agora.

Arquivos extras e o sys._MEIPASS

Se o programa lê arquivos (um .ui, imagens, sons), eles precisam ir dentro do pacote. No Windows, use --add-data "origem;destino" (no Linux e no macOS o separador é :):

pyinstaller --onefile --windowed --add-data "tela.ui;." --add-data "imagens;imagens" main.py

Aqui aparece uma pegadinha. Quando o .exe --onefile abre, ele descompacta tudo numa pasta temporária com um nome como _MEI48213, e o caminho dessa pasta fica em sys._MEIPASS. Além disso, o PyInstaller cria sys.frozen = True ("congelado"). Rodando como script normal, essas duas coisas não existem:

import sys

print("Estou dentro de um executável?", getattr(sys, "frozen", False))
print("Existe sys._MEIPASS?", hasattr(sys, "_MEIPASS"))

Estou dentro de um executável? False
Existe sys._MEIPASS? False

getattr(objeto, "nome", padrao) (aula 51) lê o atributo se ele existir, e devolve o padrão se não existir, sem dar erro.

Por isso, todo programa empacotado costuma ter uma função que monta o caminho certo nos dois casos. Esta simulação roda aqui e finge as duas situações:

import sys
from pathlib import PureWindowsPath


def caminho_recurso(nome, pasta_do_script):
    if getattr(sys, "frozen", False):
        base = PureWindowsPath(sys._MEIPASS)
    else:
        base = PureWindowsPath(pasta_do_script)
    return base / nome


script = r"C:\Users\ana\calculadora"
print("Como script:   ", caminho_recurso("tela.ui", script))

# fingindo que estamos dentro do .exe:
sys.frozen = True
sys._MEIPASS = r"C:\Users\ana\AppData\Local\Temp\_MEI48213"
print("Como executável:", caminho_recurso("tela.ui", script))
del sys.frozen, sys._MEIPASS

Como script:    C:\Users\ana\calculadora\tela.ui
Como executável: C:\Users\ana\AppData\Local\Temp\_MEI48213\tela.ui

No programa de verdade, a pasta do script vem de __file__ (o caminho do próprio arquivo .py):

import sys
from pathlib import Path


def caminho_recurso(nome):
    if getattr(sys, "frozen", False):
        base = Path(sys._MEIPASS)
    else:
        base = Path(__file__).resolve().parent
    return base / nome


print(caminho_recurso("tela.ui"))

C:\Users\ana\calculadora\tela.ui

Rodando com python main.py, aparece a pasta do projeto. Dentro do .exe, aparece a pasta _MEI.... Use sempre caminho_recurso("tela.ui") no lugar de só "tela.ui".

Atenção: Um caminho como "tela.ui", sem pasta, é procurado na pasta de onde o programa foi aberto, que muda conforme o atalho. É por isso que tantos executáveis funcionam no seu computador e falham no do amigo.

Empacotando com um script Python

Em vez de decorar o comando, dá para guardar as opções num arquivo empacotar.py e chamar o PyInstaller pelo próprio Python:

import PyInstaller.__main__

PyInstaller.__main__.run([
    "calculadora.py",
    "--onefile",
    "--windowed",
    "--name=Calculadora",
    "--icon=icone.ico",
    "--add-data=tela.ui;.",
])
python empacotar.py

(mesmas mensagens INFO do comando; no fim aparece dist\Calculadora.exe)

Montar a lista de opções a partir de um dicionário ajuda a não esquecer nada. Este trecho só monta e mostra o comando, e roda aqui:

opcoes = {
    "onefile": True,
    "windowed": True,
    "name": "Calculadora",
    "icon": "icone.ico",
}

partes = ["pyinstaller"]
for chave, valor in opcoes.items():
    if valor is True:
        partes.append(f"--{chave}")
    else:
        partes.append(f"--{chave} {valor}")
partes.append("calculadora.py")
print(" ".join(partes))

pyinstaller --onefile --windowed --name Calculadora --icon icone.ico calculadora.py

Problemas comuns

  • O .exe abre e fecha na hora: gere de novo sem --windowed e rode o .exe pelo terminal; a mensagem de erro aparece lá.
  • **FileNotFoundError de um arquivo seu:** faltou --add-data ou faltou usar caminho_recurso.
  • **ModuleNotFoundError dentro do .exe:** algum módulo é importado de um jeito que o PyInstaller não percebeu; acrescente --hidden-import nome_do_modulo.
  • O antivírus reclama: executáveis novos e sem assinatura digital costumam ser desconfiados; isso não quer dizer que o seu programa tem vírus.
Atenção: O executável só roda no sistema em que foi gerado: um .exe feito no Windows não roda no Linux nem no macOS. Para cada sistema, empacote nele mesmo.
Pratique no DIGITAR: digite este trecho no modo Programar do app. 
pyinstaller --onefile --windowed calculadora.py

Exercícios

1. Qual comando gera um executável chamado Contador.exe, sem janela de terminal, a partir de contador.py?

Ver resposta 
pyinstaller --onefile --windowed --name Contador contador.py

2. Rodei o .exe e ele abre e fecha na hora, sem mostrar nada. Como descobrir o erro?

Ver resposta

Gere de novo SEM a opção --windowed e rode o .exe pelo terminal (cmd).
Assim a mensagem de erro (o traceback) aparece no terminal. Um erro comum
é um arquivo extra (como tela.ui) que não foi incluído com --add-data.

3. O programa usa a pasta sons com vários .wav. Escreva o comando que leva a pasta inteira para dentro do executável, no Windows e no Linux.

Ver resposta 
pyinstaller --onefile --windowed --add-data "sons;sons" jogo.py
pyinstaller --onefile --windowed --add-data "sons:sons" jogo.py

A primeira linha é para o Windows (separador ;) e a segunda para Linux e macOS (separador :). No código, abra os arquivos com caminho_recurso("sons/ponto.wav").

4. Usando a simulação da aula, escreva caminho_recurso e mostre o caminho de imagens/logo.png como script (pasta C:\jogo) e como executável (sys._MEIPASS igual a C:\Temp\_MEI777).

Ver resposta

def caminho_recurso(nome, pasta_do_script):

O PureWindowsPath troca a barra / pela barra invertida do Windows sozinho.

5. Qual é a diferença entre gerar com --onefile e sem ela? Quando cada uma é melhor?

Ver resposta

Com --onefile sai um único .exe: é fácil de mandar para alguém, mas demora um
pouco mais para abrir, porque descompacta tudo numa pasta temporária a cada vez.
Sem --onefile sai uma pasta (dist\Calculadora) com o .exe e vários arquivos:
abre mais rápido, mas você precisa entregar a pasta inteira (por exemplo,
compactada num .zip ou dentro de um instalador).
