Aula para fazer no computador: o assunto desta aula precisa do seu computador. Os códigos sem o botão Executar devem ser copiados para um arquivo .py no VS Code e rodados no seu computador, como mostrado na aula 03.

Bibliotecas de outras pessoas

A biblioteca padrão do Python já é enorme, mas a comunidade criou centenas de milhares de pacotes extras: para fazer jogos (pygame), acessar sites (requests), fazer gráficos (matplotlib) e muito mais. Eles ficam no PyPI (pypi.org), a "loja de aplicativos" gratuita do Python.

Quem instala esses pacotes é o pip, um programa que vem junto com o Python. Esta aula é feita no terminal do seu computador: abra o terminal do VS Code com Ctrl+', dentro da pasta do seu projeto (aula 03).

Por que um ambiente virtual?

Imagine que o projeto A precisa da versão 1 de um pacote e o projeto B precisa da versão 2. Se tudo for instalado no mesmo lugar, um projeto quebra o outro. Um ambiente virtual (venv) é uma pasta com um Python só daquele projeto: o que você instala ali não afeta mais nada.

cd curso-python
python -m venv .venv

Isso cria a pasta .venv. O nome com ponto é um costume que muitos editores reconhecem.

Ativando o ambiente

No Prompt de Comando (cmd):

.venv\Scripts\activate

No PowerShell (o terminal padrão do VS Code):

.venv\Scripts\Activate.ps1

No Linux e no macOS:

source .venv/bin/activate

Quando der certo, o nome do ambiente aparece entre parênteses no começo da linha:

(.venv) C:\Users\Ana\Documents\curso-python>

Para sair do ambiente, digite deactivate.

Atenção: Se o PowerShell disser que "a execução de scripts foi desabilitada neste sistema", rode uma vez Set-ExecutionPolicy -Scope CurrentUser RemoteSigned, confirme com S e tente ativar de novo. Isso libera scripts só para o seu usuário. Se preferir, use o Prompt de Comando.
Dica: O VS Code percebe a pasta .venv e pergunta se quer usá-la. Aceite! Para escolher manualmente, aperte Ctrl+Shift+P e procure Python: Select Interpreter.

Este pequeno programa diz se está rodando num ambiente virtual. Salve como onde_estou.py e rode com e sem o venv ativado:

import sys

if sys.prefix != sys.base_prefix:
    print("Estou num ambiente virtual:", sys.prefix)
else:
    print("Estou no Python principal do computador")

Estou num ambiente virtual: C:\Users\Ana\Documents\curso-python\.venv

Instalando pacotes com pip

Com o ambiente ativado:

pip install requests
pip list
pip show requests
pip uninstall requests
  • pip install nome baixa e instala (e pip install nome==2.32.5 instala uma versão exata);
  • pip list mostra o que está instalado;
  • pip show nome mostra detalhes de um pacote;
  • pip uninstall nome remove.

Depois de instalar, use normalmente com import. Este programa precisa da internet, então rode no seu computador:

import requests

resposta = requests.get("https://api.github.com")
print(resposta.status_code)

200

Para saber pelo Python qual versão de um pacote está instalada, use importlib.metadata:

from importlib.metadata import version

print("pip versão", version("pip"))

pip versão 24.2

Atenção: Se aparecer ModuleNotFoundError: No module named 'requests' mesmo depois de instalar, provavelmente você instalou num Python e está rodando em outro. Ative o venv antes de rodar e confira no VS Code (canto inferior direito) se o interpretador escolhido é o da .venv. Usar python -m pip install ... garante que o pip é o do mesmo Python.

requirements.txt

Para que outra pessoa (ou você em outro computador) instale os mesmos pacotes, guarde a lista num arquivo:

pip freeze > requirements.txt

O arquivo fica assim, um pacote por linha com a versão:

certifi==2025.8.3
charset-normalizer==3.4.3
idna==3.10
requests==2.32.5
urllib3==2.5.0

Em outro computador, depois de criar e ativar um venv novo:

pip install -r requirements.txt

Como o requirements.txt é só texto, dá para lê-lo com Python, como qualquer arquivo (aula 61):

with open("requirements.txt", "w", encoding="utf-8") as f:
    f.write("requests==2.32.5\nidna==3.10\n")

with open("requirements.txt", encoding="utf-8") as f:
    for linha in f:
        nome, versao = linha.strip().split("==")
        print(f"{nome}: versão {versao}")

requests: versão 2.32.5
idna: versão 3.10

Dica: Não envie a pasta .venv para o GitHub nem para os amigos: ela é grande e só funciona no seu computador. Envie o requirements.txt — com ele, qualquer um recria o ambiente. Na aula 05 você conhece o uv e o pyproject.toml, um jeito mais moderno de fazer tudo isso.
Pratique no DIGITAR: digite este trecho no modo Programar do app. 
python -m venv .venv

3. Qual comando salva a lista de pacotes do projeto num arquivo, e qual comando instala tudo a partir dele em outro computador?

pip install -r requirements.txt

4. Ao ativar o venv no PowerShell, apareceu um erro dizendo que a execução de scripts está desabilitada. O que fazer?

Ver resposta

Rodar uma vez: Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
(e confirmar com S). Outra opção é usar o Prompt de Comando (cmd)
e ativar com .venv\Scripts\activate

Ver resposta

Porque ela é grande e só funciona no computador onde foi criada. O certo é
