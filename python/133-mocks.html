Aula 133 · Isolando dependências com unittest.mock

Nesta aula você vai aprender

  • Por que algumas funções são difíceis de testar
  • Criar objetos falsos com Mock e return_value
  • Substituir uma função temporariamente com patch
  • Conferir como um mock foi chamado

O problema: resultados que mudam

Como testar uma função que sorteia um dado? Cada vez que você roda, sai um número diferente. E uma função que manda uma mensagem pela internet? No teste você não quer mandar mensagem de verdade.

A solução é trocar essa parte imprevisível (a dependência) por um dublê que você controla. Esse dublê se chama mock (imitação, em inglês). O módulo unittest.mock já vem com o Python.

Mock: um objeto que aceita tudo

Um Mock aceita qualquer chamada e você escolhe o que ele devolve com return_value. Ele também anota como foi chamado:

from unittest.mock import Mock

enviar = Mock(return_value=True)

resultado = enviar("Oi, vó!", para="Vó Maria")
print(resultado)
print(enviar.call_count)
enviar.assert_called_once_with("Oi, vó!", para="Vó Maria")
print("Foi chamado do jeito certo")

True
1
Foi chamado do jeito certo

Se a chamada fosse diferente, assert_called_once_with daria AssertionError.

patch: troca temporária

O patch substitui uma função por um mock só durante o teste e depois devolve a original. Veja um jogo em que o jogador ganha se tirar 6 no dado:

import random
import unittest
from unittest.mock import patch


def jogar_dado():
    numero = random.randint(1, 6)
    if numero == 6:
        return "Você ganhou!"
    return f"Tirou {numero}. Tente de novo."


class TestDado(unittest.TestCase):
    @patch("random.randint", return_value=6)
    def test_ganha_com_seis(self, falso_randint):
        self.assertEqual(jogar_dado(), "Você ganhou!")
        falso_randint.assert_called_once_with(1, 6)

    @patch("random.randint", return_value=2)
    def test_perde_com_dois(self, falso_randint):
        self.assertEqual(jogar_dado(), "Tirou 2. Tente de novo.")


unittest.main(argv=[""], exit=False)

O @patch (um decorador, como na aula 56) entrega o mock como parâmetro extra do teste. Dentro do teste, random.randint devolve o número que escolhemos.

Atenção: O texto do patch é o caminho de onde a função é usada. Se o seu código faz from random import randint dentro do arquivo jogo.py, o patch é patch("jogo.randint"), e não patch("random.randint").

patch como bloco with

Também dá para usar o patch num bloco with, só em parte do código. Use side_effect para devolver um valor diferente em cada chamada:

import random
from unittest.mock import patch


def sortear_time(nomes):
    return [random.choice(nomes) for _ in range(2)]


with patch("random.choice", side_effect=["Bia", "Caio"]):
    print(sortear_time(["Ana", "Bia", "Caio"]))

print("Fora do with, o random volta ao normal.")

['Bia', 'Caio']
Fora do with, o random volta ao normal.

Dica: Use mocks só para o que é imprevisível ou lento (sorteio, data, internet, banco de dados). Se você mockar tudo, o teste deixa de testar o seu código de verdade.
Pratique no DIGITAR: digite este trecho no modo Programar do app. 
@patch("random.randint", return_value=6)

2. A função moeda() devolve "cara" se random.random() for menor que 0.5 e "coroa" caso contrário. Teste os dois casos com patch.

Ver resposta 
import random
import unittest
from unittest.mock import patch


def moeda():
    return "cara" if random.random() < 0.5 else "coroa"


class TestMoeda(unittest.TestCase):
    @patch("random.random", return_value=0.1)
    def test_cara(self, _):
        self.assertEqual(moeda(), "cara")

    @patch("random.random", return_value=0.9)
    def test_coroa(self, _):
        self.assertEqual(moeda(), "coroa")


unittest.main(argv=[""], exit=False)

3. Use side_effect para fazer um mock devolver 1, depois 2, depois 3, e mostre as três chamadas.

Ver resposta 
from unittest.mock import Mock

contador = Mock(side_effect=[1, 2, 3])
print(contador(), contador(), contador())
