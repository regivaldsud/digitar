Aula 74 · Encapsulamento: público, _protegido, __privado

Nesta aula você vai aprender

  • O que é encapsulamento e por que proteger os dados de um objeto
  • As três "visibilidades" do Python: público, _protegido e __privado
  • Como funciona o *name mangling*
  • Montar uma interface pública com métodos e properties

Por que proteger os dados

Imagine uma classe ContaBancaria em que qualquer parte do programa pode fazer conta.saldo = -1000000. Nada impede! Encapsular é esconder os detalhes internos do objeto e deixar que os dados mudem só pelos métodos certos, que conferem se a mudança faz sentido.

class Termometro:
    def __init__(self, celsius):
        self.celsius = celsius

t = Termometro(25)
t.celsius = -500
print(t.celsius, "graus? Mais frio que o zero absoluto!")

-500 graus? Mais frio que o zero absoluto!

Pense num controle remoto: você aperta botões (a parte pública), mas não mexe nos circuitos lá dentro (a parte interna).

Público: o jeito normal

Em Python, todo atributo sem sublinhado é público: qualquer um pode ler e mudar. Isso é o normal e está tudo bem para dados simples, como o nome de um aluno.

class Aluno:
    def __init__(self, nome):
        self.nome = nome

a = Aluno("Rafa")
a.nome = "Rafaela"
print(a.nome)

Rafaela

_protegido: um aviso entre programadores

Um atributo que começa com um sublinhado (_saldo) quer dizer: "isto é interno, não mexa de fora". O Python não proíbe; é um combinado entre programadores, e editores como o VS Code às vezes avisam.

class ContaBancaria:
    def __init__(self, titular):
        self.titular = titular
        self._saldo = 0

    def depositar(self, valor):
        if valor <= 0:
            print("Depósito inválido.")
            return
        self._saldo += valor

    def ver_saldo(self):
        return self._saldo

c = ContaBancaria("Joana")
c.depositar(200)
c.depositar(-50)
print(c.ver_saldo())

Depósito inválido.
200

Métodos também podem ser protegidos, como um _calcular_juros() que só a própria classe deve chamar.

__privado: o name mangling

Com dois sublinhados no começo (__senha), o Python troca o nome por dentro para _Classe__senha. Isso se chama *name mangling* ("embaralhar o nome") e evita acessos de fora sem querer.

class Cofre:
    def __init__(self, senha):
        self.__senha = senha

    def abrir(self, tentativa):
        return "Aberto!" if tentativa == self.__senha else "Senha errada."

cofre = Cofre("1234")
print(cofre.abrir("0000"))
print(cofre.abrir("1234"))
print(cofre.__senha)

Senha errada.
Aberto!
AttributeError: 'Cofre' object has no attribute '__senha'

O atributo continua lá, só que com outro nome:

class Cofre:
    def __init__(self, senha):
        self.__senha = senha

cofre = Cofre("1234")
print(vars(cofre))
print(cofre._Cofre__senha)

{'_Cofre__senha': '1234'}
1234

Atenção: O __privado não é segredo de verdade: dá para acessar com _Cofre__senha. Nunca guarde senhas reais assim. Na prática, a maioria dos programadores Python usa só um sublinhado e reserva os dois para evitar conflito de nomes com classes filhas.

Interface pública com property

Juntando tudo: o dado fica protegido e o mundo de fora usa métodos e properties. O saldo pode ser lido como atributo, mas só muda por depósito e saque.

class Conta:
    def __init__(self, titular):
        self.titular = titular
        self._saldo = 0.0
        self._extrato = []

    @property
    def saldo(self):
        return self._saldo

    def depositar(self, valor):
        self._mover(valor, "depósito")

    def sacar(self, valor):
        if valor > self._saldo:
            print(f"Saque de R$ {valor:.2f} negado.")
            return
        self._mover(-valor, "saque")

    def _mover(self, valor, tipo):
        self._saldo += valor
        self._extrato.append(f"{tipo}: {valor:+.2f}")

c = Conta("Paulo")
c.depositar(100)
c.sacar(30)
c.sacar(500)
print("Saldo:", c.saldo)
print(c._extrato)

Saque de R$ 500.00 negado.
Saldo: 70.0
['depósito: +100.00', 'saque: -30.00']

Dica: Pergunte-se: "o que quem usa minha classe precisa ver?". Isso é público. O resto — como os detalhes de _mover — fica com sublinhado.
Pratique no DIGITAR: digite este trecho no modo Programar do app. 
self._saldo = 0

Exercícios

1. Crie a classe Placar com o atributo protegido _pontos, o método marcar() (soma 1) e um property pontos sem setter. Mostre que placar.pontos = 100 dá erro.

Ver resposta 
class Placar:
    def __init__(self):
        self._pontos = 0

    def marcar(self):
        self._pontos += 1

    @property
    def pontos(self):
        return self._pontos

placar = Placar()
placar.marcar()
placar.marcar()
print(placar.pontos)
try:
    placar.pontos = 100
except AttributeError:
    print("Não dá para mudar os pontos direto!")

2
Não dá para mudar os pontos direto!

2. Qual é a diferença entre self._saldo e self.__saldo?

Ver resposta

_saldo (um sublinhado): só um aviso de "uso interno"; o Python não muda nada.
__saldo (dois sublinhados): o Python troca o nome para _Classe__saldo (name mangling),
então conta.__saldo de fora da classe dá AttributeError.
Nenhum dos dois é proteção real; são formas de avisar e evitar acessos sem querer.

3. Crie a classe Estoque com um dicionário protegido _itens, os métodos entrar(produto, qtd) e sair(produto, qtd) (que recusa sair mais do que tem) e quantidade(produto).

Ver resposta 
class Estoque:
    def __init__(self):
        self._itens = {}

    def entrar(self, produto, qtd):
        self._itens[produto] = self._itens.get(produto, 0) + qtd

    def sair(self, produto, qtd):
        if qtd > self.quantidade(produto):
            print(f"Não há {qtd} de {produto}.")
            return
        self._itens[produto] -= qtd

    def quantidade(self, produto):
        return self._itens.get(produto, 0)

e = Estoque()
e.entrar("arroz", 10)
e.sair("arroz", 3)
e.sair("arroz", 50)
print("arroz:", e.quantidade("arroz"))
print("feijão:", e.quantidade("feijão"))

Não há 50 de arroz.
arroz: 7
feijão: 0

4. Crie a classe Celular com o atributo privado __pin e o método desbloquear(tentativa), que bloqueia o celular depois de 3 tentativas erradas.

Ver resposta 
class Celular:
    def __init__(self, pin):
        self.__pin = pin
        self._erros = 0

    def desbloquear(self, tentativa):
        if self._erros >= 3:
            return "Bloqueado!"
        if tentativa == self.__pin:
            self._erros = 0
            return "Desbloqueado"
        self._erros += 1
        return "PIN errado"

cel = Celular("2580")
for t in ["1111", "0000", "1234", "2580"]:
    print(t, "->", cel.desbloquear(t))

1111 -> PIN errado
0000 -> PIN errado
1234 -> PIN errado
2580 -> Bloqueado!

Na quarta tentativa o PIN estava certo, mas o celular já tinha sido bloqueado pelas três tentativas erradas.
