Aula 44 · Parâmetros só posicionais (/) e só nomeados (*); o perigo do padrão mutável

Nesta aula você vai aprender

  • O que significa a barra / na lista de parâmetros
  • O que significa o asterisco * sozinho na lista de parâmetros
  • Como ler assinaturas como len(obj, /) na documentação
  • Por que nunca usar uma lista ou dicionário como valor padrão

Por que limitar o jeito de chamar?

Na aula 41 você viu que todo parâmetro pode ser passado pela posição ou pelo nome. Às vezes, quem escreve a função quer escolher: "este aqui só pela posição" ou "este só pelo nome". O Python tem dois símbolos para isso: a barra / e o asterisco *.

Só nomeados: o asterisco sozinho

Tudo o que vem depois de um * sozinho só pode ser passado pelo nome. Isso evita trocas perigosas, como confundir quem recebe uma transferência:

def transferir(valor, *, para, agendar=False):
    quando = "agendada" if agendar else "agora"
    print(f"Transferindo R$ {valor:.2f} para {para} ({quando})")

transferir(100, para="Ana")
transferir(50, para="Caio", agendar=True)

Transferindo R$ 100.00 para Ana (agora)
Transferindo R$ 50.00 para Caio (agendada)

def transferir(valor, *, para, agendar=False):
    print(valor, para, agendar)

transferir(100, "Ana")

TypeError: transferir() takes 1 positional argument but 2 were given

O erro diz que a função aceita só 1 argumento posicional. Com o *, quem lê transferir(100, para="Ana") não tem dúvida do que é cada valor.

Dica: Você já usou parâmetros só nomeados: em sorted(lista, key=len, reverse=True), o key e o reverse só funcionam com nome.

Só posicionais: a barra

Tudo o que vem antes de uma / só pode ser passado pela posição. É útil quando o nome do parâmetro não importa para quem chama, e assim você pode trocá-lo no futuro sem quebrar o código de ninguém:

def area(base, altura, /):
    return base * altura

print(area(3, 4))

12

def area(base, altura, /):
    return base * altura

print(area(base=3, altura=4))

TypeError: area() got some positional-only arguments passed as keyword arguments: 'base, altura'

Muitas funções prontas do Python são assim. A documentação de len mostra len(obj, /), ou seja, você não pode escrever len(obj="casa"):

print(len("casa"))
print(len(obj="casa"))

4
TypeError: len() takes no keyword arguments

Juntando tudo

Os dois símbolos podem aparecer na mesma função. A ordem é: só posicionais, /, normais, *, só nomeados:

def matricular(nome, /, turma, *, bolsista=False):
    print(nome, "-", turma, "- bolsista:", bolsista)

matricular("Ana", "8B")
matricular("Caio", turma="9A", bolsista=True)

Ana - 8B - bolsista: False
Caio - 9A - bolsista: True

Aqui nome só vai pela posição, turma vai de qualquer jeito e bolsista só pelo nome.

O perigo do padrão mutável

Agora uma armadilha famosa. Esta função deveria criar uma lista de compras nova a cada chamada:

def adicionar(item, lista=[]):
    lista.append(item)
    return lista

print(adicionar("arroz"))
print(adicionar("feijão"))

['arroz']
['arroz', 'feijão']

Surpresa: o "arroz" apareceu na segunda lista! O valor padrão é criado uma vez só, quando o def roda, e a mesma lista é reaproveitada em todas as chamadas. A solução é usar None como padrão e criar a lista dentro da função:

def adicionar(item, lista=None):
    if lista is None:
        lista = []
    lista.append(item)
    return lista

print(adicionar("arroz"))
print(adicionar("feijão"))

['arroz']
['feijão']

Atenção: Nunca use lista [], dicionário {} ou conjunto como valor padrão. Use None e crie o objeto dentro da função. Números, textos, tuplas, True/False e None podem ser padrão sem medo, porque não mudam.
Pratique no DIGITAR: digite este trecho no modo Programar do app. 
def transferir(valor, *, para, agendar=False):

Exercícios

1. Crie a função enviar_mensagem(texto, *, para) que mostre Para Bia: Oi!. Mostre uma chamada que funciona e explique por que enviar_mensagem("Oi!", "Bia") não funciona.

Ver resposta 
def enviar_mensagem(texto, *, para):
    print(f"Para {para}: {texto}")

enviar_mensagem("Oi!", para="Bia")

Para Bia: Oi!

Com o *, o para só pode ser passado pelo nome. A chamada enviar_mensagem("Oi!", "Bia") dá TypeError porque tenta passar dois argumentos pela posição.

2. Crie a função potencia(base, expoente, /) que só aceite argumentos posicionais e devolva a base elevada ao expoente. Mostre potencia(2, 8).

Ver resposta 
def potencia(base, expoente, /):
    return base ** expoente

print(potencia(2, 8))

256

3. Na função def f(a, /, b, *, c), quais destas chamadas funcionam: f(1, 2, c=3), f(1, b=2, c=3), f(a=1, b=2, c=3) e f(1, 2, 3)? Teste.

Ver resposta 
def f(a, /, b, *, c):
    return a + b + c

print(f(1, 2, c=3))
print(f(1, b=2, c=3))
for chamada in ["f(a=1, b=2, c=3)", "f(1, 2, 3)"]:
    try:
        eval(chamada)
    except TypeError:
        print(chamada, "-> TypeError")

6
6
f(a=1, b=2, c=3) -> TypeError
f(1, 2, 3) -> TypeError

As duas primeiras funcionam. f(a=1, ...) falha porque a só aceita posição, e f(1, 2, 3) falha porque c só aceita nome. (O eval roda um texto como código; usamos aqui só para testar as chamadas que dão erro.)

4. Esta função tem a armadilha do padrão mutável. Corrija: def registrar(nota, notas=[]): notas.append(nota); return notas.

Ver resposta 
def registrar(nota, notas=None):
    if notas is None:
        notas = []
    notas.append(nota)
    return notas

print(registrar(8))
print(registrar(10))

[8]
[10]

Com None como padrão, cada chamada sem a lista começa com uma lista vazia nova.
