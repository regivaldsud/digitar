Uma interface, muitas formas

Polimorfismo (do grego: "muitas formas") é quando o mesmo comando funciona com objetos de tipos diferentes, e cada um responde do seu jeito. Você já usa isso: len("casa"), len([1, 2]) e len({"a": 1}) funcionam com tipos bem diferentes.

class Pix:
    def pagar(self, valor):
        return f"Pix de R$ {valor:.2f} enviado"

class Cartao:
    def __init__(self, parcelas):
        self.parcelas = parcelas

    def pagar(self, valor):
        return f"{self.parcelas}x de R$ {valor / self.parcelas:.2f} no cartão"

class Dinheiro:
    def pagar(self, valor):
        return f"R$ {valor:.2f} em dinheiro, troco no caixa"

def finalizar_compra(forma, valor):
    print("Compra finalizada:", forma.pagar(valor))

for forma in [Pix(), Cartao(3), Dinheiro()]:
    finalizar_compra(forma, 150)

Compra finalizada: Pix de R$ 150.00 enviado
Compra finalizada: 3x de R$ 50.00 no cartão
Compra finalizada: R$ 150.00 em dinheiro, troco no caixa

A função finalizar_compra não sabe nem quer saber qual é a forma de pagamento. Ela só confia que o objeto tem o método pagar. Para criar uma forma nova, é só fazer outra classe — sem mexer na função.

Duck typing

Repare que Pix, Cartao e Dinheiro nem herdam da mesma classe! Em Python vale o ditado: "se anda como pato e grasna como pato, então é um pato". Isso se chama *duck typing* (tipagem do pato): o que importa é o objeto ter os métodos certos, não a classe dele.

class Pato:
    def falar(self):
        return "quack"

class Robo:
    def falar(self):
        return "bip bop"

class Papagaio:
    def falar(self):
        return "curupaco!"

for coisa in [Pato(), Robo(), Papagaio()]:
    print(coisa.falar())

quack
bip bop
curupaco!

Dica: Quando quiser garantir que todas as classes tenham o método, junte polimorfismo com classe abstrata (aula 78): o Python avisa na hora se alguma esquecer.

Polimorfismo com herança

Com herança, a mãe define a interface e cada filha sobrescreve do seu jeito. O código que usa os objetos trata todos igual:

class Funcionario:
    def __init__(self, nome, base):
        self.nome = nome
        self.base = base

    def salario(self):
        return self.base

class Vendedor(Funcionario):
    def __init__(self, nome, base, vendas):
        super().__init__(nome, base)
        self.vendas = vendas

    def salario(self):
        return self.base + self.vendas * 0.05

class Estagiario(Funcionario):
    def salario(self):
        return self.base * 0.6

equipe = [Funcionario("Lúcia", 3000), Vendedor("Caio", 2000, 40000), Estagiario("Nina", 2500)]
for f in equipe:
    print(f"{f.nome}: R$ {f.salario():.2f}")
print(f"Folha total: R$ {sum(f.salario() for f in equipe):.2f}")

Lúcia: R$ 3000.00
Caio: R$ 4000.00
Nina: R$ 1500.00
Folha total: R$ 8500.00

O princípio de Liskov

A cientista da computação Barbara Liskov propôs uma regra para herança, que ficou conhecida como princípio da substituição de Liskov: um objeto da classe filha deve poder substituir um da classe mãe sem quebrar o programa. Em outras palavras, a filha pode fazer mais, mas não pode desrespeitar o que a mãe promete.

Veja uma herança que quebra a regra: toda Ave promete voar, mas pinguim não voa.

class Ave:
    def voar(self):
        return "voando alto"

class Pinguim(Ave):
    def voar(self):
        raise NotImplementedError("pinguim não voa!")

def passeio(aves):
    for ave in aves:
        try:
            print(type(ave).__name__, ave.voar())
        except NotImplementedError as e:
            print(type(ave).__name__, "-> ERRO:", e)

passeio([Ave(), Pinguim()])

Ave voando alto
Pinguim -> ERRO: pinguim não voa!

A função passeio foi escrita para aves e quebrou com um pinguim. O problema não é a função: é a herança, que prometeu algo que a filha não cumpre.

Consertando a hierarquia

A solução é organizar as classes para que cada promessa seja verdadeira: toda ave se move, mas só as voadoras voam.

class Ave:
    def __init__(self, nome):
        self.nome = nome

    def mover(self):
        return "anda"

class AveVoadora(Ave):
    def mover(self):
        return "voa"

    def voar(self):
        return "voando alto"

class Pinguim(Ave):
    def mover(self):
        return "nada"

for ave in [AveVoadora("Bem-te-vi"), Pinguim("Pingu"), Ave("Ema")]:
    print(ave.nome, ave.mover())

Bem-te-vi voa
Pingu nada
Ema anda

Agora qualquer ave pode entrar no lugar de outra quando o assunto é mover(), e só quem é AveVoadora promete voar().

Atenção: Sinais de que a herança fere o princípio de Liskov: a filha sobrescreve um método só para dar erro, ignora parâmetros que a mãe usa, ou devolve um tipo diferente do da mãe (a mãe devolve número e a filha devolve texto).
Pratique no DIGITAR: digite este trecho no modo Programar do app. 
for forma in formas: print(forma.area())

class Email:

2. Usando polimorfismo, calcule a área total de uma lista com um Retangulo(4, 5), um Triangulo(6, 3) (base e altura) e um Quadrado(2).

Ver resposta 
class Retangulo:
    def __init__(self, b, h):
        self.b = b
        self.h = h

    def area(self):
        return self.b * self.h

class Triangulo:
    def __init__(self, b, h):
        self.b = b
        self.h = h

    def area(self):
        return self.b * self.h / 2

class Quadrado:
    def __init__(self, lado):
        self.lado = lado

    def area(self):
        return self.lado ** 2

formas = [Retangulo(4, 5), Triangulo(6, 3), Quadrado(2)]
for forma in formas:
    print(type(forma).__name__, forma.area())
print("Total:", sum(f.area() for f in formas))

Retangulo 20
Triangulo 9.0
Quadrado 4
Total: 33.0

3. A classe Arquivo tem ler() e escrever(texto). Alguém criou ArquivoSomenteLeitura(Arquivo) em que escrever dá erro. Isso respeita o princípio de Liskov? Como reorganizar?

Ver resposta

Não respeita: quem recebe um Arquivo espera poder escrever, e a filha quebra essa promessa.
Uma saída é ter uma classe mãe ArquivoLeitura (só com ler) e uma filha ArquivoEditavel
(com ler e escrever). Assim cada classe só promete o que consegue cumprir.

4. Faça a função descrever(x) que funciona com qualquer objeto que tenha o método resumo(). Teste com uma classe Livro e uma classe Filme, sem herança entre elas.

Ver resposta 
class Livro:
    def __init__(self, titulo, paginas):
        self.titulo = titulo
        self.paginas = paginas

    def resumo(self):
        return f"livro {self.titulo}, {self.paginas} páginas"

class Filme:
    def __init__(self, titulo, minutos):
        self.titulo = titulo
        self.minutos = minutos

    def resumo(self):
        return f"filme {self.titulo}, {self.minutos} min"

def descrever(x):
    print("Recomendação:", x.resumo())

descrever(Livro("O Pequeno Príncipe", 96))
descrever(Filme("Divertida Mente", 95))

Recomendação: livro O Pequeno Príncipe, 96 páginas
Recomendação: filme Divertida Mente, 95 min
