O que é SOLID

SOLID é um conjunto de cinco conselhos para escrever classes que não viram um "monstro" difícil de mexer. Não são leis: são ideias que ajudam quando o programa cresce.

  • S — Responsabilidade única: cada classe cuida de uma coisa só.
  • O — Aberto/fechado: dá para acrescentar comportamento novo sem reescrever o que já funciona.
  • L — Substituição de Liskov: uma classe filha deve funcionar em qualquer lugar onde a mãe funciona (aula 79).
  • I — Segregação de interfaces: é melhor ter várias interfaces pequenas do que uma enorme.
  • D — Inversão de dependência: dependa de abstrações, não de detalhes.

S: uma responsabilidade por classe

Imagine uma classe de boletim que calcula a média e imprime e salva em arquivo. Qualquer mudança no formato da impressão mexe na mesma classe do cálculo. Separando, cada parte muda sozinha:

class Boletim:
    def __init__(self, aluno, notas):
        self.aluno = aluno
        self.notas = notas

    def media(self):
        return sum(self.notas) / len(self.notas)


class ImpressoraDeBoletim:
    def imprimir(self, boletim):
        print(f"{boletim.aluno}: média {boletim.media():.1f}")


b = Boletim("Marina", [8, 7.5, 9])
ImpressoraDeBoletim().imprimir(b)

Marina: média 8.2

O e D: aberto para extensão, dependendo de abstrações

Aqui a loja calcula o frete sem saber qual transportadora é usada. Para criar uma transportadora nova, basta uma classe nova; a Loja não muda:

from abc import ABC, abstractmethod


class Frete(ABC):
    @abstractmethod
    def calcular(self, peso_kg):
        ...


class Correios(Frete):
    def calcular(self, peso_kg):
        return 15 + 2 * peso_kg


class Motoboy(Frete):
    def calcular(self, peso_kg):
        return 12.0


class Loja:
    def __init__(self, frete: Frete):
        self.frete = frete

    def total(self, preco, peso_kg):
        return preco + self.frete.calcular(peso_kg)


print(Loja(Correios()).total(100, 3))
print(Loja(Motoboy()).total(100, 3))

121
112.0

Dica: Não tente aplicar SOLID em programas de 20 linhas. Use quando perceber que uma mudança pequena obriga a mexer em muitos lugares.

I: interfaces pequenas

Se uma impressora simples for obrigada a ter os métodos digitalizar e enviar_fax só porque uma classe-mãe enorme pede, algo está errado. Em Python, prefira classes-mãe pequenas e combine as que precisar:

class Imprime:
    def imprimir(self, texto):
        print("Imprimindo:", texto)


class Digitaliza:
    def digitalizar(self):
        return "imagem.png"


class ImpressoraSimples(Imprime):
    pass


class Multifuncional(Imprime, Digitaliza):
    pass


ImpressoraSimples().imprimir("trabalho de história")
print(Multifuncional().digitalizar())

Imprimindo: trabalho de história
imagem.png

Pratique no DIGITAR: digite este trecho no modo Programar do app. 
class Loja:  # depende de Frete, não de Correios

Exercícios

1. Crie uma nova classe de frete RetirarNaLoja, que sempre custa 0, e use com a Loja do exemplo sem mudar a classe Loja. Qual princípio você aplicou?

Ver resposta 
class Frete:
    def calcular(self, peso_kg):
        raise NotImplementedError


class RetirarNaLoja(Frete):
    def calcular(self, peso_kg):
        return 0


class Loja:
    def __init__(self, frete):
        self.frete = frete

    def total(self, preco, peso_kg):
        return preco + self.frete.calcular(peso_kg)


print(Loja(RetirarNaLoja()).total(100, 3))

100

O princípio aberto/fechado (O): você estendeu o comportamento sem modificar a Loja.
