O caminho de um pedido em produção

O runserver é só para desenvolvimento: lento e sem segurança. Num servidor de verdade (uma máquina Linux alugada, como uma VPS), o caminho fica assim:

Navegador --HTTPS--> Nginx --> Gunicorn --> Django --> PostgreSQL
                       |
                       +--> arquivos estáticos e de mídia

  • Nginx recebe os pedidos da internet, cuida do HTTPS e entrega CSS e imagens direto;
  • Gunicorn roda o Django com vários processos;
  • PostgreSQL é o banco de dados, mais robusto que o SQLite para muitos usuários.

O settings.py de produção

import os
from pathlib import Path

BASE_DIR = Path(__file__).resolve().parent.parent
DEBUG = False
SECRET_KEY = os.environ["DJANGO_SECRET_KEY"]
ALLOWED_HOSTS = ["meusite.com.br", "www.meusite.com.br"]
CSRF_TRUSTED_ORIGINS = ["https://meusite.com.br", "https://www.meusite.com.br"]
STATIC_ROOT = BASE_DIR / "staticfiles"
SECURE_PROXY_SSL_HEADER = ("HTTP_X_FORWARDED_PROTO", "https")
SESSION_COOKIE_SECURE = True
CSRF_COOKIE_SECURE = True
Atenção: Nunca publique com DEBUG = True: as páginas de erro mostram partes do seu código e das configurações para qualquer pessoa. E a SECRET_KEY vem de uma variável de ambiente (aula 177), nunca escrita no código que vai para o GitHub.

Antes de publicar, rode python manage.py check --deploy: ele lista as configurações de segurança que faltam.

No servidor (Ubuntu)

sudo apt update
sudo apt install python3-venv postgresql nginx certbot python3-certbot-nginx
git clone https://github.com/seu-usuario/agenda.git
cd agenda
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt gunicorn
python manage.py migrate
python manage.py collectstatic
gunicorn config.wsgi:application --bind 127.0.0.1:8000 --workers 3

Depois, configure o Nginx para repassar os pedidos ao Gunicorn, crie um serviço do systemd para o Gunicorn ligar sozinho e gere o certificado HTTPS gratuito com o Let's Encrypt:

sudo certbot --nginx -d meusite.com.br -d www.meusite.com.br
Dica: Comece por uma plataforma que faz a maior parte disso por você (vários serviços de hospedagem aceitam Django direto do GitHub). Montar o servidor na mão é ótimo para aprender, mas tem mais passos.
Pratique no DIGITAR: digite este trecho no modo Programar do app. 
python manage.py check --deploy

Exercícios

1. Você publicou com DEBUG = False e o site responde 400 Bad Request. Qual configuração provavelmente está faltando?

Ver resposta 
ALLOWED_HOSTS = ["meusite.com.br", "www.meusite.com.br"]

Com DEBUG = False, o Django só atende os domínios listados em ALLOWED_HOSTS.

2. Gere uma SECRET_KEY nova e forte com a biblioteca padrão do Python.

Ver resposta 
import secrets

print(secrets.token_urlsafe(50))

(exemplo — a sua saída pode ser diferente)
BNNmx1s5VjLpBo5T9tpK_sh1I3JTYZVcctag8_TLCqRZc8WaE4aff_hgc2RDbfTmCN4

Guarde o valor numa variável de ambiente do servidor, não no código.
